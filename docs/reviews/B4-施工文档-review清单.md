## 2. 需要确认的取舍

| 项 | 本轮建议 | 原因与影响 |
|---|---|---|
| 管理身份 | B4用真实admin的Bearer Key，B7换session／CSRF | 19尚未交付，管理接口仍须实际鉴权；不增加固定token或免鉴权入口 |
| 管理写入 | PUT完整标量＋models事务替换；Key独立子资源 | 旧repo更新不碰mapping，不能交给实现会话猜部分更新；补Owned父锁与删除锁序，防越权／孤儿 |
| 别名引用 | 删除渠道不隐式重写default／fallback，B5过滤缺失项 | 保持现有store删除语义；19.2管理页面显示／修复配置，别名／价格管理不混入渠道L2 |
| Key反馈 | B4仅按配置SWRR，失败动态降权后置 | Endpoint无KeyID，渠道结果不足以归因到某把Key；禁止用last-picked猜测异步请求 |
| Redis健康 | 原HASH增version、新增版本读＋CAS，旧原语不改 | 单次HSET原子不等于业务读改写原子，需避免多副本丢计数及旧probe恢复新禁用 |
| 恢复与故障 | 冷却到期只准后台probe，成功才恢复；Redis故障不放行；用户上游400／404／422不计渠道故障 | 明确后台半开与普通请求分离；Redis故障使候选不可用；按Kind与状态码区分用户错误，避免坏请求禁用渠道 |
| 统计与检查点 | B4只镜像健康／最近探活；错误率／p99生产后续冻结；脚本读实时health | 单次probe不是p99，当前HealthRegistry仅bool结果；18仍被动无业务反向依赖，B4不依赖B7页面 |

其他明确边界：SWRR为每实例序列；probe固定首启用Key，仅证明被测路径；允许多副本重复出站但同版本结果至多提交一次。允许管理员配置私网／loopback上游，不承诺公网SSRF隔离。跨副本配置仍60s TTL；新原语和全部改动由各L2独审，文档review不等于认可未来实现。
