## 三、必须落实的集成契约

### 1. 入口接缝与有界透明请求

- RegisterV1Routes负责/v1全路径，auth／precheck／executor／models均不能为空。POST按Auth→有界解析→WithModel写回c.Request→Precheck→Execute；GET models同样鉴权，不做chat解析／配额预检。无效输入零Precheck／Execute／上游调用，未鉴权大正文仍401。
- 固定10×1024×1024字节上限，先限读取再解码，超限413；application/json允许参数，否则415；完整单个非null对象，禁止尾随JSON和重复顶层字段，其他非法输入400。
- model非空string；stream缺省false、null／非bool拒绝；messages非空数组，每项对象有非空string role，其余content／tool_calls等原始结构保留，不把content收窄为string。
- stream_options缺失／null／对象合法，对象内include_usage存在则须bool，其余字段保留。未知顶层进Extra，不全局DisallowUnknownFields；调用链对输入只读，不因上游模型重写／强制usage污染原始请求。复用内部JSON工具时保留13.4自己的64KiB和字段限制。
- GET models输出冻结OpenAI list envelope，id为别名、object=model、owned_by=gaigate，按name升序、空data=[]；列全部已配置别名，不虚构enabled字段或按当前健康／余额过滤。
- access.ChatExecutor(req)不冒充router.Executor(plan)。access生产不import router／meter／proxy／bootstrap，未来B5在装配处适配；Prechecker只保留已冻结Precheck子集，不提前补未来配额接口。

### 3. 错误安全、提交与原因消费

- bootstrap将转发错误包为access.ExecutionError，Cause保留分类链，WroteHeader复制结果，TimedOut仅由TTFB／Overall结果确定；完整ResultKind在bootstrap按安全方式记录，不迫使access依赖proxy。
- 按00 §6.9第8项和15.2 §3.4消费结果：Overall锁存后错误链可能同时含Canceled，不能仅errors.Is(Canceled)就覆盖已经确定的TimedOut。区分真正客户端取消和预算原因，不新增公开字段／哨兵来绕开现有契约。
- 入口未提交时按13-L1／13.3映射一次JSON：未知模型404、无候选503、内部SQL／配置500；上游401／403→502 upstream_auth_failed，429／5xx／网络／协议／其他状态→502 upstream_error，TTFB／Overall→502 upstream_timeout，code均加gaigate_，带request_id。
- 上游400／404／422只有在Body未截断、完整合法OpenAI error对象且能证明安全时保留其error字段／状态，补顶层request_id，不透传其他顶层字段／任意响应头。复用adapter对Endpoint.APIKey的过滤，handler再防客户端Bearer回显，包括解析后字符串／转义；无法证明安全退回502，不能把截断JSON／HTML／敏感cause或错误体写进日志。
- 已提交失败由入口panic(http.ErrAbortHandler)真实异常终止，不再JSON、错误SSE或补Done；客户端取消不继续写。proxy此前未提交应仍给handler一次错误回复机会，不能回退15.2已修好的提交前deadline清理。

### 4. Recover、摘要和实际装配

- 保持RequestID→AccessLog→Recover→Auth。Recover首先识别ErrAbortHandler并原样re-panic；普通panic未提交仍500及安全故障日志，已提交转ErrAbortHandler并不追加JSON。不能用Gin或外层再次吞掉它，让截断变正常结束。
- AccessLog的defer仍恰一次，记录真实已发状态；HTTP200伴中断另有安全结构化故障原因，不假改已发状态。panic值／底层cause可能含秘密，不直接输出原文；保持ts键、request_id和既有日志契约。
- AccessLog入口建立本请求独有的线程安全共享摘要；WithUserID／WithModel／WithChannelID保持签名和标准context取值，并在摘要存在时同步，完成日志读取摘要，缺失时沿旧值回退。摘要不存凭据／正文，不作为授权来源。
- 真实证明bootstrap内层派生ctx的channel能进入外层完成日志；至少两个并发请求不同渠道不串值，不能只在handler手工覆盖c.Request掩盖缺口。正文仍经真实Gin／WrapWriter，保留Status／Size／Written及Flush／deadline能力。
- cmd装配既有Auth、KeyService／UserKeyRoutes、配置repo、Provider／Forwarder、临时执行器与V1Routes；配置值只由装配层传入，不让业务包读全局Viper／环境。复用13.4命令，不复制首次签发或在启动／seed中自动生成用户Key。
- 启动／探针／关闭等原协议保留；若长流接入暴露真实生命周期矛盾，给具体复现和最小建议交主会话，不擅自借此改已冻结关闭协议或承诺未经验证的HTTP/2／TLS行为。
