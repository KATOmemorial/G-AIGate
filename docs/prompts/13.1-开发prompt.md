## 三、必须落实的契约

1. **Key 生成**：32 个 crypto/rand 随机字节，用 base64.RawURLEncoding 编码后前置 sk-，raw 总长 46；prefix=raw[:8]，含 sk- 共 8 字节；hash=完整 raw 的 SHA-256 小写 hex。GenerateKey 返回 raw／prefix／hash／error，失败三个字符串为空。包内可注入 reader 验证失败，不引入全局可变随机源。
2. **仓储与身份**：复用 uint64 的表模型，公开 ID 和 Principal 是 int64，转入 Principal 前检查正数与溢出。前缀索引非唯一，FindByPrefix 返回包括吊销／过期在内的全部候选、按 id 升序，逐项恒时比较完整摘要，不能只认第一条。空列表为 []，SQL 错误保留 %w 原因。
3. **吊销 owner**：RevokeOwned 以 user_id＋keyID 条件更新；本人已吊销仍成功，他人／不存在均 store.ErrNotFound。RowsAffected=0 不能直接判不存在，须核对该 owner 下存在性。吊销提交后的新鉴权即时拒绝，在途请求不撤销。
4. **鉴权顺序**：格式 → prefix 候选 → 完整 hash → Key 状态 → UTC 过期（now>=expired_at 即过期；nil 永久）→ 用户存在且启用 → 完整 Principal。无匹配凭据 401；吊销／过期／禁用分别 403；真实仓储故障、关联用户缺失或 ID 非法为内部错误 500，不伪装 401。
5. **HTTP 与 context**：只允许单个 Authorization 值、一个 Bearer scheme 和一个 Key，scheme 忽略大小写；重复 header、逗号拼接、坏形状均 401，格式错误零仓储调用。RequestID → AccessLog → Recover → Auth 顺序不变；成功把 Principal 与 WithUserID 的标准 context 写回 c.Request，不能只 gin.Context.Set。失败写一次 OpenAI 风格 envelope，含 request_id 并 Abort。
6. **隐私**：响应与日志不含完整 raw／hash、用户密码／密码哈希、渠道密钥或 DSN；内部错误不给客户端回显 SQL／凭据。请求 context 贯穿到 SQL，不在请求路径用 context.Background。
