# 12.2 场景控制 API 与验收脚本（L2）

> 状态：草案（待 review） | 上游：[12-L1](../12-mock-provider.md) | 批次：B2 | 预计工作量：0.5 天
> 上下文包：12-L1 §2（场景协议）、12.1（Engine 接口）

---

## 1. 模块定位

可编程上游的"控制面"：切换/查询场景的 HTTP API + 五场景验收脚本。脚本本身是 B4/B5/B6 集成检查点的可复用零件。

## 2. 目标 / 非目标

**目标**：`PUT /admin/scenario`、`GET /admin/scenarios`；`test/e2e/mock_scenarios.sh`（五场景断言，入库即回归资产）。

**非目标**：鉴权（mock 是测试设施，仅本机监听）；场景持久化（重启回到默认 normal——特性而非缺陷）。

## 3. 输入输出

```
PUT /admin/scenario
{"key":"sk-mock-a","scenario":"downtime","params":{"downtime_mode":"503"}}
→ 200 {"key":"sk-mock-a","scenario":"downtime"}
（params 可省略 = 全默认值；非法 scenario → 400）

GET /admin/scenarios
→ 200 {"sk-mock-a":{"scenario":"downtime",...},"sk-mock-b":{"scenario":"normal",...}}
```

**验收脚本** `test/e2e/mock_scenarios.sh`（结构冻结，实现按 01 §5 入库）：

```bash
# 用法: ./test/e2e/mock_scenarios.sh [mock_base_url]   默认 http://127.0.0.1:18080
# 顺序执行 5 个断言组，每断言组 = PUT 场景 → curl /v1/chat/completions → 检查
# ① normal   → stream 响应含 8 帧 data: + [DONE] + usage 帧
# ② slow     → 总耗时 ≥ 2s 且成功
# ③ downtime → HTTP 503
# ④ rate_limited → HTTP 429 + Retry-After 头
# ⑤ interrupted  → 输出 3 帧后连接断开（curl 退出码非 0，已收内容含 3 个 data:）
# 全部通过 → exit 0 并打印 PASS 列表；任一失败 → exit 1 并打印失败断言
```

## 4. 设计说明

1. **脚本只增不改**（01 §5）：B4/B5 的健康/容灾脚本会 `source` 本脚本的 PUT 封装函数，而不是复制粘贴。
2. **断言用最原始的工具**（curl + grep + exit code），不引测试框架——e2e 脚本的生命力在于十年后还能跑。

## 5. 验收标准（可执行）

```bash
go run ./cmd/mockprovider &
go run ./cmd/g-aigate &          # 无需网关，本脚本直打 mock；但为验证链路也可选经网关
./test/e2e/mock_scenarios.sh     # → exit 0，5 个 PASS
# 反向验证：手动 PUT 非法场景 → 400
```

## 6. 依赖

上游：12.1（Engine）。被依赖：14.3/B4 检查点、16.x/B5 检查点、17.2/B6 检查点、20.1（`make demo` 的底层零件）。

## 7. 主要风险

- bash 在 Windows 的执行环境（Git Bash/WSL）差异：脚本用 POSIX 子集，`#!/usr/bin/env bash`，文档注明运行环境。
- `interrupted` 断言依赖 curl 对连接关闭的退出码行为——用 `--no-buffer` 并捕获已输出内容判断，不依赖具体退出码值。
