## 1. 模块定位

mock 的控制面与 B2 回归资产：在 12.1 已交付的独立进程上注册场景更新／查询 API；提供可 source 的控制封装和可执行的五场景脚本。它为 B4／B5／B6 编排故障，不依赖网关先实现。

## 2. 目标 / 非目标

**目标**：PUT /admin/scenario、GET /admin/scenarios；HTTP patch DTO 到 12.1 完整参数的转换；与数据面共用 Engine；`test/e2e/lib/mock_control.sh` 和 `test/e2e/mock_scenarios.sh`；控制与脚本的行为验收及 B2 检查点证据。

**非目标**：真实鉴权、场景持久化、重做 12.1、修改网关路由／鉴权、全链 Compose 编排、增加抓包／请求正文回显 API。无新增数据库或 Go 第三方依赖。不读取用户真实供应商 Key。

## 3. 输入输出

### 3.1 依赖接口与装配

消费 12.1 的以下接口，不平行维护第二份状态：
- `NewEngine() Engine`、`DefaultScenarioParams() ScenarioParams`。
- `Engine.Set(key string, s Scenario, p ScenarioParams) error`：完整配置校验后原子替换。
- `Engine.Get(key string) (Scenario, ScenarioParams)`、`Resolve(key, overrideHeader string) (Scenario, ScenarioParams, error)`：数据面快照。
- `Engine.Snapshot() map[string]ScenarioConfig`：独立副本，仅已显式配置的 Key。
- 本 L2 新增 `RegisterControlRoutes(r gin.IRoutes, e Engine)`；main 构造一次 Engine，传给 12.1 和本 L2 的路由注册。允许增量修改 mock 的 main 装配，不改变其默认地址、健康探针和关闭契约。

Set 返回后才向控制客户端返回成功，因此该成功响应之后开始 Resolve 的请求必须读到新值；在途响应仍遵循旧快照。注册两套不同 Engine、请求睡眠期间持锁、后台异步更新后提前返回成功均不符合契约。

### 3.2 PUT /admin/scenario

```json
{
  "key": "sk-mock-a",
  "scenario": "downtime",
  "params": {
    "downtime_mode": "503"
  }
}
```

根对象只允许 key、scenario、params；key 和 scenario 必填且为字符串，校验沿用 12.1。params 可省略，给出时必须是对象（包括空对象），显式 null 不接受。

**每次请求从全默认参数出发**，按“本次出现”的字段覆盖，校验后完整替换，不合并旧状态。params 省略或 {} 均表示全默认值；例如先设置 slow 的 ttfb_delay=5s，再 PUT slow 且不带 params，延迟必须回到 2s。

| JSON 字段 | 类型 | 默认值 | 零值／非法值处理 |
|---|---|---|---|
| chunks | 整数 | 8 | >0；零、负、浮点或超 Go int 范围拒绝 |
| chunk_interval | duration 字符串 | "50ms" | "0s" 合法，负值／无法解析拒绝 |
| ttfb_delay | duration 字符串 | "2s" | "0s" 合法，负值／无法解析拒绝 |
| downtime_mode | 字符串 | "503" | 仅 "503"／"refuse"，空串拒绝 |
| fail_after_chunks | 整数 | 3 | >=0；最终 interrupted 额外满足 1<=k<chunks |
| prompt_tokens | 整数 | 12 | 0 合法，负值拒绝 |
| completion_tokens | 整数 | 34 | 0 合法，负值拒绝 |

- duration 以 time.ParseDuration 解析；例如 "500us"、"1.5ms" 合法，输入是字符串而非隐含毫秒的数字。不要求输出保留输入拼写；返回使用 time.Duration.String() 的规范形式。
- DTO 必须区分字段缺失与显式零；参数 null、未知字段、错误类型、畸形 JSON、尾随第二个对象均为 400。不要用零值填默认导致 "0s"／0 无法表达。
- JSON 对象键若重复则拒绝 400，避免“同一请求两份配置”的解释分歧；该校验只针对控制根对象及 params，不扩张 chat 请求的兼容面。
- 数值解析与 total token 相加检查沿用 12.1；拒绝溢出，不以 float64 截断整数。
- body 上限 64KiB，超过 413；Content-Type 需 application/json（允许 charset），否则 415。
- 校验失败不得调用 Set 写状态；若 Set 返回校验错误，同样 400、状态不变，不映射成 500。其他运行错误记日志并返回 500 mock_internal。

**200 响应 DTO**（以下为结构示意，key_id 为完整 64 位十六进制值）：

```json
{
  "key_id": "<sha256hex(完整测试 key)>",
  "key_prefix": "sk-mock-",
  "scenario": "downtime",
  "params": {
    "chunks": 8,
    "chunk_interval": "50ms",
    "ttfb_delay": "2s",
    "downtime_mode": "503",
    "fail_after_chunks": 3,
    "prompt_tokens": 12,
    "completion_tokens": 34
  }
}
```

为遵守 01 §8，控制响应**不回显完整 Key**：key_id 为完整测试 key 的 SHA-256 小写 hex；key 长于 8 字符时 key_prefix 取前 8 字符，长度不超过 8 时返回空串，避免将短标识完整回显。这是标识映射，不以此前缀作为唯一标识。响应包含实际生效的完整参数，便于确认默认补齐结果。旧草案的 `{"key":"sk-mock-a",...}` 响应由本稿替换；请求仍使用完整测试 key 以定位场景。

成功／失败响应统一 Cache-Control: no-store；JSON 错误体沿用 12.1 的 mock_error 外形，参数错误码 mock_invalid_request，不打印原始 key 或 body。控制接口无 Authorization 要求，仅在隔离测试环境使用。

### 3.3 GET /admin/scenarios

```json
{"scenarios":[{"key_id":"<64位hex>","key_prefix":"sk-mock-","scenario":"normal","params":{"chunks":8,"chunk_interval":"50ms","ttfb_delay":"2s","downtime_mode":"503","fail_after_chunks":3,"prompt_tokens":12,"completion_tokens":34}}]}
```

- 只列成功 Set 的 Key；启动后为 `{"scenarios":[]}`，非 null。仅数据面访问未配置 Key 不产生记录。
- 字段与 PUT 成功 DTO 一致，按 key_id 升序，方便确定性断言；通过 Snapshot 副本映射响应，不把内部按明文 key 索引的 map 直接序列化。
- 每次读取是一份一致快照；响应对象与列表不会成为修改 Engine 的入口。返回 no-store。
- 不实现 DELETE／PATCH／单 Key 查询；测试用例可重新 PUT normal 恢复默认，不靠重启服务恢复其他调用方状态。

### 3.4 脚本库接口与可执行脚本

新增文件：
- `test/e2e/lib/mock_control.sh`：只定义控制函数，无顶层请求、输出、cd、set、trap 或验收调用。被 source 时不得改变调用方 shell 选项、工作目录、trap、环境和位置参数，不自动拉起／停止任何进程。
- `test/e2e/mock_scenarios.sh`：定位自身目录后 source 上述库，主动执行五场景断言。按 01 §5 入库后只增不改；后续需求以新增库／脚本或新版本实现，不把修改历史验收作为过关手段。

本轮只冻结一个供 B4／B5 复用的函数接口：
`mock_set_scenario <base_url> <test_key> <scenario> [params_json]`。
params_json 缺省 {}；只发一次 PUT。成功要求 curl 成功且 HTTP 200，函数 return 0、stdout 为空；失败 return 非零、原因到 stderr。不使用 eval、bash -c 或执行参数内容；body 按数据传给 curl。为避免 bash 手写通用 JSON 转义，本封装 test_key 仅接受 ASCII 字母、数字、下划线和连字符组成的非空测试标识（如 sk-mock-a）；scenario 只接受五个已知枚举；params_json 是调用方提供的受信 JSON 对象片段，由服务端最终校验。这个封装限制不改变 HTTP API 的 key 合法域。

可执行脚本用法：
`bash test/e2e/mock_scenarios.sh [mock_base_url]`，默认 http://127.0.0.1:18080。首步检查 /healthz，服务未启动则明确失败，不等待用户输入，也不要求网关运行。

仅使用 bash、curl、mktemp 及 POSIX grep/sed/awk 等文本工具；不依赖 jq、Python、GNU 专用 grep 选项。HTTP 断言采集状态码、响应体和 curl 退出码，不能因 429／503 是预期就掩盖连接失败；JSON data 一帧一行，按内容／usage／DONE 分类计数，不把 grep data 总数误当内容数。

脚本仅使用专属 `sk-mock-e2e-a`／`sk-mock-e2e-b`，开头初始化这两个 Key，退出时恢复二者 normal＋默认参数。不得改写 seed 的 sk-mock-a／b；不得把所有 Key 全局重置。临时文件在独立 mktemp 目录，退出时清理；cleanup 错误须报告，不掩盖原失败状态，若原本成功而恢复失败则 exit 1。不停止用户 mock 或其他中间件。

## 4. 设计说明

1. **HTTP patch 的省略语义独立于完整配置**：每次 PUT 重建默认，显式零值有效；解析／校验全部完成才 Set，失败不改变状态。
2. **响应指纹替代完整 Key**：不把测试设施当作回显真实凭据的例外；相同 prefix 仍可用 key_id 区分。控制查询只为观察测试状态。
3. **库和验收脚本分开**：B4／B5 source 函数库即可编排自己的故障，不会隐式执行 B2 验收、修改 shell 状态或覆盖现场场景。

| # | 行为断言 |
|---|---|
| ① | PUT normal／slow／downtime／rate_limited／interrupted，各返回实际生效的完整参数；省略 params、空对象、部分字段覆盖均正确 |
| ② | 旧配置 5s 被新 PUT 省略参数重置为 2s；显式 0s／0 保留；"1.5ms" 解析成功且输出等价规范 duration |
| ③ | 未知场景、非法 key、字段／类型／null／负值／计数范围／token 溢出／重复键／未知字段／多 JSON／超大 body／媒体类型：400／413／415，前后 Snapshot 相同 |
| ④ | GET 初始空数组，配置后只列显式 Key；按 key_id 排序；hash 与 prefix 正确（短 key 的 prefix 为空）；响应字段不含完整 key／内部 map key，成功失败 no-store |

| ⑦ | source 库无网络调用、输出和 shell 状态变化；函数成功／失败 return、stderr、参数作为数据而非执行均符合 §3.4 |
| ⑧ | curl 指向不可达服务或返回非 200 时封装失败；脚本不因错误路径被 set -e 提前打断而漏掉预期断流断言与清理 |

### 5.2 五场景脚本

独立终端前台启动 `go run ./cmd/mockprovider`，另一个 Git Bash 终端：
```bash
bash test/e2e/mock_scenarios.sh
# 预期 5 组 PASS、exit 0；任一断言失败即 exit 1 并标出场景和原因。
```

| 组 | 控制与请求 | 断言 |
|---|---|---|
| normal | PUT e2e-a normal 默认；chat stream=true、include_usage=true | HTTP 200、curl exit 0；8 内容、1 usage（12/34/46）、1 DONE |
| slow | PUT e2e-a slow 默认 | 先不写响应头；curl time_starttransfer >=1.8s、在 10s 请求预算内完成；同 normal 的帧计数、exit 0 |
| downtime | PUT e2e-a downtime／503 | HTTP 503、mock_unavailable JSON；curl 传输完成，不能把连不上当成 503 |
| rate_limited | PUT e2e-a rate_limited | HTTP 429、Retry-After=1、mock_rate_limited JSON |
| interrupted | PUT e2e-a interrupted 默认；chat stream=true、include_usage=true | HTTP 200、3 内容、0 usage、0 DONE、curl 非零且非超时；用 5s max-time 兜底，但“等满超时”不算断流通过 |

每组 chat 都带 JSON Content-Type 和测试 Authorization；流式用 `--http1.1 --no-buffer`，不经过代理／网关。至少增加一项组内隔离断言：e2e-a 为 downtime 时 e2e-b normal 仍成功；不增加第六个主场景。失败时给出采集到的状态／帧数／退出码，日志不得包含完整测试 Key。

正常流统计采用真实行协议，不假定 JSON 对象字段顺序；12.1 将每个 SSE JSON 放在单独 data 行。脚本只解析该模板子集，不宣称是通用 JSON／SSE 解析器。

## 7. 主要风险

- Go JSON 对 null／零值／重复字段的默认处理不能替代本契约校验；审查须检查失败前后状态与显式零。
- 控制响应不得直接序列化内部 Snapshot 明文 key map，日志也不能泄漏 key/body。
- interrupted 的预期 curl 非零必须主动采集；因 set -e 提前退出、到期超时或 DNS 失败都不能冒充 PASS。
- Git Bash 使用实际 curl 程序，不使用 PowerShell Invoke-WebRequest 别名。临时目录／恢复逻辑应在错误路径仍执行，不删除项目目录或数据卷。
