## 1. 模块定位

可编程 HTTP 上游的服务端：`cmd/mockprovider` 独立运行，`internal/mock` 提供场景引擎和 `POST /v1/chat/completions`。B3 的 OpenAI 适配器将其当作普通上游；它不进入网关内部请求管道，不实现 `provider.Provider`，不依赖其他业务包。12.2 在同一 Engine 上追加控制面。

## 2. 目标 / 非目标

**目标**：按测试 Key 隔离的场景快照；五场景的流式／非流式行为；最小 chat 请求校验；SSE 模板、usage 和结束标记；取消传播可观察性；进程入口、地址校验与有界关闭；单元及真实 TCP 行为测试。

**非目标**：12.2 控制 API／持久化／正式 e2e 脚本、真实鉴权及推理、`/v1/models`、`/v1/responses`、完整 OpenAI 协议、HTTP/2／TLS、网关路由与计费。可通过 httptest 的 Engine.Set 和请求头验证场景，不提前实现控制 API；本 L2 进程冒烟只需默认／header 场景。

## 3. 输入输出

### 3.1 包与接口

仅使用 Go 标准库及仓库已有依赖（如 Gin、ULID）；`internal/mock` **不 import 任何其他 internal 包**。入口使用 `gin.New()` 装配，不复用网关配置加载、Recover 或 store。

```go
// internal/mock：已冻结的模块内接口，由 12.2 消费。
type Scenario string
const (
    Normal      Scenario = "normal"
    Slow        Scenario = "slow"
    Downtime    Scenario = "downtime"
    RateLimited Scenario = "rate_limited"
    Interrupted Scenario = "interrupted"
)
type ScenarioParams struct {
    Chunks           int
    ChunkInterval    time.Duration
    TTFBDelay        time.Duration
    DowntimeMode     string
    FailAfterChunks  int
    PromptTokens     int
    CompletionTokens int
}
type ScenarioConfig struct {
    Scenario Scenario
    Params   ScenarioParams
}
type Engine interface {
    Set(key string, s Scenario, p ScenarioParams) error
    Get(key string) (Scenario, ScenarioParams)
    Resolve(key, overrideHeader string) (Scenario, ScenarioParams, error)
    Snapshot() map[string]ScenarioConfig
}
func NewEngine() Engine
func DefaultScenarioParams() ScenarioParams
func RegisterChatRoutes(r gin.IRoutes, e Engine)
```

- NewEngine 初始无显式 Key；Get 未配置 Key 返回默认 normal + 全默认参数，**不创建记录**。默认值／快照按值返回，调用者修改不影响 Engine。
- Set 接收**完整**参数，不把 Go 零值当作“未指定”。校验 key、场景名及参数成功后，在同一临界区替换；失败返回带原因的普通错误，原状态不变。不新增跨模块哨兵。
- Resolve 读取一次 Key 快照；header 为空则使用快照场景，有值只替换场景名，保留参数并校验最终组合。未知覆盖返回 error；不写 Engine。HTTP 层把错误映射为 400。
- Snapshot 仅列已成功 Set 的 Key，返回独立 map 与值副本。不存在的默认 Key 不在列表中。
- Set／Get／Resolve／Snapshot 并发安全。Set 完成后的新解析看到新状态；解析已完成的请求不重复 Get，不因控制切换改变行为。执行计时／网络写出时不得持状态锁。

### 3.2 参数默认及合法域

| 字段 | 默认 | 完整参数合法域／含义 |
|---|---|---|
| Chunks | 8 | >0，完整响应的内容帧数 |
| ChunkInterval | 50ms | >=0，内容帧之间的间隔；0 表示不人为等待 |
| TTFBDelay | 2s | >=0，slow 在任何响应头／正文之前等待；0 合法 |
| DowntimeMode | `503` | 仅 `503` 或 `refuse` |
| FailAfterChunks | 3 | >=0；当最终场景为 interrupted 时额外要求 1 <= k < Chunks |
| PromptTokens | 12 | >=0，合成输入用量，允许显式 0 |
| CompletionTokens | 34 | >=0，合成输出用量，允许显式 0 |

完整参数无缺省补齐；DefaultScenarioParams 返回上表。12.2 负责从默认值构建本次完整参数再调用 Set。无关场景也检查基本合法域；`FailAfterChunks < Chunks` 只在 interrupted 下要求，因此 normal 的 Chunks=1 可正常使用，若 header 强制 interrupted 而 k 不适用则 400。

key 要求去除首尾空白后非空，且原值不含空白／控制字符；存储使用原字符串，拒绝而不静默归一化。HTTP Bearer 提取后的 key 与控制 API 的 key 使用同一校验。本设施只使用测试标识，不校验它是否真实存在或属于某个用户。参数不做静默截断、取整或把显式零值改回默认值。 duration 保留 time.Duration 的精度，12.2 使用可解析的 duration 字符串，**不套用 11.4 限流窗口的整毫秒限制**。合成 token 的 total 必须可在 Go int 中安全相加，溢出参数拒绝。

### 3.3 HTTP 请求与错误

`POST /v1/chat/completions`：

- `Content-Type: application/json`（允许 charset 参数）；不支持的媒体类型 415。
- `Authorization: Bearer <测试 Key>` 必填，缺失／格式错／key 校验失败为 401。
- body 上限 1MiB，超出为 413；一个 JSON 对象，model 为非空字符串、messages 为非空对象数组；stream 缺省 false，显式值须为 bool；stream_options 若给出须为对象，include_usage 若给出须为 bool。畸形 JSON、null 根对象、尾随第二个 JSON 或已声明字段类型错为 400。
- 只消费 model、stream、messages 的上述最小结构及 stream_options.include_usage；允许并忽略其余请求字段（如 tools、temperature、max_tokens、user），不回显或保存请求正文。messages 的内部内容不执行完整协议验证。
- 验证输入后 Resolve 一次再执行场景；所有 4xx 输入错误必须发生在模拟延迟／写流之前。
- model 回显本次请求传入的模型名；它可与网关对外别名不同，不写死 gpt-4o-demo。
- mock 上游错误格式为 `{"error":{"message":"...","type":"mock_error","code":"mock_invalid_request"}}`，码按类别为 `mock_unauthorized / mock_unsupported_media_type / mock_request_too_large / mock_invalid_request / mock_unavailable / mock_rate_limited`。错误 message 不含完整测试 Key／请求正文；不使用 `gaigate_` 前缀或网关哨兵。

端点以 POST 注册，未实现路由返回 404；不新增模型列表或请求回显调试端点。

### 3.4 输出模板与逐帧计数

一条响应内 id、created、model 一致：id 非空并具有 chatcmpl- 前缀，created 为请求开始时的 Unix 秒；不要求跨响应 id 固定。内容模板第 i 帧为 `mock-i `（i 从 1 开始），完整非流式 content 为 N 段按序拼接。usage 为参数固定值，与模板字符数或 max_tokens 无推算关系。

正常流使用 `Content-Type: text/event-stream; charset=utf-8`、`Cache-Control: no-cache`，不设置 Content-Length，不启用压缩。每个事件 `data: <payload>\n\n`，逐帧 write + flush；首个内容帧立即发送，之后内容帧之间等待 ChunkInterval。最后内容帧的 finish_reason 为 stop，其余为 null；第一个内容帧带 role=assistant。**不另加 role-only 或 finish-only 帧**，以保持内容帧计数 N。

```text
data: {"id":"chatcmpl-...","object":"chat.completion.chunk","created":0,"model":"gpt-4o-demo","choices":[{"index":0,"delta":{"role":"assistant","content":"mock-1 "},"finish_reason":null}],"usage":null}

... 共 N 个内容帧，最后一个 finish_reason="stop" ...

data: {"id":"chatcmpl-...","object":"chat.completion.chunk","created":0,"model":"gpt-4o-demo","choices":[],"usage":{"prompt_tokens":12,"completion_tokens":34,"total_tokens":46}}

data: [DONE]

```

示例 created=0 仅为示意，运行时用请求快照秒数。仅 include_usage=true 发送 usage 帧，此时所有内容帧 usage=null；未开启时不发送 usage 帧，内容帧可省略 usage。非流式为 `chat.completion` JSON，单 choice 含 message(role=assistant, content=完整模板)、finish_reason=stop，始终含 usage。

默认计数：不含 usage 时 8 内容 +1 DONE=9 个 data 事件；含 usage 时 8 内容 +1 usage +1 DONE=10。interrupted 默认只有 3 内容帧，finish_reason 均不为 stop，无 usage 和 DONE。后续适配器不能依靠 choices[0] 提取 usage。

### 3.5 五场景、真实断连与取消

- normal：按 §3.4 完成。非流式不等待内容帧间隔，直接输出完整 JSON。
- slow：先等待 TTFBDelay，不预写头、不先 Flush；等待必须监听请求 ctx。随后执行 normal，非流式仅增加该首字节前延迟。
- downtime/503：立即 503 JSON（mock_unavailable）；不得带 SSE 成功头。
- downtime/refuse：输入校验及 Resolve 后，在写 HTTP 响应前终止**本次连接**；后续 normal 请求仍能访问同一个 listener。此模式允许 empty reply／EOF／reset，不锁定 OS 错误字符串。
- rate_limited：立即 429 JSON（mock_rate_limited），响应头 Retry-After=1。
- interrupted：stream=true 时写出并 Flush 恰好 k 个内容帧后**异常终止 HTTP/1.1 响应**，不能正常 return 完成 chunked 编码；客户端须收到已写内容，并在后续读取上得到非正常完成错误。stream=false 在任何响应前断连，沿用 refuse 的传输故障语义，不拼半个 JSON。
- 实现可采用 net/http 的 ErrAbortHandler 或经验证等价的当前连接终止方式；若选 ErrAbortHandler，Gin recover 不得将其吞掉或变成 500。不能以停整个 listener、伪造错误 SSE 帧、自然 EOF +缺少 DONE 代替真正传输中断。中断用真实 httptest.Server／TCP 验证，ResponseRecorder 只用于普通响应。
- 所有延迟／帧间等待用 ctx 可取消的等待；写／flush 失败立即退出，不继续生产后续帧。不为每个请求启动无主 goroutine，日志记录 completed、canceled、interrupted 或 error，取消退出须有测试证据。

### 3.6 入口、日志与关闭

配置仅 `MOCK_ADDR`，默认 `127.0.0.1:18080`；空值按未设置，非法 host:port／端口超范围及监听失败退出非零并说明原因。容器可显式设 `:18080`；不依赖 GAIGATE_SECRET_MASTER_KEY 或数据库配置。增加 `GET /healthz` 返回 200 `{"status":"ok"}`，用于进程与脚本可达性探测，不注入场景，不列模型。

入口用 slog JSON，时间键 ts；每条请求摘要有 request_id（合法的 X-Request-Id 可沿用，否则生成 req_+ULID）、model、scenario、chunks_written、outcome、latency_ms。chunks_written 只计已写出的内容帧；不打印完整 Key、Authorization 或请求正文，只允许 key 前缀最多 8 字符。入站 request ID 仅接受 req_+合法 ULID，否则重新生成；不 import 网关 middleware。场景注入的已知中断记录 outcome=interrupted，不当作进程崩溃堆栈刷屏。

SIGINT／SIGTERM 停止收新请求，Shutdown 预算 3s；超时后 Close 释放在途连接及等待 handler。自动化验证关闭函数；Windows 原生信号限制沿用 01 §10，不要求用 Git Bash kill 证明 SIGTERM。20.1 再做容器进程级全链验证。

## 4. 设计说明

1. **参数完整值与 HTTP patch 分层**：Engine.Set 只接收验证后的完整配置；12.2 用可区分未提供／显式零的 DTO 补默认，避免零延迟、零 token 无法表达或重置时继承旧参数。
2. **取快照后执行**：锁只保护内存状态，HTTP 等待不持锁。Set 返回即对后续解析可见，在途请求语义稳定。
3. **可验收的协议子集**：明确帧计数、usage 的独立空 choices 帧，以及异常断连证据。此 mock 是网关的测试输入，不能让客户端与服务端一起“错误地通过”。

## 7. 主要风险

- recover 吞掉故障注入、header 提前 Flush、把内容帧与 usage 混数，是本 L2 的主要审查点。
- request ctx 取消不等于“handler 已退出”；要有服务端退出证据。3s Shutdown 超时后须关闭活动连接，避免测试设施长时间残留。
- 短时间断言使用区间；故障类型不绑定 Windows／Linux 的具体网络错误文本。
- duration／计数合法不代表低成本；本机测试使用受控小参数。此处不扩成生产流量限额系统。
