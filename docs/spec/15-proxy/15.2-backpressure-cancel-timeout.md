# 15.2 背压 / 取消传播 / 双超时（L2）

> 状态：草案（待 review） | 上游：[15-L1](../15-proxy.md) | 批次：B3 | 预计工作量：1 天
> 上下文包：15-L1 §3（背压链条）、15.1（Forward 契约）、13.2（Stream 内部结构）、10.1（ProxyConfig）

---

## 1. 模块定位

把 15-L1 决策①的**背压链条**和决策③的**双超时**做实并验证。15.1 是"能转发"，本 L2 是"慢客户端、断客户端、慢上游三种恶劣条件下行为仍然正确"。

## 2. 目标 / 非目标

**目标**：TTFB 与整体双计时器（含与 13.2 的时间边界）；取消传播全链验证；慢客户端背压验证（上游读取被暂停）；超时参数从 ProxyConfig 注入。

**非目标**：新的转发逻辑（15.1 已定）；限流（不做）；连接数上限（20.2 部署层处理）。

## 3. 输入输出

```go
// 双超时实现要点（本 L2 冻结）：
// TTFB 计时：进入 Forward() 启动；首个事件到达即停止并记 FirstByteMs。
//   注意时间边界：连接建立+响应头耗时发生在 13.2 ChatStream 返回之前，
//   本计时覆盖的是"进入转发 → 首个事件"，完整 TTFB = ChatStream 耗时 + FirstByteMs，
//   16.4 打点时两段相加（18.1 的 gaigate_upstream_ttfb_seconds 口径在此冻结）。
// Overall 计时：进入 Forward() 启动，覆盖整个流；到期 s.Close() + ResultOverallTimeout。
// 两个 timer 用 time.AfterFunc 或 select 分支实现；TTFB 触发时若未写头 → ResultTTFBTimeout 且不写任何字节。

// 取消传播链（验收锁定）：
// 客户端断开 → r.Context().Done()（Gin handler 传入的 ctx）
//           → Forward 返回 ResultClientCanceled + s.Close()
//           → 13.2 适配器取消上游 HTTP 请求（context cancel 传播）
//           → 上游连接关闭（e2e 用 mock 连接日志验证）
// goroutine 收敛：Forward 返回后，适配器读取 goroutine 必须在 s.Close() 后 ≤100ms 退出
```

**背压链条的验证方法**（本 L2 核心验收，不实现新代码而是用测试钉死行为）：

```
假上游以固定速率产事件 → [适配器有界 chan，容量 64] → 转发循环 → 阻塞的假客户端 w
断言：假客户端只消费 k 帧后停住 → 等待 2×间隔 → 假上游的已产事件数 ≤ k + 64 + 少量在途
     （即：上游被反压暂停，而非事件在网关内无限堆积）
```

## 4. 设计说明

1. **背压不新增机制，只验证链条**：有界 channel（13.2）+ 阻塞写（15.1）天然形成反压，本 L2 的价值是把链条**用测试钉死**，防止后续重构（比如有人"优化"成无界队列）悄悄破坏它——测试即契约。
2. **TTFB 时间边界的显式冻结**：两段式 TTFB（ChatStream 段 + 首事件段）容易在 16.4 集成时算重或算漏，在此写死口径，18.1 指标按此打点。
3. **整体超时不写任何额外错误帧**：头已发出，写 HTML 错误页是对 SSE 流的污染——直接断连，客户端按流中断处理（与上游断流同语义，客户端只需处理一种情况）。

## 5. 验收标准（可执行）

```bash
go test ./internal/proxy/... -race
# 用例：
# ① TTFB：假 Stream 首事件延迟 100ms，TTFBTimeout=50ms → ResultTTFBTimeout，客户端零字节，未调 Flush
# ② TTFB 边界：首事件延迟 50ms，TTFBTimeout=100ms → 正常转发
# ③ Overall：流总长 500ms，OverallTimeout=200ms → 第 200ms 断连 ResultOverallTimeout，客户端已收部分帧
# ④ 取消：客户端 ctx cancel → ResultClientCanceled + Close() 调用 + 读取 goroutine ≤100ms 退出（WaitGroup 断言）
# ⑤ 背压（§3 的验证方法）→ 上游产事件数被限制在 k+64+ε
# ⑥ -race 下全绿（转发循环与 onChunk 并发安全）

# e2e（B3 检查点组成部分）：
./test/e2e/mock_scenarios.sh 之外追加：
# ⑦ curl -N 经网关收流，2 秒后 Ctrl+C → mock 日志显示上游请求被取消（连接非自然结束）
# ⑧ mock slow(TTFB 2s) + 网关 TTFBTimeout 10s（默认）→ 正常；调配置至 1s → 502 零字节
```

## 7. 主要风险

- 时间相关测试的稳定性（CI 慢机）——超时断言用区间而非精确值（50ms 配置 + 100ms 断言上限）。
- Windows 下 curl Ctrl+C 的信号传递差异——e2e ⑦ 在 Git Bash 验证并注明。
