## 1. 模块定位

完成 15 模块在慢上游、慢客户端和取消下的资源退出保证。不是只加两个 select 分支：opener、HTTP body、满队列、正在阻塞的 Write／Flush 都必须被同一尝试生命周期覆盖。

## 2. 目标 / 非目标

目标：opener 之前起算的 TTFB／Overall、原因分类、写期限与主动打断、Close／worker／watcher 收敛、有界背压和真实 TCP 验证。M1 双预算／状态边界，M2 慢写／取消／背压和基线验证，逐段停点。

非目标：重试、计量、部署连接上限、HTTP/2 或反向代理下未经实证的保证；不改 15.1 的公开签名，不改 12 的脚本。StreamBuffer 已在 13.2 注入，此处不新建第二队列。

## 3. 输入输出与精确语义

沿用 15.1 Forwarder／ForwardOptions／ForwardResult；配置读取与注入由 13.3 的 cmd 装配负责，本层不读 Viper／全局环境变量。

### 3.1 单次尝试的时间轴

- 方法进入为 t0；在调用 opener 前创建继承客户端 ctx 的尝试 context 和取消／计时机制。TTFB 到 t0+TTFBTimeout，Overall 到 t0+OverallTimeout；父 deadline 更早则优先。参数要求均正，不要求 Overall 大于 TTFB；谁先到谁生效。
- **TTFB** 覆盖 DNS／连接／响应头／首个合法完整 SSE data；心跳和注释不停止计时。非流式覆盖到完整合法 JSON 已读取（B3 保守口径，不是收到任意一个原始字节）。第一个可转发载荷就绪且当时未超时，记录 FirstByteMs 并停止 TTFB；随后客户端慢写仅受 Overall／父取消约束。
- **Overall** 从同一 t0 持续到写出及流资源关闭。不能在 ChatStream 返回后重启预算。opener 必须遵循传入 context，适配器已提供取消退出契约；不通过启动一个游离 goroutine 假装超时返回。
- 到期时触发取消与回收，不承诺方法在该纳秒瞬间已经返回；后续 worker／watcher 退出按 §3.3 的 500ms 上限独立验证，不能把清理等待隐藏成新的一轮 Overall 预算。
- 因 TTFB／Overall 取消分别返回 ResultTTFBTimeout／ResultOverallTimeout；客户端 ctx 取消返回 ResultClientCanceled，父 DeadlineExceeded 保留其原因并归 OverallTimeout。ctx／deadline 已生效时不能把适配器派生读错误记为上游异常。若多个原因已同时满足，先判父取消／deadline，再判 Overall，再判 TTFB。
- 在 opener 失败、事件到达和提交前重新核验取消／到期状态；不能因 select 随机选中已有事件而在已超时后继续提交。

以上预算按每次候选尝试独立计算，16.4 可另设整请求预算但不能吞掉更早的客户端 deadline。FirstByteMs 只是一段 t0 到载荷就绪，不再把 ChatStream 耗时相加；18.1 消费时须沿用应用层口径。

### 3.2 正在 Write／Flush 时

仅 select ctx 无法打断同步阻塞写。生产 HTTP/1.1 路径须使用底层 ResponseController／等价写 deadline 能力：首次写之前设置 Overall／父 deadline 中较早者；客户端取消时主动使当前写截止。所有调用必须在 handler 生命周期内，不能在返回后继续操作 ResponseWriter。

沿 Gin 与已有包装层取到底层能力，Flush 错误必须可观测；同时保留外层写入统计。能力缺失／ErrNotSupported 在提交前返回内部错误，不静默降级；httptest.ResponseRecorder 只能用于不依赖 deadline 的单元用例，不能证明生产慢写保证。

watcher 必须受控、可停止、可等待；先停止／等待 watcher，再返回 handler。流 body.Close 和 worker 退出同样等待。未提交时不得把下游 deadline 提前设为已过期，使 handler 连超时 JSON 都写不出；已经过期的写 deadline 不承诺清零可恢复，因此前置超时应只取消上游、不触发下游写期限。正常退出前清理未过期 deadline，失败后已提交由 handler 异常中止，不再复用该响应。

Go 具体能力参考 [ResponseController／SetWriteDeadline](https://pkg.go.dev/net/http@go1.25.0#ResponseController.SetWriteDeadline)。不得将“调用 context cancel”当作“正在写的网络操作已退出”的证据。

### 3.3 背压与收敛

阻塞客户端写 → 转发停止取 Events → 固定容量 channel 写满 → parser 停止解析／读取。最多保留容量 C 的完整事件、转发在途事件和 parser 的有限读取缓冲；单帧还受 13.2 的 1 MiB 上限约束。TCP／HTTP 自身发送缓冲另计，不能以“上游进程总发送量 <= C”作为跨网络的错误断言。

关闭验收在 worker 已进入读／发送／写的屏障后触发取消；适配器 worker、转发 watcher 都有退出通知并被等待。在可控本机 fixture 中，取消后目标 100ms、验收上限 500ms，计时从取消触发起算；不要用全局 goroutine 数恰好不变代替。超出预算须报告具体阶段，不能吞超时继续标 PASS。

## 4. 设计说明

统一 t0 消除旧稿漏掉响应头等待的时间洞；opener 让 proxy 不 import HTTP adapter 仍能持有完整预算。TTFB 在有效载荷就绪时停，Overall 再兜慢客户端，避免拿上游超时替客户端慢写分类。通道上限与帧上限共同提供内存上限，底层 deadline 才能把背压中的慢写变为可退出状态。

| 写／Flush 阻塞 | 可控支持 deadline 的 fake 和真实 TCP 不读客户端，两者均被 Overall／取消唤醒；watcher 全部退出 |

| 边界 | 非正参数在 opener 前拒绝；Overall<TTFB、已取消 ctx、事件与 deadline 同到，避免错误提交 |

### 11.2 生命周期、写出与原因处理

两种方法都在入口记录 t0，校验参数后、opener 前建立预算 ctx；Overall 的绝对截止为 t0+OverallTimeout，TTFB 定时器也从 t0 计算。opener 同步接收其派生上游 ctx，不起游离 opener goroutine。预算 ctx 与上游清理取消分开：退出时先取消上游并等待唯一 Stream.Close，预算和下游 watcher 在 Close 期间仍有效，最后再停止／等待 watcher、处理 deadline、检查最终原因及回收预算定时器。正常清理取消不会被当成客户端取消去主动过期下游。

首个合法 Chunk／UsageDone／Done 或完整合法 JSON 就绪后，在锁内重新核验父状态和绝对截止，再记录一次 FirstByteMs、停止 TTFB；已开始或排队的 TTFB 回调也检查同一状态，退出时会被等待。opener 返回、事件到达、载荷就绪、提交前和 Write 后 Flush 前均检查原因；最终清理后再次检查。原因顺序为父取消／deadline、Overall、TTFB；派生读取／写出或 Close 错误保留在 errors.Is／As 链中，不能覆盖已生效预算。父 deadline 与底层写 deadline 同时生效但父定时回调尚未调度时，等待其 Done 信号以保留 WithDeadlineCause 原因。

沿原生／Gin／真实 WrapWriter 的标准 Unwrap 链取得 FlushError 与 SetWriteDeadline，链条查找有 64 层上限。提交前用 **零 deadline** 验证 setter 实际支持，不 Flush、不提交，也不在等待上游时安装会过期的下游期限。首次成功写之前才设置 Overall／父 deadline 的较早值；正文仍经原外层 Write 保留 Gin 统计。到保守提交边界时注册受控取消回调，只调用已解析的底层 deadline setter，不读写 Gin 状态；取消会使正在阻塞的输出截止。

返回前停止或等待该回调，之后才清理仍未过期的写期限；已到期／已取消的响应不通过清零假设恢复。若取消或 deadline 穿过清零操作，在 owner 返回前重新设置立即截止，避免清理把已取消的响应延期。setter／清理错误继续保留在错误链中。已提交失败仍由未来 13.3 handler 承担 HTTP 异常终止，本层不 panic／recover、不追加错误帧／JSON／Done。
