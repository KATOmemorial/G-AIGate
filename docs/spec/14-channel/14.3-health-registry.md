## 3. 契约（已冻结）

### 3.1 版本化原语（store增量归本L2）

```go
type HealthRecord struct { Snapshot HealthSnapshot; Version uint64 }
type VersionedHealthState interface {
    LoadVersioned(ctx context.Context, channelID int64) (HealthRecord, error)
    CompareAndSwap(ctx context.Context, channelID int64,
        expected HealthRecord, next HealthSnapshot) (bool, error)
}
func NewVersionedHealthState(client *redis.Client) VersionedHealthState
```

同一`gaigate:health:{channelID}` HASH沿既有四字段，新增无TTL字段version，旧快照结构和Load／Save不改。无key为零record，旧四字段无version视为version=0。正int64 ID；旧字段整数范围／bool严格合法，version为uint64；坏数据返回error，不自动抹平为零。next失败数／时间戳不得负，Version=MaxUint64不可递增则error、无写。

CAS必须Redis WATCH／事务比较expected的version及整个快照，匹配后原子HSET四字段＋version+1，保持无TTL并保留未知字段；冲突返回false,nil，不写，不在store里重跑业务判断。可用等价单key原子实现，但须精确支持uint64版本，不能用Lua double悄悄丢精度。ctx取消／Redis错误保留分类；不创建辅助锁key或业务定时器。

14.3为此HASH业务状态唯一写入者，统一走版本接口；不得混用旧Save。原Save的B2语义与回归保留，不声称它是CAS。CAS是14.3新增交付，不回填成11.4历史已有能力。

### 3.2 状态机

HealthRegistry签名保持00 §6.4。构造接收VersionedHealthState、阈值／冷却／state timeout、时钟及安全logger；生产时钟用UTC，测试可控。每次状态操作有StateTimeout总预算（默认500ms），继承更早调用ctx；CAS冲突最多重读重算16次，仍冲突则安全记录失败，不无限阻塞或另起重试goroutine。对外void的Report不能吞掉故障日志，IsAvailable故障返回false。

| 当前状态与事件 | 转移 |
|---|---|
| key缺失／DisabledUntil=0，IsAvailable | true；不创建状态，不看MySQL展示 |
| DisabledUntil非0（无论是否已到期），IsAvailable | false；不自动恢复，不改状态 |
| 未禁用，普通ok=true | ConsecutiveFailures归0；保留探活信息；CAS推进版本 |
| 未禁用，普通ok=false | 失败数+1，饱和于阈值；达到阈值设DisabledUntil为ceil((now+DisableDuration)的unix秒)，确保不早于预算 |
| 已禁用，普通true／false | 无状态变化、不延长冷却、不恢复；在途结果不用于解禁 |
| 未禁用，后台探活成功／失败 | 成功清失败数；失败按一次有效失败计数并可触发禁用；更新最近探活结果 |
| 已禁用且now未到DisabledUntil | 跳过探活；不提前出站 |
| 已禁用且冷却已到，后台探活成功 | 清失败数、DisabledUntil=0，恢复可用 |
| 同上，探活失败 | 保持失败数为阈值，设新的now+冷却（向上到秒），仍禁用 |

计数“连续”以Redis成功提交顺序为准；probe与普通请求的有效失败均为信号，不承诺阈值恰由5个用户请求组成。LastProbeAt为实际已发起探活的完成时间unix秒，LastProbeOk为结果；普通请求不改它们。禁止用冷却半开状态放用户试探，B4的半开仅是后台探测资格。

后台探活开始前保存HealthRecord及实际探测配置指纹（enabled／Provider／BaseURL／映射／所选KeyID、status、密文）；完成先重新读取无缓存配置，不同或已删除则丢弃，再仅CAS该expected一次。任何期间提交的健康状态变化同样令结果过期，不对新状态重算。这防止旧失败／成功覆盖新状态；多个副本同版探活至多一个结果提交。不用开始时间猜代际。丢弃不改LastProbeAt／展示，允许下轮重试。配置重读与Redis提交之间仍有跨存储竞态窗口，不承诺分布式事务或对已在途探测追溯撤销。

只有真正发起的Provider调用才计探活结果；上游HTTP失败／网络／自身ProbeTimeout为false，父任务取消忽略。枚举SQL、缺映射／Key／坏密文等探测配置失败安全记录，不伪装成上游成功，不写健康信号；本批不会因配置故障自动把健康写为正常。

### 3.3 探活任务、展示与配置

```go
type HealthOptions struct {
    ProbeInterval, DisableDuration, ProbeTimeout, StateTimeout time.Duration
    FailureThreshold, ProbeConcurrency int
}
type HealthService interface {
    HealthRegistry
    Start(ctx context.Context) error
    Close(ctx context.Context) error
    Read(ctx context.Context, channelID int64) (store.HealthSnapshot, error)
}
func NewHealthService(channels store.ChannelRepo, keys store.KeyRepo,
    state store.VersionedHealthState, tester ConnectivityTester,
    opts HealthOptions, logger *slog.Logger) (HealthService, error)
```

构造校验依赖与完整配置，不隐式启动。Start只准一次，重复返回普通生命周期错误且不重复起worker；Close取消并等待全部owner，幂等，未Start也可Close，已Close后Start拒绝。Read用于实时HTTP读取，返回原始快照和可分类错误，不吞Redis故障；生产用UTC实时时钟，测试用包内私有时钟注入，不加跨模块clock依赖。Close预算到期仍须确认已取消的有界操作退出，不能只return ctx.Err后继续关闭其仍在使用的Redis；不新建一轮预算掩盖超时。

复用14.1 ConnectivityTester／ProbePicker，每渠道读取最新启用配置及model升序首映射，默认ProbeTimeout=5s，最小非流式chat。手动test继续不喂健康；后台是独立受控任务。每个副本允许重复出站，明确不是全局单探活；由版本提交裁决，多副本不重复累计同版探活结果。

首次启动立即一轮，之后以ProbeInterval调度；一轮未结束不重叠，不堆积tick。固定ProbeConcurrency工作数（默认4），队列有界、最多该数并行网络请求；不为每渠道起无限goroutine。每轮及时响应取消，任何SQL／Redis／HTTP均有ctx预算，不能让枚举SQL无限挂住；枚举使用本轮ProbeTimeout预算，单渠道探测各有同一ProbeTimeout。所有worker有owner、退出等待；使用现有errgroup依赖，不新增第三方库。

state CAS后通过有界、可合并的展示更新队列（最多1024个待处理channelID，满时安全记录并丢弃展示更新）交自有worker，重新读Redis当前状态后镜像MySQLhealth_status／last_checked_at（UpdateHealthView新方法）；不得在请求路径另起goroutine或逐事件无限排队。状态健康=healthy，未有有效探活且未禁用=unknown，禁用=disabled，冷却到期未恢复=cooling。展示允许异步延迟／写故障，不改变IsAvailable；最后checked取最近有效探活，不能把普通请求完成当探活。SQL受StateTimeout预算、只写展示两列、不刷管理updated_at，不覆盖enabled／weight／URL。跨副本展示可能暂时旧值，以实时health为准；Close取消并等待展示worker，剩余展示任务允许丢弃。

不维护error_rate_cache／latency_p99_cache，不把单次耗时称p99，未来18.1／16.2冻结生产者及冷启动排序。无需迁移、新表或新Redis key。

新增`GET /api/v1/admin/channels/:id/health`，同14.1 auth／admin保护，no-store。200白名单：channel_id、enabled、available（enabled且健康允许）、consecutive_failures、disabled_until、last_probe_at、last_probe_ok；后三时间／bool沿快照原值，时间为unix秒。不存在404；Redis失败503 gaigate_health_unavailable，不返回伪零快照。此HTTP可用带error的registry内部读取，不改变跨模块bool接口。

新增ChannelConfig.ProbeConcurrency int（1..64，默认4）、StateTimeout time.Duration（至少1ms，默认500ms）；沿14.1 ProbeTimeout。既有FailureThreshold上限MaxInt32；ProbeInterval／DisableDuration仍>0，DisabledUntil向上到秒，允许正亚秒配置但实际冷却可能多不足1s，须文档化／测试；极端时间加法或unix转换溢出拒绝。全量配置同步结构／默认／env／样例／校验，10.1历史默认不改。

### 3.4 bootstrap与关闭

本L2给bootstrap注入HealthRegistry，从既有enabled候选中按priority／id寻找首个IsAvailable=true，再调用14.2 picker一次。无健康候选503、零上游；绝不在已选渠道调用失败后尝试下一渠道。保留alias校验、摘要、opener、双预算、错误映射与异常终止，新的健康是候选过滤，不是回退。

每次真实attempt结束至多报一次：ResultSuccess为true；StreamInterrupted／TTFBTimeout／OverallTimeout为false；UpstreamError通常为false，但可分类上游HTTP400／404／422视作请求错误、忽略，避免用户坏请求禁用渠道；401／403／429／5xx、网络／协议／重定向失败仍false。ClientCanceled／WriteError忽略；picker／SQL／解密尚未发起不报。先按ResultKind，只有UpstreamError分支再看UpstreamError.StatusCode，不从错误链Canceled反推。固定有效payload的后台探活400仍是失败，与用户请求分类不同。Report用独立有界清理ctx保留request_id，避免上游预算ctx已取消导致合法失败信号完全丢失；不得启动脱离handler的goroutine，最多StateTimeout。分别记录proxy退出与健康上报延迟，不篡改proxy的500ms收敛承诺。

cmd在Redis客户端构造后、HTTP服务前装配registry／worker，并共享真实repo／cache；Redis仍沿惰性连接＋readyz，不偷换启动fail-fast（台账#20仍属20.1）。worker启动失败需清理已取得资源。HTTP停止并处理在途后，先取消并等待worker，再usage drain→Redis→MySQL；取消发出后等待超时不能放任worker继续用已关闭资源，应以自身ctx预算保证退出并验证所有owner等待。原HTTP Shutdown超时与依赖独立预算保持，不扩为无限等待。

## 4. 设计说明

版本字段只为原子状态及晚到结果隔离；不是分布式全局探活租约。禁用到期保持排除与CAS恢复闭合，避免把冷却到时误当健康已证实。Redis缺失视unknown可用，与Redis不可达／坏数据不放行明确区分。
