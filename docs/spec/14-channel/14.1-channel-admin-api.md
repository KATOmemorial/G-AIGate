## 3. 契约（已冻结）

### 3.1 路由与身份

`RegisterAdminRoutes(r gin.IRouter, auth gin.HandlerFunc, isAdmin func(context.Context) bool, service AdminService, tester ConnectivityTester)`注册完整路径，依赖非nil（含typed nil）。先auth，再isAdmin，再读body／调业务；cmd的isAdmin只读标准ctx的access.PrincipalFromContext且Role=store.RoleAdmin。channel不import access，不信body／header中的role或Gin零散值。

| 方法及路径（公共前缀 /api/v1/admin/channels） | 成功结果 |
|---|---|
| GET 前缀 | 200 {"data":[ChannelView...]}，id升序，空[]；本版不分页 |
| GET /:id | 200 ChannelDetail |
| POST 前缀 | 201 ChannelDetail；渠道＋models＋初始Key同一事务 |
| PUT /:id | 200 ChannelDetail；完整管理标量＋全量models，Key不变 |
| DELETE /:id | 204无体；不存在404，不承诺重复成功 |
| POST /:id/keys | 201 KeyView；追加Key，weight=1／status=1 |
| PUT /:id/keys/:key_id | 200 KeyView；仅完整更新weight／status |
| DELETE /:id/keys/:key_id | 204；非本渠道／不存在同404 |
| POST /:id/test | 200 ProbeResult；实际上游失败仍200且ok=false |

ID为正int64，溢出400。无／坏身份401或既有13.1规定的403；已鉴权非admin为403 gaigate_forbidden。拒绝在正文读取、渠道仓储、加密、出站之前；鉴权自身查用户／Key不属于禁止的渠道业务。所有管理响应no-store，错误沿既有OpenAI envelope＋request_id；19.1未来替换session／CSRF，不能漏子路由。此身份过渡已获用户确认，不是裸管理口授权。

### 3.2 输入与视图

有body的POST／PUT仅application/json（允许参数），64KiB先有界读取、恰好合法、+1为413，媒体不符415。单个非null对象，无尾随JSON，拒绝未知字段、每层管理对象重复键（含转义同名）。缺失／null／显式零区分，body不接受id。

- 创建必填name／provider／base_url／models／keys；priority默认0、weight默认1、enabled默认true。PUT必填name／provider／base_url／priority／weight／enabled／models，禁止keys；缺字段400，不作部分更新。
- name非空且最多128 Unicode字符，不trim；provider仅openai，mock通过openai协议接入；base_url最多255字节，为合法http／https绝对URL及端口，无userinfo／query／fragment／opaque，沿adapter路径前缀与/v1语义。允许私网／loopback，不向错误输出URL。
- priority为int32；渠道／Key weight为1..10000整数；enabled为bool。models为1..64个`{"model":"别名","upstream_model":"上游名"}`，两名非空、各最多128 Unicode字符，对外model不得重复，必须在ModelRepo.List中已有，不在此创建别名；未知400。
- 初始keys为1..64个string，每把1..484字节、无控制字符，secret.Encrypt随机nonce且密文不超过512字节，统一weight=1／status=1。POST Key仅`{"key":"..."}`；PUT Key仅必填weight／status，status=0或1，禁止读／改原明文，轮换用新增→停用／删除旧Key。
- 手动test仅`{"model":"本渠道映射的对外名"}`；未知渠道404，无该映射400。允许对enabled=false渠道诊断，不改变enabled／健康／Key权重。

ChannelView仅id、name、provider、base_url、priority、weight、enabled、health_status、last_checked_at、created_at、updated_at。Detail另含models（model升序）与keys（id升序）。KeyView仅id、channel_id、weight、status、created_at；绝不返回明文／密文／hash，不解密生成前缀。时间UTC RFC3339，空last_checked_at为null，空集合[]；列表不带Key集合，不直接序列化ORM模型。

服务侧CreateChannelInput／UpdateChannelInput按上述字段与取值冻结：HTTP先区分缺失并补创建默认，再转为完整服务输入；服务侧不接受“缺失即局部更新”。输入模型使用ModelMappingInput（Model／UpstreamModel string），不是带ChannelID的ORM映射。服务及构造接口：

```go
type AdminService interface {
    List(context.Context) ([]ChannelView, error)
    Get(context.Context, int64) (*ChannelDetail, error)
    Create(context.Context, CreateChannelInput) (*ChannelDetail, error)
    Update(context.Context, int64, UpdateChannelInput) (*ChannelDetail, error)
    Delete(context.Context, int64) error
    AddKey(context.Context, int64, string) (*KeyView, error)
    UpdateKey(ctx context.Context, channelID, keyID int64, weight int32, status int8) (*KeyView, error)
    RemoveKey(ctx context.Context, channelID, keyID int64) error
}
func NewAdminService(channels store.ChannelRepo, keys store.KeyRepo, models store.ModelRepo,
    invalidator store.Invalidator, masterKey []byte) (AdminService, error)
```

构造检查nil／typed nil与32字节masterKey并复制密钥。视图字段／JSON命名按上文，不以ORM对象作HTTP DTO。服务重验输入合法性；HTTP无效输入零写／出站，随机／加密失败不返回部分结果。

### 3.3 store增量与事务

复用既有ChannelRepo.Create／Delete及KeyRepo.ListByChannel；新签名见00 §6.10：ChannelRepo.List、ListModels、UpdateConfig，KeyRepo.CreateOwned、UpdateOwned、RemoveOwned。新增方法不缓存，旧签名／语义不变，fake同步，业务不直接SQL。

UpdateConfig事务内锁既有父渠道，更新管理标量并全量替换映射，失败整体回滚，同值成功不误报404，不改健康列／Key／created_at。三个Key Owned方法事务锁父行，查询及更新以channel_id＋key_id约束；既有ChannelRepo.Delete须先锁同一父行再级联删除，与Owned统一锁序，保留旧缺失／级联语义，避免并发后新插入孤儿。UpdateOwned同值成功且密文／created_at不变。加密、HTTP等待不放事务锁内。

管理写成功调用与/v1共享的Invalidator.InvalidateAll；失败不失效。失效保证正常串行写后读，沿既有singleflight／TTL取舍，不新增多副本强一致承诺。Create后的响应读取失败可能写已提交，不能把失败响应承诺成“绝无写入”；测试须区分写前失败、事务回滚和提交后响应失败，客户端可重新列表确认。

删除沿现有事务级联models／keys，保留model_aliases的default_channel_id／fallback_ids，不隐式删别名或重排回退链。16.1须过滤不存在渠道、全空503；该引用语义登记台账。Key新增在父不存在时404；所有SQL故障500并保留内部分类，不输出敏感cause。

### 3.4 最小探测与装配

本L2声明channel.EndpointPicker／HealthRegistry（00 §6.4／§6.10）；SWRR实现归14.2。交付`NewProbePicker(channels store.ChannelRepo, keys store.KeyRepo, masterKey []byte) (EndpointPicker,error)`，仅用于探测：首个id最小active Key→GetModel→secret.Decrypt→独立Endpoint；不因enabled=false拒绝手动诊断。Key缺失包装provider.ErrNoCandidate；SQL／坏密文／provider不符为内部错误。不接管B3业务，不动SWRR位置。

`ConnectivityTester.Test(ctx context.Context,ch *store.Channel,model string) (ProbeResult,error)`；`NewConnectivityTester(picker EndpointPicker, upstream provider.Provider, timeout time.Duration) (ConnectivityTester,error)`构造并校验依赖。ProbeResult仅ok bool、latency_ms int64（总调用耗时，非TTFB／p99）、status_code int（无响应0）、reason枚举success／upstream_error／timeout。

固定非流式user消息content=ping、Extra.max_tokens=1，使用Provider.Chat。ctx派生总预算覆盖picker／解密／Chat，更早父ctx优先；不接收任意messages／header／Key／场景覆盖。实际发起后的上游失败／超时是ProbeResult(ok=false),nil；配置／SQL错误→500，缺Key→503，无映射请求→400，渠道缺失404。父取消不追加响应。结果不带上游body／URL／cause／Key，手动测试不喂健康结果。

ProbePicker与后续正式picker复用channel内部的端点校验／组装辅助，复用secret，不复制协议实现；不同只在选Key策略及是否允许禁用渠道。channel不import具体openai，由cmd注入。故障通过自有mock控制API设置，不改mock、不扩adapter测试header。

cmd最小修改：共享同一ConfigCache供admin和/v1，注入现有Bearer／admin判定及Provider，注册实际管理路由；不改变bootstrap当前首渠道／首Key、proxy或鉴权实现。新增ChannelConfig.ProbeTimeout time.Duration，yaml channel.probe-timeout、环境GAIGATE_CHANNEL_PROBE_TIMEOUT，默认5s、至少1ms；配置结构／加载／默认／校验／样例／测试本L2交付。CLI不会因此启动任务或改变其初始化预算。
