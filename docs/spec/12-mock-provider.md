## 1. 模块边界

**做什么**：独立进程 `cmd/mockprovider`，服务逻辑位于 `internal/mock`；提供 OpenAI chat 子集端点、五种故障场景、按上游测试 Key 隔离的场景控制、可复用验收脚本。只依赖 Go 标准库和仓库已有第三方库，不 import 任何其他 `internal/*` 包，不读取 MySQL／Redis，不要求网关启动。

**不做什么**：真实推理、真实鉴权、完整 OpenAI 协议、`/v1/models` 或 `/v1/responses`、网关计量和路由。它**不是** `provider.Provider` 的实现；13.2 的适配器将它当作普通 HTTP 上游。本轮对齐 00 §5.2，消除旧依赖图把 mock 写成 Provider 实现的矛盾。

宿主默认监听 `127.0.0.1:18080`；仅显式设置 `MOCK_ADDR=:18080` 才监听容器所需的所有接口。20.1 负责容器网络隔离和端口映射。控制面与数据面共用端口，仅用于隔离测试环境；不传入真实供应商密钥。

## 2. 场景协议（跨模块验收输入，细则由 12.1／12.2 定义）

**隔离单位**：`Authorization: Bearer <测试 Key>` 中的完整测试字符串作为场景 ID；不是网关用户 Key 校验。控制接口使用同一字符串；seed 的 `sk-mock-a`／`sk-mock-b` 可直接使用。

**优先级**：合法的 `X-Mock-Scenario` 单请求覆盖 > 该 Key 已存场景 > 默认 normal。覆盖只改变场景名，保留该 Key 的完整参数快照；未知覆盖名或覆盖后参数不适用于该场景时返回 400，不修改存储配置。

**一致性边界**：请求通过输入校验后只解析一次场景及参数，释放锁后执行。Set 返回后开始解析的新请求读到新配置；在途流、延迟请求沿用原快照。控制面不等待慢流结束，不在计时、写网络或 sleep 期间持状态锁。

| 场景 | 流式 | 非流式 |
|---|---|---|
| `normal` | N 个内容帧，按选项附 usage，再发送 [DONE] | 单个完整 JSON，始终含 usage |
| `slow` | 写任何响应头／字节之前延迟 D，再走 normal | 延迟 D 后返回 normal JSON |
| `downtime` | 503 JSON；或 refuse 模式在 HTTP 响应前断连 | 同流式 |
| `rate_limited` | 429 JSON，`Retry-After: 1` | 同流式 |
| `interrupted` | 已发送 k 个内容帧后异常中断，无 usage、无 [DONE] | HTTP 响应前断连；不构造半段 JSON |

`refuse` 为保留的场景参数名，实际指**接受连接后关闭当前请求连接**，不等同于未监听端口造成的 TCP connection refused，也不得关闭共享 listener。若未来测试必须覆盖连接建立失败，脚本另选未监听端口，不改变这个参数含义。

**帧计数**：正常流的内容帧固定 N；usage 帧是另一个 JSON data 帧；[DONE] 是单独结束标记。默认 N=8，开启 usage 时共 8 内容 +1 usage +1 DONE，合计 10 个 SSE data 事件。不得把所有 data 行都算作内容帧。具体 payload、参数默认与合法域见 12.1 §3。

## 3. 关键设计决策

1. **独立 HTTP 进程**：适配、首字节超时、取消和流式中断必须穿过真实 HTTP/TCP；ResponseRecorder 不能单独证明断流。
2. **快照隔离而非修改在途流**：场景切换可立即编排后续故障，同时让一条响应可重复、可解释。返回成功即完成更新，不依赖传播等待。
3. **完整替换 + 默认补齐**：每次 PUT 从全局默认参数出发，叠加本次显式字段，再一次性校验、替换；不继承前次 PUT 的参数。持续状态仅在进程内，重启清空。
4. **传输中断须有错误证据**：interrupted 不能仅少发 [DONE] 后正常 return，验收须同时证明内容已收到、结束标记缺失、读取失败，且服务仍可处理后续正常请求。

## 5. 风险与已定取舍

- 默认仅 loopback；容器需显式覆盖地址。不是通过“无鉴权但默认监听所有接口”兑现本机设施。
- 故障注入仅支持本地明文 HTTP/1.1；不承诺 HTTP/2／TLS 断流语义。具体 EOF／reset／curl 非零码取决于客户端，验收不锁死一个 OS 错误字符串。
- 正常 SSE 正文是模板文本；usage 是参数给定的合成值，并不与模板字符数或 max_tokens 自动一致。它验证计量取值路径，不模拟真实 tokenizer。
- 锁与快照需要并发验收并执行 -race；中断、取消路径不能泄漏 handler／连接。20.1 接管全链部署，不在此引入网关依赖。

## 6. 验收要点

- 12.1：五场景流式／非流式、输入错误、场景隔离／快照、取消、进程启动均有行为断言；真实连接上证明中断。限定测试及 -race 绿，补齐工程基线。
- 12.2：控制 API 验收、source 无副作用、五场景脚本和 B2 检查点实际执行。脚本只使用 bash、curl 及 POSIX 文本工具，不要求 jq、Python、网关或在线模型。
- 业务失败场景使用 mock 自己的上游错误体，不冒用网关的 `gaigate_` 哨兵／错误码。
- 合并前按 01 §6 完成相应回归、lint、独立审查和验收记录；测试依赖未启动导致的 SKIP 不算完整 B2 通过。
