## 1. 模块定位

将公开模型别名解析为有序、去重、无密钥的Plan。16.1负责候选集合与过滤、16.2负责集合内排序、16.3负责实际许可、16.4负责选Key及执行；本L2不把健康过滤写成自动重试。

## 2. 目标／非目标

- 交付router类型、候选解析、Router编排、只读依赖注入和router.route-timeout配置。
- 消费#21／#31的未来接缝，准备移除bootstrap；本份不替换生产网关，也不关闭整项台账。
- 不查询渠道Key、不解密、不推进14.2 SWRR，不调用Provider／proxy，不实现策略或Redis熔断，不新增表／迁移／后台任务／依赖。

## 3. 冻结契约

类型Candidate／Plan／RouteStrategy／BreakerState及三态常量／BreakerView／BreakerInspector／Router以00 §6.11为准，由本L2首先声明；Permit／BreakerOutcome／Breaker完整接口及行为由16.3交付，不重复定义已有三态类型。可选接口采用显式依赖，不用生产AllowAll breaker假装正式可用。

```go
type Orderer interface {
    Order(ctx context.Context, model string, strategy RouteStrategy,
        candidates []Candidate) ([]Candidate, error)
}
type RouterOptions struct {
    DefaultStrategy RouteStrategy
    RouteTimeout    time.Duration
}
func NewRouter(models store.ModelRepo, channels store.ChannelRepo,
    health channel.HealthRegistry, breaker BreakerInspector, orderer Orderer,
    opts RouterOptions, logger *slog.Logger) (Router, error)
```

构造校验nil及typed-nil依赖、策略、正整毫秒RouteTimeout（1ms..1min，默认2s）。本L2在config.RouterConfig增RouteTimeout，默认／GAIGATE_ROUTER_ROUTE_TIMEOUT／yaml样例／fail-fast完整同步；DefaultStrategy沿既有字段。构造及Route不隐式打开数据库或Redis。

### 3.1 输入与别名

Route继承更早ctx，并为整个解析及排序建立一次RouteTimeout，不为每个repo／候选刷新预算。已取消及时返回、保留ctx与cause。内部输入须非空有效UTF-8、原值匹配，不trim／大小写转换；不递归解析UpstreamModel为另一个别名。现有HTTP入口只校验非空字符串，数据库别名最多128字符；超过128字符不可能命中，应直接返回access.ErrModelNotFound／404，不将它误报内部500或新增入口400规则。

ModelRepo.Resolve必须命中；ErrNotFound包装为access.ErrModelNotFound，保留原错误供errors.Is。nil别名、返回Name不匹配或显式非法strategy为普通配置错误；不误报404。有效策略显式参数优先，Auto再取非空alias.Strategy，否则全局DefaultStrategy；非法别名strategy不静默换默认。现有DDL／seed将strategy写为weighted，这仍算别名显式值，改变全局默认不会覆盖该值；本轮不通过猜测“默认值等于未设置”改变数据库含义。HTTP入口只传Auto，不消费用户header／Extra的路由要求。

### 3.2 候选集合

| 策略 | 初始集合与顺序 |
|---|---|
| fallback_chain | default_channel_id非nil在先，再ParseFallbackIDs得到的ID；按首次出现去重，逐项ChannelRepo.Get读取，绝不额外并入其他渠道 |
| weighted／cost_first／latency_first | ChannelRepo.ListActiveByModel公开别名对应的全部候选；复制后按priority降序、ID升序建立稳定输入 |

ID必须1..MaxInt64；default为nil合法，0／超范围为坏配置。fallback成功解析出的uint64项若为0或超过MaxInt64，同样拒绝；文本空／JSON null为无回退，坏JSON／类型（含负数、小数、字符串项）沿store.ParseFallbackIDs整体视无回退，不先另造严格解析器改变helper语义。调用该helper前限制原始文本最多64KiB，超限报配置错误，不改store解析语义。删除的引用匹配ErrNotFound时过滤，其他SQL错误终止。有效唯一初始集合最多64；超限先报错、不截断，不借健康过滤掩盖超大配置。重复的仓储行按ID归并，内容不一致须报配置错误。

每项依次检查enabled和ID／Provider=openai／weight=1..10000等有效标量；禁用项过滤，非法配置报普通错误。读取GetModel(channelID, 对外别名)，缺mapping过滤；校验ChannelID／Model匹配、UpstreamModel非空有效字符串（沿14.1名称范围）。Candidate保存渠道值副本与该映射名，不含Key；拷贝LastCheckedAt等指针，返回值不得反向修改缓存对象。

然后只读health.IsAvailable与breaker.Inspect；health=false、Eligible=false过滤；Inspect的显式error终止，不把Redis坏数据当“没有候选”。不得调用Acquire／Complete，也不根据MySQL health_status／error_rate_cache／latency_p99_cache放行。未知breaker状态或无效view须报错，不当closed。无候选返回provider.ErrNoCandidate。

### 3.3 排序与快照

仅对过滤后副本调用Orderer一次，校验其输出为同一组候选的排列：不能新增、丢失、重复或篡改渠道／映射。返回Plan.Model为原公开别名、Strategy为已解析策略。零候选不调用orderer。输入对象及内部缓存不被排序原地修改；同请求的Plan不受随后配置对象变更影响。

Plan是请求内乐观快照，不是跨SQL／Redis事务；现有配置TTL仍60s。实际执行再查健康与许可，Pick时映射变更会由16.4跳过；本L2不承诺删除／禁用即时全副本生效，也不将一次规划视为半开预留。

## 4. 设计说明

生产newRouter直到16.2／16.3交付后才在16.4装配。本份验收可用有行为断言的Orderer／Inspector测试替身，清楚标注不是正式breaker。依赖接口采用最小只读投影也可，但正式构造签名及语义不得由实现会话另改。所有错误日志固定阶段／request_id／安全channel_id，不输出BaseURL、Key、完整alias配置或上游正文。
