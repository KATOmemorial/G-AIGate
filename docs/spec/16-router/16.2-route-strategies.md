# 16.2 路由策略与本地延迟样本（L2）

> 状态：v0.11施工候选，2026-10-30，待用户review，未冻结／实现。上游：[16-L1](../16-router.md)／00 §6.11。批次：B5；前置：16.1完成独审及授权交付。

## 1. 模块定位

对16.1生成的无密钥候选集排序。四个策略都产出完整的不重复排列，16.4消费次序；本模块不出站、不调用picker或breaker，不做用户额度或实际计费。

## 2. 目标／非目标

- 实现Orderer及可被16.4同步喂样本的StrategyEngine；weight归渠道，SWRR仍归14.2的Key。
- 处理#32的latency_first数据来源／冷启动；MySQL两展示列生产、Prometheus／OTel及页面仍后置，不关闭#32整项。
- 不新增价格维度／DDL、secret、后台采样worker或跨副本延迟Redis协议，不改11.2 PriceRepo缓存。

## 3. 候选契约

```go
type StrategyEngine interface {
    Orderer
    ObserveSuccess(ctx context.Context, channelID int64, model string, elapsed time.Duration)
}
func NewStrategyEngine(prices store.PriceRepo, logger *slog.Logger) (StrategyEngine, error)
```

构造校验依赖及typed-nil，不启动服务。生产时钟／随机源用标准库；为确定性边界测试提供包内私有时钟与随机源注入，不新增跨模块clock或随机框架。ObserveSuccess是有界内存操作，ctx只承载请求值、不做外部I/O；输入非法丢弃并安全记录，不能panic或改变既有响应。

### 3.1 共同规则与priority

拒绝未知策略、非16.1有效候选、重复ID／非法权重及超过64项，不修改任何输入slice、channel指针或字符串存储。fallback_chain仅保留16.1给定次序；其他策略先按Priority降序分组，只在同priority组内应用算法。相同主排序值按Channel.ID升序，跨组不得越级，保证低优先级为后备。所有Order均继承Route总ctx／deadline，SQL走同一ctx，取消保留cause。

### 3.2 weighted

同组从剩余候选中按正整数Weight抽取一个，移除后继续，形成加权不放回排列；首位P(i)=w_i/sum(w)。输入先按ID归一化，随机ticket覆盖[0,sum)且不偏一；权重与总和用检查过的int64（每项1..10000、最多64）。不是每请求先抽一次后把其余按ID，也不是对Key再次做SWRR。默认随机源并发安全，不用固定seed导致所有副本同序；允许生产非确定，测试必须注入可复现ticket。

### 3.3 cost_first

Route开始取同一UTC now快照，每个不同UpstreamModel最多查询一次PriceRepo.Effective(ctx, model, now)。按InputPricePerM+OutputPricePerM从低到高；价格均须非负、Currency=CNY，使用精确比较避免int64加法溢出，不用float32或按本请求max_tokens猜成本。

ErrNoPrice表示未知价格，放在同priority所有已知价之后；全未知退化ID顺序。真实SQL／ctx错误返回error，nil／负价／不支持币种为坏配置。相同映射模型同价，无渠道ID价格列，不拿对外别名单价假装不同渠道的独立成本。这个等量输入／输出的代理排序不替代17.3的整数计价；当前PriceRepo的60s当前时刻缓存继续有效，不使用历史at查询假装精确生效切换。

### 3.4 latency_first与样本

自有内存表按(channelID, 对外别名)隔离，记录ResultSuccess的完整实际attempt耗时（单调时钟差，Duration），不记录FirstByteMs／端到端总请求／probe或失败。窗口为本实例(now-60s, now]，每键按到达顺序最多最近256个有效完成样本，至少5个才算已知；排序取nearest-rank第ceil(0.99*n)个耗时。0耗时有效、负值拒绝；移除过期在采样与读取时发生。

同priority先已知p99升序，再未知；同值和全部冷样本按ID。不人为加测、不因为未知就出站探测，不从MySQL latency_p99_cache／error_rate_cache读取。样本是本实例最近成功请求的有限集合，不能对外宣称全量跨副本P99；进程重启冷启动是允许行为。

最多4096个键，写入新键超限先淘汰最久未ObserveSuccess键，时间同值按(channelID,model)排序确定；读取不刷新该时间。每键内存有界，锁只覆盖表与样本拷贝，排序／日志／PriceRepo均在锁外。无定时器或后台goroutine；并发Order与Observe无竞态，不保存原请求、正文、Usage指针或Key。新策略算法／TTL不另增用户配置。

| priority | 每策略跨组保持优先级；fallback_chain严格原链；同值ID、空集与单项 |
| weighted | 6:3:1注入ticket精确覆盖6／3／1首位；全排列无重复缺失，后续条件权重正确；输入乱序归一化、零／负／越界、并发随机安全，不能只跑统计大样本碰运气 |

## 7. 风险与移交

cost代理依赖upstream模型名有价格，不保证给出每渠道采购价；未知价后排是已声明取舍，不改变B6无价格降级。成功延迟存在选择偏差、有限样本及副本差异，保留冷启动确定性；本候选不主动探索未知渠道，完全冷时ID在先的渠道会先累积样本，未被实际尝试的渠道可持续未知，不能宣称自动发现所有渠道的最优延迟。#32仅数据来源与排序部分折入本份，展示列／聚合／页面及#11完整更新语义归原owner。
