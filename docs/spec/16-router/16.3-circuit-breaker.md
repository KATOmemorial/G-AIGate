## 1. 模块定位

在多个网关副本间共享时间窗口、三态及单个half-open探测许可。16.3自持Lua；store只提供既有Redis客户端，不把业务状态机塞回11.4，不读取或修改14.3健康HASH。

## 2. 目标／非目标

实现00 §6.11的Inspect／Acquire／Complete，替代尚未实现的旧Allow／OnResult候选。许可支持中性释放、回报去重、晚到结果隔离及持有者消失后的恢复；不以进程锁实现全局单探测。

本L2不调用上游、picker、proxy或HealthRegistry，不启动probe／后台清理worker，不接生产网关、不新增管理API／依赖／MySQL字段。Redis惰性连接及readyz基线不变，启动fail-fast #20仍归20.1。

## 3. 冻结契约

```go
// BreakerState复用16.1已声明的三态类型，不重复声明。
type BreakerOutcome string // success/failure/neutral
type Permit struct { /* 不透明且不可变；只由16.3生成 */ }
type BreakerOptions struct {
    Window, OpenDuration, StateTimeout time.Duration
    MinSamples int
    ErrorThreshold float64
}
func NewBreaker(client *redis.Client, opts BreakerOptions, logger *slog.Logger) (Breaker, error)
```

接口以00为准。构造拒绝nil、非法时长／样本／NaN或Inf阈值，不做Redis I/O；原默认60s／20／0.5／30s，新增StateTimeout=500ms。router.state-timeout完整配置由本L2交付；既有window／openDuration细化为1ms..1h正整毫秒，minSamples=1..1000000，阈值为1..1000000的整数百万分比。最多六位小数，不能静默四舍五入；十进制浮点解析的机器舍入可规范化，但规范化规则／容差须有边界测试。拒绝0／负／非整ms／越界／非有限值不访问Redis。

### 3.1 操作、时间与错误

每个公开操作继承caller更早ctx及一次StateTimeout，无内部无限重试，不新开超时；共享store.NewRedis的ContextTimeoutEnabled配置，单独伪造client必须同样遵守deadline。发生错误保留errors.Is／cause，安全文本不包含Redis地址／上游凭据。Redis错误不能转成closed；Acquire返回nil,nil仅表示本次被状态／容量拒绝，error表示未知／坏状态。

Inspect使用只读Lua及Redis TIME，缺失三类key时返回closed／Eligible=true但不初始化。校验状态与关联key类型，closed且有容量、open到期、half-open lease到期时才有领取资格；活跃half-open返回false。它不得清理TTL、裁剪窗口、写HASH或预占许可，100次Inspect之后仍只有零次Acquire。

Acquire在同一次原子脚本中校验／清理到期许可、判断资格、登记token并返回permit。closed也登记，最多4096个尚有效在途许可；到容量时拒绝新领取，不抢占／丢弃旧许可。lease是Duration，调用者按00剩余预算规则生成；库接受1ms..24h正整毫秒，不延长ctx。token每次Acquire唯一、epoch与token均为不透明字符串，不转Lua double或靠时间戳相等判重。

Lua中的权威时间为TIME毫秒，不接受实例wall clock替代。窗口是(now-window,now]，完成结果按Complete实际处理时刻落样本，open_until／lease_until均同一时钟。以TIME所得精确整数及检查过的毫秒加法操作；channelID只用于规范化十进制key，不经Lua浮点重新编码。数值超出Lua安全整数或统计乘法上界时返回error，不近似比较。非正channelID、nil／零值／非法permit、未知outcome在Redis前拒绝；合法但已失效的permit则沿幂等无当前状态变化语义处理。

### 3.2 三类key与原子性

| key（同一channelID hash tag） | 内容与生命周期 |
|---|---|
| gaigate:breaker:{channelID} | HASH：schema/policy指纹、state、epoch、open_until_ms、probe_token、probe_until_ms；不TTL |
| gaigate:breaker:events:{channelID} | ZSET：score=完成TIME毫秒，member=唯一token＋success/failure标记；每次有效Complete裁剪旧样本，TTL至少覆盖最后完成时刻起一个完整Window |
| gaigate:breaker:pending:{channelID} | ZSET：score=lease截止毫秒，member包含epoch／唯一token／许可类别；Acquire／Complete原子维护，TTL不早于仍有效的最大lease截止 |

三key供同一Lua的KEYS显式传入，不动态拼出跨slot key。HASH缺失但其他key存在、错误类型、字段缺失／坏枚举／非法数值等为坏状态，不能自动抹平。half-open未过期的probe必须有对应pending，否则error；probe过期后pending自然到期允许重领。未知HASH扩展字段保留，不顺便改健康／配额key。

所有类型／字段／参数／新结果数值检查先于任何写入；Lua脚本运行中报错不会替你回滚已执行的写，必须设计并用零写见证证明非法输入不产生部分裁剪／记数／转态。正常操作允许清理已过期pending；旧epoch／过期结果不改当前窗口与状态，过期许可自身的清理不冒称“全key逐字零写”。

策略指纹包括schema版本、Window、MinSamples、阈值百万分比、OpenDuration及4096容量口径。多副本不匹配时fail closed并安全报错，不自动重置反复翻转。修改策略的运行约定为协调停流、显式清理该渠道这三类key后重新建立，不能只删HASH；B5不附带线上一键清空工具或裸重置接口。

### 3.3 状态转移

| 当前与事件 | 原子结果 |
|---|---|
| 全部key缺失，Acquire | 初始化closed新epoch，登记closed permit |
| closed，Acquire | 保持epoch／状态，登记permit；不计请求样本 |
| closed，有效Complete success/failure | 消费pending，记一个样本并裁剪窗口；n>=MinSamples且failure/n>=阈值则open，open_until=now+OpenDuration，换epoch |
| closed，中性Complete | 只释放该许可；窗口／状态不变 |
| open且未到期，Acquire | 拒绝，不延长冷却 |
| open且到期，Acquire | 转half-open，新epoch／唯一probe token，登记lease；同轮其他副本拒绝 |
| half-open且有效probe未到期，Acquire | 拒绝 |
| half-open probe到期，Acquire | 原probe失效，新epoch／token替换，只放行一个 |
| 有效probe success | 清窗口，closed新epoch，解除probe |
| 有效probe failure | open新epoch，新一轮now+OpenDuration |
| 有效probe neutral | 回到可再次领取的open（open_until=now），新epoch；不声称恢复、不添加成功／失败样本 |
| 重复／失效／旧epoch Complete | 无当前窗口／状态变化；不释放其他token，不覆盖新probe |

窗口包含所有有效完成样本，不按“最近N条”截断；同毫秒的两次结果因token不同必须计两次。closed切open后，旧closed请求再成功不能关闭新open；半开旧探测超时后成功也不能释放新probe。到期比较now>=until，不因主动Inspect提前转态。失败占比为failure*1000000 >= n*thresholdPPM的精确比较，零样本不除零，最小样本是总成功＋失败数；中性不进分母。

### 3.4 去重、丢回包与并发

Complete仅消费本permit对应、未过期且epoch有效的pending一次；重复脚本执行不重复入样本。closed与probe都要具备相同幂等保证，不能只给half-open加token。

Acquire内部生成的请求token在一次公开调用及go-redis透明命令重试中保持一致。重复执行同一有效token的脚本返回同一许可／截止，不新分配或延长lease，避免服务器成功但回包丢失导致重复占位；若调用方最终收到error，不出站，遗留许可至多存活到原lease。NOSCRIPT回退沿现有Script机制，不因脚本cache miss丢样本。Complete丢回包后重试同permit同样幂等。

Redis时钟、配置、网络故障可能使一次反馈丢失；16.4记录安全失败，不伪造成功。不存在进程内全局single-flight保证，不依赖本地mutex保护跨实例状态。lua源码归internal/router，不修改模块缓存／store业务接口。

## 4. 设计说明

健康连续失败／后台探测和breaker滑动窗口／half-open是两套独立状态机；16.4从同一实际结果分别映射。health恢复不自动closed breaker，breakerclosed也不能绕过health=false。客户端取消或写失败不是上游故障，需要neutral释放probe，否则既不该把它判成功，也不能无限占名额。

### 11.2 M1实现及§5覆盖范围

库构造要求显式Options且零Redis I/O，不沿16.1零值默认；同时拒绝未启用ContextTimeoutEnabled的自建client，保证注入client具备既有store.NewRedis的deadline语义。配置层默认与StateTimeout新字段及既有参数细化仍归M2，本轮未提前修改internal/config或样例。私有阈值规则为：先拒绝非有限及范围外值，再要求与整数PPM的十进制canonical值相差不超过其向上两个binary64 ULP；不以固定十进制容差四舍五入。合法六位十进制、相邻ULP、三ULP、额外小数、NaN／Inf和上下限已有测试，M2须在配置私有校验中保持相同口径。

生产Lua只用Redis TIME；测试通过自有miniredis.SetTime／FastForward推进TIME，溢出用例仅替换测试实例私有script，不导出clock或用实例wall clock代替生产权威时间。三key显式传入KEYS，同一规范化十进制channel hash tag；epoch／token使用128bit随机字符串，不经Lua数字转换。Inspect使用Script.Run的只读分支，在任何写入前返回；未采用miniredis不支持的EVAL*_RO命令。只读性以连续100次Inspect前后完整数据和TTL不变、冷启动零key与后续Acquire仍可领取见证，不能将仅脚本缓存加载计作业务状态写入。

Lua先完成类型、字段、指纹、pending／events成员、精确整数和新计算结果检查，再进入集中commit段；所有正常写入目标的类型已验证，保留HASH未知扩展字段。events保留完整有效窗口；pending不截断有效许可，TTL取最大截止，HASH不TTL。ZSET score可用指数形式返回精确整数，须单独检查有限、安全整数及非负；HASH／ARGV字段仍严格十进制解析。Acquire在一次调用中固定token，重执行同有效token返回原epoch／类别／截止而零写；Complete仅消费有效pending一次。无进程锁、后台任务或共享store／health改动。
