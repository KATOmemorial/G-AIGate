## 3. 冻结契约与构造

```go
type ExecutorOptions struct {
    Forward proxy.ForwardOptions
    StateTimeout, PreparationTimeout time.Duration
    MaxAttempts int
}
func NewExecutor(picker channel.EndpointPicker, upstream provider.Provider,
    forwarder proxy.Forwarder, breaker Breaker, health channel.HealthRegistry,
    strategies StrategyEngine, opts ExecutorOptions, logger *slog.Logger) (Executor, error)
```

StateTimeout采用min(router.state-timeout, channel.state-timeout)，PreparationTimeout沿router.route-timeout；MaxAttempts沿新router.max-attempts（默认3，1..16），本L2同步config字段／env／yaml／校验／样例。Forward不改15的签名／配置。校验nil／typed-nil、正时长、许可lease上限：Forward.OverallTimeout＋StateTimeout＋500ms须不超过24h，先检查余量／加法溢出再计算，不能让Duration溢出后绕过上限；无舍入延长真实ctx，不把新校验回填成10.1历史已有。

00类型为权威；构造只组合依赖，不联网或启动worker，不允许生产test-only breaker／空forwarder替代。首次生产接线必须同时启用16.1真实repo、16.2同一StrategyEngine、16.3同一Redis及本执行器。

### 3.1 请求级预算与适配

在cmd装配侧使用不含选择逻辑的适配器实现access.ChatExecutor：进入时从原请求ctx建立一次OverallTimeout逻辑ctx，先Router.Route(Auto)再Executor.Execute；所有SQL／Redis／Pick／Provider继承该逻辑ctx及更早父期限。适配器可留internal/bootstrap作为薄接缝，但原executor选择／执行代码及TODO #21/#31须移除，不能保留双套可切换生产路径。

每次proxy仍以传入opener开始独立TTFB／Overall计时；后续attempt不会刷新逻辑请求总预算。选路超时、候选准备超时和逻辑耗尽按阶段记录，不伪造proxy的FirstByteMs或结果Kind；逻辑deadline在尚未提交时返回access.ExecutionError{TimedOut:true}沿既有502映射，父主动取消保持取消不写响应。局部Route／准备deadline到期但逻辑预算尚有效时为内部阶段错误500，不置上游TimedOut或自行换渠道掩盖SQL／状态服务超时。proxy已锁存的OverallTimeout不能因错误链含Canceled降为ClientCanceled。

Execute亦校验非nilPlan／req／principal／writer、plan.Model=req.Model、Strategy合法、候选有效／唯一且<=64；不得自建匿名Principal或接受任意外部Plan出站。直接库调用Executor时也从同一父ctx限制最多Forward.OverallTimeout，已有适配逻辑期限更早则不延长；不会通过两次WithTimeout叠加成两份预算。

### 3.2 候选与许可生命周期

顺序：检查逻辑ctx／writer未提交→候选健康重检→Acquire许可→一次Pick→校验Endpoint→proxy。health=false、无permit可跳过；不得在Route里提前Acquire或在这里再调一次Inspect抢名额。Acquire的lease由当前逻辑剩余时间＋一次StateTimeout＋500ms向上到毫秒生成、上限24h；仅许可失联保护，不重开执行预算。

每候选准备包含健康／Acquire／Pick／Endpoint检查，统一PreparationTimeout并继承逻辑剩余；不能给每一项再开2s。实际opener使用proxy传入的ctx，而非准备ctx（准备ctx完成后取消不能误杀后续attempt）。已经取得许可时，所有准备失败／父取消／panic退出均须neutral Complete，回报在同步有界清理范围内；不得泄漏probe名额或让清理阻塞下一候选无限久。panic清理后沿原ErrAbortHandler／Recover协议传播，不recover成普通成功。

仅provider.ErrNoCandidate（如无Key）、mapping ErrNotFound、或Endpoint.Model与Candidate.UpstreamModel不一致等明确失效项可neutral后跳过；SQL／坏密文／错误Provider／Endpoint字段与ChannelID／Provider／BaseURL不匹配为真实配置错误，终止而不报上游故障。Endpoint读取后的Key只在本attempt局部，不入Plan、日志、错误body或跨请求缓存。映射变更时不覆盖Endpoint.Model拼出旧计划，不在当前请求重读重规划。

通过检查后才设置middleware.WithChannelID及记录真实attempt；为保证完成摘要只对应真实出站，正式channel摘要在opener真正被调用时同步更新，不能由跳过／仅Pick的候选覆盖。Provider的ChatRequest是共享只读对象；不改req.Model／Messages／Extra，用Endpoint.Model由适配器映射上游模型。

Stream走Forward，非流式走ForwardNonStream；整个尝试包括proxy关闭Stream／网络、定时器与下游写控制退出，返回后才能考虑下一个。每channel至多一次，MaxAttempts只计真实opener调用；跳过项不计上游尝试，但候选总数与逻辑总预算仍限制遍历。不得同渠道换Key、偷偷调用Provider自带重试或等待Retry-After。

### 3.3 重试矩阵及终结

必须逐项执行00 §6.11表：WroteHeader=true绝不回退；父／逻辑取消、下游写失败、成功、HTTP400／404／422、401／403或其他不可重试协议错误均停止。仅尚未提交的TTFB／Overall／StreamInterrupted，或匹配UpstreamError且Retryable=true，才在有剩余预算／次数／候选时继续。不能因为HTTP状态是5xx就无视Kind／WroteHeader，也不能只凭errors.Is(Canceled)推翻Kind。

在同一个真实WrapWriter→Gin→net/http writer上串行多attempt，不能为下一次造新ResponseRecorder掩盖残留头／写deadline；提交前失败不得写错误响应或Flush成功头。保留15.2自身清理逻辑，测试验证可复用；若发现已交付proxy接缝缺口交主会话裁定，不自行改Provider／proxy／middleware冻结行为。

无任何opener且候选耗尽→ErrNoCandidate（503）；有实际失败后耗尽→最后实际失败（保留完整Kind／WroteHeader／TimedOut与Cause），不errors.Join一个ErrNoCandidate导致503抢先。后续纯跳过不抹掉先前失败，后续明确基础设施错误则保留其阶段／cause而非伪装503。最终已提交错误由原access映射路径ErrAbortHandler结束，无第二段JSON／SSE、无伪Done。

### 3.4 双反馈与观测边界

真实attempt结束后，按00矩阵对许可Complete一次，并在应报时health.ReportRequestResult一次。ClientCanceled／WriteError及请求错误400／404／422对breaker是neutral；health不报。401／403／429／5xx／网络或协议失败对两者失败，但不代表每种都允许回退。准备失败无健康信号，许可中性释放；未取得许可不调用Complete。

Complete与Report共用同一StateTimeout清理ctx（context.WithoutCancel保留request_id），操作顺序固定Complete→Report，不在两项之间刷新；其中一项失败／超时仍安全记录，不能阻断成功响应或制造再次出站。清理必须同步退出，不起游离goroutine；逐attempt清理总耗时单列，逻辑上游预算不因清理重启。feedback可在请求已耗尽后最多继续一次StateTimeout，保留proxy自身500ms收敛与原HTTP handler等待关闭协议。

ResultSuccess才向同一StrategyEngine.ObserveSuccess喂完整attempt单调耗时（不含准备／反馈），每次只喂一次；即使返回Usage也不据此额外写库。每attempt安全日志保留request_id、channel_id、公开model、Kind、WroteHeader、FirstByteMs、Chunks、attempt序号、attempt_elapsed_ms和feedback_elapsed_ms；request_done仍只由原中间件一条，最终摘要为最后实际尝试渠道。不得用opener时间再加FirstByteMs，或把两次attempt统计成两次用户请求。

17.1／17.2／18.1／18.2留具名TODO与台账消费：后续计量按逻辑请求／失败部分消费另冻，不在B5声明已结算；观测模块被动消费安全摘要，不反向import业务。当前不另做通用observer框架、计量桩或自定义指标协议。

### 3.5 生命周期与网关

真实/v1路由只替换ChatExecutor装配，Auth／Prechecker顺序、本人Key／admin API／readyz均保持。HealthService及Redis由cmd共享，breaker不自有Redis Close，不启动后台owner；原HTTP停止及在途handler等待→health worker取消等待→usage drain→Redis→MySQL顺序保留。取消在前一attempt清理／反馈／准备之间发生时禁止下一次opener，所有Stream和临时fixture进程须Join。

### 11.2 M1实际实现及机制证据

仅新增`internal/router/executor.go`与`executor_test.go`，声明冻结Executor／ExecutorOptions／NewExecutor，构造无I/O／worker，依赖nil／typed-nil及正时长、显式MaxAttempts 1..16、24h lease余量在加法前校验。配置默认3及env／yaml／跨模块装配校验仍属M2；M1测试显式传3，没有提前改config。
