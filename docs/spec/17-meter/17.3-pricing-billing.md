# 17.3 报价、正式结算与账单（L2）

> 状态：已冻结（2026-11-10用户确认cee221a候选，见末尾冻结记录），未实现／验收。上游：[17-L1](../17-meter.md)／[00 §6.12](../00-总纲.md)，前置17.1／17.2独审授权交付。本份M1→确认M2→确认M3，最终独审后才授权交付B6。

## 1. 报价及客户收费

实现Pricer与组合Recorder，签名沿00。Quote在已解析公开别名、首次真实Provider前用一次当前UTC取PriceRepo.Effective，沿60s当前价缓存，不用历史at绕缓存制造精确切价承诺。quote保存PriceID／公开model／CNY输入输出单价及UTC毫秒时间；Quote函数只接受本次当前时刻快照，不提供历史重新计价API。无价ErrPriceUnavailable保留ErrNoPrice并503 gaigate_price_unavailable，坏价／SQL故障500，零Provider／零许可泄漏。合法零价有效。

Calculate使用非负int64 usage／价格，精确计算ceil((in×inPrice+out×outPrice)/1e6)，两方向合并一次ceil，成本上限MaxInt64；不浮点、不逐方向分别ceil，不用max_tokens预估账单，不重用cost_first上游价格。测试(1,1)×(1,1)结果1而非2；报价变更不改已持有快照，重试Commit不能重新报价。

Recorder嵌入Pricer；router以持有Quote和最终Measurement调用Calculate后构造Settlement，Recorder.Commit再次检查公开model／quote／usage与cost一致，拒绝任意填价或不配套的成功明细，再委托QuotaGuard.Settle。ErrPriceUnavailable由access定义，meter使用同值别名，入口无meter反向依赖；缺价与SQL错误不能混为同一503。

## 2. 正式router／cmd接线

ExecutorOptions新增Accounting meter.Recorder与EstimateCharsPerToken。Accounting=nil仅保留旧库调用的B5行为，其他依赖／执行接口保持；非nil时C必须符合17.1。17.3生产cmd必须注入同一真实Recorder／QuotaGuard／持久化repo及workers，不提供用户配置关闭财务。bootstrap仍只负责Route→Execute，不另造第二次记账路径；没有Provider的Route／预检拒单不记录消费。

Executor在合法非空Plan后、首Provider前Quote公开model，失败不出站；每实际attempt有独立Collector，stream通过原同步onChunk观察，nonstream在opener获取response／usage只读快照。Forward最终返回后，只有最后成功attempt Finish结果进入用户收费；失败usage不累加，terminal失败／取消／写失败的逻辑行0tokens／0cost。有opener才终态Commit一次，先前失败后成功只一行，ChannelID为最后实际opener，GroupID为认证快照，CreatedAt为CompletedAt UTC毫秒。

现有ResultKind仍驱动breaker／health／回退和p99。Commit位于整次Execute结束、所有Stream Close及双反馈退出后，WithoutCancel保留request_id并仅一次meter.state-timeout；总handler最迟多此预算，不延长上游逻辑预算、不改变已提交响应／latched Overall／ErrAbortHandler。正常返回或panic有实际opener时均尽力终态归档（panic为failed零收费），有界清理后panic沿原协议传播；同ID不得defer和普通路径写两次。Finish／整数溢出／提交失败在已成功写出后不能改HTTP，只记录安全accounting_commit_failed，不能伪造成功账或用估算掩盖坏权威usage。

不得持有完整请求／Key／Raw直到后台任务；Settlement只含必要标量、身份、量、价格及时间。Quote后因健康全不可用等无opener耗尽仍503无账，不以报价存在制造收费。前次失败usage的供应商成本不属于客户账，后续若要承担／转嫁另冻，不承诺供应商exactly-once。

生产同时替换AllowAll为真实QuotaGuard.Precheck，429发生于Route／Quote／Acquire／Pick／Provider之前；没有17.3装配的17.2库不算#22完成。SettleQueueSize旧配置及UsageRepo仍可兼容旧用途，B6财务不走丢弃队列，不挂双Record；OnDrop和accounting_commit_failed是不同事件。

## 3. 账单物化

新增000003迁移，将bills唯一键改(user_id,group_id,period)，按17.2空旧账前提及down非空保护实施；不改000001、不猜历史归属。LedgerQueries为新增store只读查询接口，财务计算在meter，store不import meter；保留BillRepo原方法供旧调用，新组合查询／替换月方法明确按三元键，旧Upsert重复同user／group／month幂等。

按usage_records.CreatedAt的UTC月、UserID和GroupID快照SUM客户tokens与cost；诊断行0自然不收费。月重建单SQL一致性快照及事务覆盖，清除本次无明细的旧物化行，不能只upsert留下幽灵账单；所有聚合结果以精确数值校验int64上限，失败整月不部分更新。多实例重建须数据库月级互斥／等价串行事务，不能让较旧快照覆盖较新已物化结果；不得持请求ctx搞后台锁。

聚合worker显式Start／Close、默认每1min（meter.bill-interval为1s..1h正整毫秒），处理当前和上一个UTC月，各轮串行。新明细最多允许延后24h，因此覆盖上月足够；提供包内服务RebuildMonth供测试／未来运维显式触发，不新增公网写账接口。日期切换及任务取消用私有可控时钟验证，不sleep等整月。

查询API以SQL明细实时聚合为准，bills用于物化验证／未来读取优化；不拿有延迟bills声称立即等于最新账。验收在本轮明细写入静默并等待一次重建后比较bills=sum明细，若后台出错旧结果必须可识别为未更新，不能填0或返回假成功。

## 4. HTTP读取、身份与CSV

meter.RegisterRoutes接收身份中间件及只读服务；由cmd注入现有Bearer认证，业务只读标准Principal，19.1后续接session／CSRF，不任意header指定用户。全部no-store；无权限401/403、参数错误400、超额导出413、真实查询故障500，公开错误不含SQL／凭据／正文。

| 路由 | 冻结合同 |
|---|---|
| GET /api/v1/user/quota | 无target_id参数，仅当前APIKey／user／group的六个配置及SQL权威已用、UTC快照；可显示本人所属group总额，不返回其他用户明细 |
| GET /api/v1/user/usage | 本人明细，period缺省当前UTC月，严格YYYY-MM且仅当前及前23个月；page≥1，page_size默认20／最大100，稳定created_at DESC,id DESC，精确total；字段为request_id／公开model／本人的数值用量／cost／status／estimated／latency／时间，不返回Key／正文／内部URL |
| GET /api/v1/billing/summary | period同上，实时按本人(user,历史group,月)聚合；admin才允许user_id／group_id显式筛选或scope=all，普通用户带这些参数403而非忽略 |
| 同路由?format=csv | 同权限／期间过滤，聚合行最多1000，先取上限+1／确认数量，超限413且零部分CSV；UTF-8、固定ASCII列名、数值金额微元与tokens，不混展示货币舍入；CSV结构由encoding/csv生成 |

summary默认scope=self且page/page_size规则同上，scope=all须admin；self不能用current group过滤排除历史归属。CSV不分页，输出选定期间全部授权聚合行，>1000拒绝而非默默截断。JSON金额／tokens作为十进制字符串输出以避免JS 2^53精度丢失；IDs保持正整数十进制字符串。CSV只输出user_id,group_id,period,input_tokens,output_tokens,total_cost_micro，字符串可注入风险字段不在列内；若未来加名称必须另定公式注入防护。

所有自助服务层也要求调用者身份与scope，不能只靠HTTP middleware防IDOR；APIKey吊销／用户disabled沿现有实时鉴权。期月解析真实检查月01..12、不接受路径SQL片段；排序白名单不接任意order字段。配额配置CRUD仍19，价格／别名编辑仍19.2，不能本次开放写价／重置计数接口。

## 5. 生命周期、配置及B6检查点

新增meter.state-timeout默认1s（1ms..5s整毫秒），meter.bill-interval默认1min（1s..1h整毫秒），C沿17.1细化；yaml／env／默认／样例／非法标量齐全，不复用proxy Overall当后台无限期限。worker拥有者在cmd共享，constructor不启动，Start失败清理已启动owner；HTTP及在途handler→health stop/join→meter两个worker stop/join→旧usage drain→Redis→MySQL。允许留下已持久pending任务供重启，不允许留下goroutine／TCP；不把Close超时当已经全部退出。

新增test/e2e/quota_race.sh和自有真实SQL／Redis／双渠道HTTP fixture，原M0／B4／B5脚本不改。旧“usage_records==0”的B5进程断言如在正式B6装配下运行，须改为新的一逻辑行收费口径并保留原不重试／privacy／关闭等证据；旧库nil Accounting行为单独保留，不能加生产关闭开关假装历史回归绿。

检查点：100并发受控放行→成功持久化后追加请求429零Provider；另用顺序请求命中每层／每周期token与成本边界；软告警不拒；失败→备成功只末次一账，terminal取消／中断／写失败零收费、无opener不入账；权威0usage与缺usage估算；SQL相同ID重试一行／异载荷拒绝，outbox在进程重启／Redis丢回包后不双投影。等待pending清空及账单重建后，SQL成功客户用量与六计数增量／bills一致；故障注入期间不宣称恒等。真实SQL已提交但回包丢失与提交前断线区分；后者若最终无账必须明确事故且不污染成功响应。
