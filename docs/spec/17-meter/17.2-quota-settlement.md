# 17.2 耐久明细、配额与幂等投影（L2候选）

> 状态：2026-11-10候选，待用户review；未冻结／实现。上游：[17-L1](../17-meter.md)／[00 §6.12](../00-总纲.md)，前置17.1。本份先交库／迁移，17.3再整体生产装配，#22不在本份提前关闭。

## 1. 定位

MySQL客户明细为权威，预检只读不预扣；Redis为精确、可重放、允许滞后的六计数投影。此为对旧Redis唯一已用草案的候选修订，代价是预检多SQL读取。不能将Lua单HASH累加、丢弃式队列或同进程锁称成跨库幂等结算。

## 2. 新迁移与访问层

归本L2实施新增000002迁移，不改000001。迁移前必须证明usage_records和bills为空（B5没有财务写入）；非空实例明确拒绝，保留原数据，交主会话另定迁移方案。迁移内也须有执行期非空保护，不能只有文档提醒或依赖检查后不再写的假设；应用升级须先停旧写入。MySQL DDL不整体事务回滚，必须记录每一步失败恢复和dirty migration处理，不擅自删业务行／migrate force。

- usage_records新增group_id BIGINT UNSIGNED、price_id可空BIGINT UNSIGNED、input_price_per_m／output_price_per_m可空BIGINT、quote_at可空DATETIME(3)，成功必须快照完整、失败可全空；原model存公开别名。
- input_tokens／output_tokens改为BIGINT及Go int64，约束为非负且和不溢出；其余原字段保持，Estimated=int8 0/1、LatencyMS=uint32（范围校验后转换）。request_id为网关req_+ULID，新增唯一键；按api_key_id／group_id+created_at增加索引，保留原查询索引。
- 新quota_outbox：request_id VARCHAR(32)主键、payload_hash BINARY(32)、state(pending/claimed/done)、owner_token可空、lease_until可空DATETIME(3)、next_attempt_at／created_at DATETIME(3)、retry_count BIGINT非负；任务金额／身份只从关联不可变明细读，不复制正文。明细与任务同一事务。
- down仅允许两表及新增账务行均空且无pending任务时执行，禁止截断大token或抹历史GroupID。旧测试映射随新列宽适配，保留原行为／失败断言。

新增store.SettlementRepo，接口候选如下，具体DTO在store，meter负责显式转换，store不import meter：

```go
type SettlementRepo interface {
    Commit(ctx context.Context, rec UsageRecord) error
    UsedAt(ctx context.Context, userID, keyID, groupID int64, at time.Time) (QuotaUsageSnapshot, error)
    Claim(ctx context.Context, owner string, limit int) ([]QuotaTask, error)
    MarkDone(ctx context.Context, requestID, owner string) error
    RetryLater(ctx context.Context, requestID, owner string) error
}
type Used struct { Tokens, Cost int64 }
type PeriodUsage struct { Daily, Monthly Used }
type QuotaUsageSnapshot struct {
    At time.Time
    APIKey, User, Group PeriodUsage
}
type QuotaTask struct {
    Record UsageRecord
    PayloadHash [32]byte
    Owner string
    LeaseUntil time.Time
}
```

QuotaUsageSnapshot含同一at UTC及三target×daily/monthly的非负tokens／cost，UsedAt用单条SQL聚合，过滤created_at∈[周期起点,at]且相同snapshot身份（group按明细group_id，不按用户当前关系）。重复APIKey/User/Group行都只属对应维度，各层不相加当总客户消费。Claim使用SQL UTC_TIMESTAMP(3)条件更新／事务锁领取，固定30s租约且原子归属，避免依赖只有MySQL8支持的SKIP LOCKED；limit=1..100，租约过期可接管，MarkDone／RetryLater必须校验owner，不让旧worker完成新claim。

Commit规范化CompletedAt/QuoteAt到UTC毫秒，Latency到非负整毫秒，保留原snapshot供同ID重试。request_id、所有身份正int64、公开model有效<=128字符、status枚举、价格字段配套、金额／tokens／Estimated／字段宽度逐项校验，不静默截断。新记录CompletedAt只接受服务器当前时刻前24h至后1s；已有同ID重试不受旧时间窗影响。状态success可含0价／0tokens，failed/canceled必须0token/0cost且estimated=0；非成功不建有增量任务。

唯一键冲突后逐字段比较完整规范化不可变载荷：相同no-op，不同error且不写／不覆盖；同批内重复也要验证。payload_hash为规范化字段编码SHA256，不能只信相同hash而跳过字段约束。旧UsageRepo保持Record无返回、OnDrop及drain，但批INSERT重试要用同样逐项相等性判定：相同已落行不重插，冲突整批回滚并按旧策略丢弃／OnDrop，禁止UPDATE原明细或通用INSERT IGNORE。新增B6字段在旧非财务测试允许零Group／空报价；只有新SettlementRepo及生产Recorder强制完整财务字段，不能把兼容旧API作为新写入绕过。

## 3. QuotaGuard

沿00的Precheck(ctx,*access.Principal)及新Settle(ctx,Settlement)候选。meter实现，注入QuotaRepo／SettlementRepo／logger、state-timeout；构造nil／typed-nil及Options验证、不联网。Settle同步校验和提交明细／任务，**不在HTTP请求中逐个调用AddUsed**；Redis由worker处理。

预检取一次at UTC，在同一操作总state-timeout内最多三次ListByTarget获取key→user→group配置，再一次UsedAt；每target最多daily/monthly两行、错身份／重复period／负限额或soft_ratio非法报500。缺行或limit=0不限，但仍记录所有六类投影，不因当前无限额遗漏未来可配置的已用。

任一已用tokens或cost>=正limit硬拒：access.ErrQuotaExceeded，同一哨兵由meter包装，入口未提交429 gaigate_quota_exceeded；零新Route／Acquire／Pick／Provider／报价。SQL故障保留cause并500，不当未配置。soft_ratio∈(0,1]且最多两位小数，按整数百分比比较ceil(limit×ratio)，先硬拒再软告警；软告警不拒、只固定安全事件／request_id／target_type与必要ID，不泄漏Key／SQL。

Precheck对已提交SQL明细可见，不需等Redis。并发检查不锁、不预扣，100个同时通过可超限；明确区别超额与漏扣。晚到请求归它自身认证GroupID快照与CompletedAt周期；用户换组不改变旧账，新请求旧组不能通过当前User表回写。

## 4. quota_outbox与原子Lua

新增meter.ProjectionWorker，显式Start／Close；构造不启动。250ms轮询、batch≤100、逐任务一次state-timeout默认1s／上限5s，失败保留任务并有界退避最大30s，不能达到重试次数后删任务。多实例仅claim owner工作，异常退出租约恢复；SQL连接／事务／Rollback及worker关闭需真实TCP有界证据，不只WithContext或goroutine计数。

Lua归meter，输入为固定request_id／hash、六个周期key、标记key、金额与原period末+1h绝对到期。复用gaigate:quota:used:{type}:{id}:{YYYY-MM-DD或YYYY-MM}及tokens/cost_micro；新增gaigate:quota:settled:{request_id}存hash，TTL到原月末+1h。当前仅standalone Redis，KEYS全部显式传入；不冒称Cluster可多slot原子。

脚本先检查全部key类型、字段／非负int64、入参／hash／标记冲突、所有精确加法结果，再写六计数及标记。int64不得经过Lua double失真；可用十进制字符串加法与逐位上界校验，Redis写操作前完成所有验证，非法状态零部分写。字段缺失按合法0初始化，已有负值／小数／溢出不能当0。固定绝对到期不续周期、不将旧任务写入当前period；TIME到期的daily不重建，monthly仍有效则只更新monthly，全部过期只标任务已完成。已存在同hash标记直接成功；不同hash报错。标记／计数去重与TTL行为必须原子。

执行后再MarkDone；丢回包／MarkDone失败重复同任务不双加。没有SQL+Redis分布式原子提交；未投影任务可能滞后，但SQL账及预检正确。Redis整库丢失、done任务历史投影重建不在本轮自动保证，另登记运维项；不得把缺投影当客户没有消费。正常验收等待outbox无pending再对账，故障注入要保留pending／事故证据。
