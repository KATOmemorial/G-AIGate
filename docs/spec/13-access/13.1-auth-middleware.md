## 1. 模块定位

管道 §3.1 第①步：`Authorization: Bearer sk-...` → `Principal` 注入 ctx。同时交付 store 侧的 `APIKeyRepo` / `UserRepo`（11-L1 §2 已列为模块内接口，11.2/11.3 均未覆盖，本 PR 归属调整）与 Key 生成函数（13.4 复用）。

## 2. 目标 / 非目标

**目标**：`Authenticator` 实现（00 §6.2 契约）；Gin 中间件；哨兵错误；`GenerateKey()`；`APIKeyRepo` / `UserRepo`。

**非目标**：Key 的增删改 HTTP（13.4）；会话登录（19.1）；Key 用量统计（17）。

## 3. 输入输出

```go
// internal/access
func NewAuthenticator(keys store.APIKeyRepo, users store.UserRepo) Authenticator

// 哨兵错误（00 §6.7）：ErrUnauthorized / ErrKeyRevoked / ErrKeyExpired / ErrUserDisabled

// Key 生成（13.4 复用）：
// raw = "sk-" + base62(crypto/rand 32B)；prefix = raw[0:11]（"sk-"+8 字符）；hash = sha256hex(raw)
func GenerateKey() (raw, prefix, hash string)

// 中间件：提取 Bearer → Authenticate → Principal 注入 ctx（key: access.PrincipalKey）
func AuthMiddleware(a Authenticator) gin.HandlerFunc
// 失败响应（00 §8.2 格式）：401 gaigate_unauthorized / 403 gaigate_key_revoked / 403 gaigate_key_expired / 403 gaigate_user_disabled
```

```go
// internal/store（本 PR 交付）
type APIKeyRepo interface {
    FindByPrefix(ctx context.Context, prefix string) ([]APIKey, error) // 前缀索引查询，通常 0~2 行
    ListByUser(ctx context.Context, userID int64) ([]APIKey, error)
    Create(ctx context.Context, k *APIKey) error
    Revoke(ctx context.Context, id int64) error  // status → 0
}
type UserRepo interface { Get(ctx context.Context, id int64) (*User, error) }
```

**鉴权路径**：Bearer 提取 → `FindByPrefix` → 逐行 `subtle.ConstantTimeCompare(hash)` → 命中后检查 Key status/expired_at → `UserRepo.Get` 检查用户 status → 构造 Principal。

## 4. 设计说明

1. **prefix 定位 + 恒时比较**：前 8 字符 base62（约 2×10¹⁴ 空间）把全表扫描缩为索引点查；hash 比对用 `crypto/subtle` 防时序侧信道。这两点是"Key 存储怎么做"的标准答案。
2. **不区分"不存在"与"错误"**（13-L1 §4）：统一 401，防 Key 枚举。
3. **首版不做 Key 缓存**：唯一索引点查（单行级）在内部网关量级下足够快；缓存引入失效复杂度（吊销要即时生效），收益不成比例——文档化取舍，面试可讲。

## 5. 验收标准（可执行）

```bash
go test ./internal/access/... -run TestAuth   # 真实 MySQL（B2 测试库）+ fixture：
# ① 正确 Key → Principal 字段完整（UserID/APIKeyID/GroupID/Role）
# ② 无 Authorization / 非 Bearer / 格式错 → 401 gaigate_unauthorized
# ③ 坏 Key（hash 不匹配，含同前缀碰撞 fixture）→ 401
# ④ 吊销 Key → 403 gaigate_key_revoked；过期 Key → 403 gaigate_key_expired
# ⑤ 用户被禁用 → 403 gaigate_user_disabled
# ⑥ GenerateKey：10000 次无重复；prefix/hash 长度正确
# ⑦ 中间件集成：httptest 经中间件访问 dummy 路由，401/403/200 三态
```

## 6. 依赖

## 7. 主要风险

- 中间件位次错误（Auth 跑到 AccessLog 之前会丢 user_id 字段）——用例⑦锁定。
- `expired_at` 为 NULL 的永久 Key 语义（NULL = 永不过期）——用例覆盖。
