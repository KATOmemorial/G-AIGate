# 13.1 APIKey 鉴权中间件（L2）

> 状态：B3 修订候选，待用户 review（2026-10-20；未实现） | 上游：[13-L1](../13-access.md) | 批次：B3 | 预计工作量：1.5 天
> 依赖 00 v0.9 候选；用户批准统一冻结后开工。完整上下文包见 §9。

## 1. 模块定位

数据管道第①步：用户 Bearer Key → Principal → 标准请求 context。补交 users／api_keys 仓储及生成能力；表已在 11.1 建好，11.2／11.3 没有实现这两个 repo。本 L2 归属增量已登记 00 §6.3，交付代码仍放 internal/store。

## 2. 目标 / 非目标

目标：Authenticator、Gin 中间件、标准 context 身份读写、四个鉴权哨兵、用户 Key 生成、UserRepo／APIKeyRepo 及共用 OpenAI 风格错误输出。必须区分无效凭据与仓储故障。

非目标：Key HTTP／命令（13.4）、用户密码登录（19.1）、限流启用（台账 #19）、配额、鉴权缓存或数据库迁移。不开 /v1 路由，不修改 seed。

里程碑：M1 仓储与生成、M2 鉴权与中间件／回归。初次阅读并检查分支后直接实施 M1；每个里程碑交付后等待确认，最终交新会话独立审查。

## 3. 输入输出

```go
// internal/access；Principal／Authenticator 字段和方法沿用 00 §6.2
func NewAuthenticator(keys store.APIKeyRepo, users store.UserRepo) Authenticator
func GenerateKey() (raw, prefix, hash string, err error)
func WithPrincipal(ctx context.Context, p *Principal) context.Context
func PrincipalFromContext(ctx context.Context) (*Principal, bool)
func AuthMiddleware(a Authenticator) gin.HandlerFunc
// 本包定义：ErrUnauthorized、ErrKeyRevoked、ErrKeyExpired、ErrUserDisabled
```

```go
// internal/store；本 L2 实现，不与现有渠道 KeyRepo 混名
type APIKeyRepo interface {
    FindByPrefix(ctx context.Context, prefix string) ([]APIKey, error)
    ListByUser(ctx context.Context, userID int64) ([]APIKey, error)
    Create(ctx context.Context, k *APIKey) error
    RevokeOwned(ctx context.Context, userID, keyID int64) error
}
type UserRepo interface {
    Get(ctx context.Context, id int64) (*User, error)
    FindByUsername(ctx context.Context, username string) (*User, error)
}
func NewAPIKeyRepo(db *gorm.DB) APIKeyRepo
func NewUserRepo(db *gorm.DB) UserRepo
```

- raw = sk- + 32 个 crypto/rand 随机字节的 base64.RawURLEncoding，长度 46；prefix=raw[:8]，**含 sk-，共 8 字节**；hash 是完整 raw 的 SHA-256 小写 hex（64 字节）。不得把 8 位写成 sk- 后另取 8 位；与 11.1 DDL 注释一致。生成失败返回错误且三个字符串为空，不产出部分凭据；可用包内 reader 注入验证失败，不引入共享可变随机源。
- APIKey 复用 models.go：ID／UserID 是 uint64，外部接口 ID 为 int64。构造 Principal 前检查 ID 为正且不超过 MaxInt64，超界为内部错误；不更改已冻结表字段类型。
- FindByPrefix 包括 active／revoked／expired 的候选，按 id 升序；空结果为非 nil 空 slice。idx_api_keys_prefix 是**非唯一**索引，uk_api_keys_hash 唯一；不能只检查第一行。
- ListByUser 按 id 升序，返回本人所有状态记录；DTO 脱敏由 13.4 做。Create 仅存 hash／prefix，不接收 raw；显式填写 status=1、UTC created_at，expired_at=nil 为永久 Key；回填 ID。非法参数在 SQL 前拒绝，数据库错误按 %w 保留。
- RevokeOwned 必须以 user_id 和 id 双条件写入 status=0；已吊销的本人 Key 返回 nil，不存在／他人 Key 均包装 store.ErrNotFound。RowsAffected=0 不能直接当不存在，须核对同一 owner 下存在性；不得先查任意 ID 后无 owner 条件更新。
- UserRepo 未命中包装 store.ErrNotFound；读取不得返回密码／哈希到 HTTP 或日志。

鉴权顺序：校验 raw 的固定形状 → 取 prefix 查候选 → 将摘要恒时比较，直到命中完整 hash → Key 状态 → expired_at（now >= expired_at 视过期，UTC）→ 用户存在且启用 → Principal。仓储真实错误返回内部错误，不包装为 ErrUnauthorized。关联用户缺失按内部数据异常处理，禁用按 ErrUserDisabled；不缓存判断结果。

Authorization 只允许一个 header 值、一个 Bearer scheme 和一个 Key（scheme 忽略大小写，可接受空白分隔）；缺失、重复、逗号拼接或格式非法均 401，格式非法不访问仓储。合法形状但无匹配摘要同为 401；不泄露“无此 Key”细节。

中间件顺序保持 RequestID → AccessLog → Recover → 路由组 Auth。成功后把 WithPrincipal 与既有 middleware.WithUserID 得到的 context 写回 c.Request，再 c.Next；失败写一次 00 §8.2 envelope 并 Abort。身份不可仅存 gin.Context.Set。401／403 映射见 13-L1 §4；SQL／其他内部错误为 500 gaigate_internal，响应和日志不得含 Key／hash／DSN。

## 4. 设计说明

前缀只缩小查询范围，不承诺唯一；恒时比较摘要避免直接比较明文。无缓存使吊销提交后的新鉴权生效，在途请求不强制撤销。鉴权服务只判定身份，HTTP 层负责状态和错误体；同包共用错误输出供 13.3／13.4 复用，不使 middleware 反向 import access 形成环。

## 5. 验收标准（可执行）

`go test -p 1 -count=1 ./internal/access/... ./internal/store/... ./internal/middleware/... -v`；用本仓 GAIGATE_TEST_MYSQL_* 连接专用 gaigate_test，需真实跑仓储用例，不以 SKIP 算通过。跨包共享重建库按 01 §5 串行，包内重建用例不 t.Parallel。

| 用例 | 必须断言 |
|---|---|
| 生成／失败 | 46 字节、base64url 可解为 32 字节、prefix=raw[:8]、摘要正确；注入失败时无部分值；多次无重复只作补充 |
| 仓储／碰撞 | 同 prefix 多候选，正确 hash 不在首行仍命中；Find 不筛状态；List 隔离及顺序；hash 唯一约束 |
| 正常身份 | UserID／APIKeyID／GroupID／Username／Role 完整；标准 context 可取身份，日志 user_id 与之匹配 |
| 凭据错误 | 缺失／错 scheme／重复 header／坏长度与字符／坏摘要；格式错误零仓储调用，均 401 |
| 状态／时间 | 吊销 403；过期前／恰到／之后；nil 永久；禁用用户 403；数据库故障与关联用户缺失 500 |
| 吊销闭环 | 本人重复吊销成功；他人／缺失统一 ErrNotFound；提交后新鉴权立即 403，不把 RowsAffected=0 误判 |
| context／隐私 | 取消传播到 SQL；错误 envelope request_id；响应与日志无完整 raw／hash／密码 |
| 管道 | 真实 RequestID／AccessLog／Recover／Auth 组合，成功／401／403／500 各一次写出且日志准确 |

有并发用例执行限定 -race（本机 cgo 不可用用既有 Docker 路径）；合并前再完成 01 §6 的全仓真实 MySQL 回归和 lint。记录实际命令、版本、PASS／FAIL／SKIP 与环境恢复，不将 mock 数据库替代真实 SQL 归属验证。
