## 1. 模块定位

用户 Key 的创建、本人列表和吊销，以及尚无任何用户 Key 时的本地签发入口。存储只接收摘要，明文只在创建成功时返回一次；后续 19.1 复用业务服务与 DTO。

## 2. 目标 / 非目标

目标：KeyService、三个 handler、可注入身份中间件的路由注册、本地 cmd/g-aigate-key；创建／列表／吊销和即时失效验收。M1 服务与 HTTP，M2 本地命令与生命周期闭环，逐段停点。

非目标：登录／会话／CSRF（19.1）、管理员 HTTP 代建、过期时间编辑、批量删除、限流和自动轮换；不改 seed、迁移或增加可从 header 指定用户的开发鉴权桩。

## 3. 输入输出

### 3.1 身份与 Go 接缝

```go
// internal/access；DTO 的字段与 JSON 名见下表
type KeyService interface {
    Create(ctx context.Context, name string) (*CreatedKey, error)
    List(ctx context.Context) ([]KeyView, error)
    Revoke(ctx context.Context, keyID int64) error
}
func NewKeyService(keys store.APIKeyRepo, users store.UserRepo) KeyService
func RegisterUserKeyRoutes(r gin.IRouter, identity gin.HandlerFunc, svc KeyService)
```

identity 必须非 nil；handler 只从标准 ctx 取 Principal，缺身份返回 401。不从 body／query／header 取 user_id；服务复核用户仍存在且启用。B3 注册时注入 13.1 AuthMiddleware；19.1 注册时改为已验证会话／CSRF 身份中间件，不改 owner 规则和 Key 业务服务。RegisterUserKeyRoutes 负责 /api/v1/user/keys 全路径；避免重复套前缀。

Create 内部生成 raw／prefix／hash → 仅将 hash／prefix／元数据入库 → 成功后返回 CreatedKey。失败不返回任何 raw，用户数据禁止直接序列化 store.APIKey，防 key_hash 泄露。

### 3.2 HTTP 契约

| 请求 | 输出与限制 |
|---|---|
| POST /api/v1/user/keys | application/json，完整单个对象；只允许可选 name，缺省为空，显式 null／非 string／未知字段／尾随 JSON 拒绝；name 最多 128 个 Unicode 字符，不 trim 后静默改名 |
| 成功创建 | 201 CreatedKey：id、name、key、key_prefix、created_at；id 为正 int64，key 仅本次有，key_prefix 为含 sk- 的 8 字节 |
| GET /api/v1/user/keys | 200 数组（空为 []）；KeyView 仅 id、name、key_prefix、status、created_at、expired_at，按 id 升序，包括已吊销／已过期 |
| DELETE /api/v1/user/keys/:id | 正整数 int64；本人存在 Key（含已吊销）204 无体；他人／不存在统一 404 gaigate_not_found；非法 id 400 |
| 共通 | 身份错误沿 13.1；仓储故障 500 gaigate_internal；所有响应 Cache-Control: no-store，创建／列表不含 hash；时间 RFC3339 UTC，expired_at 为 null 或 UTC 时间 |

POST 正文固定上限 64 KiB，超限 413；空体／null／重复顶层字段／类型错 400；媒体类型非 application/json（允许参数）415。此接口处理元数据，不沿用 chat 的 10 MiB 上限。Name 长度按既有 api_keys.name VARCHAR(128)，不增加字段。

吊销调用 RevokeOwned(ctx, Principal.UserID, keyID)，更新提交后新鉴权立即 403。可吊销当前鉴权 Key，这次 DELETE 成功后它不再能鉴权；“重复 DELETE 仍 204”以另一把有效身份凭据为前提，不要求已吊销凭据继续授权。已放行的其他在途请求不撤销。

### 3.3 本地首次创建

正式新增 `cmd/g-aigate-key`，命令契约：

```bash
go run ./cmd/g-aigate-key -config config.yaml -user admin -name m0-demo
# 成功：exit 0；stdout 恰一个 CreatedKey JSON（含一次性 key），stderr 只记脱敏信息
# 不存在／禁用用户、缺 user、非法 name、配置／DB 故障：exit 非 0，stdout 无明文
```

显式 -user 必填且无隐式默认用户，-name 默认空。沿既有 config.Load 和 GAIGATE_MYSQL_*／GAIGATE_SECRET_MASTER_KEY 配置基线，普通 Config 校验仍执行，但命令仅打开 MySQL、按 username 查已存在用户，不连接 Redis、不启动 HTTP／worker、不迁移／seed 或创建用户。使用可取消且总时限 10s 的命令 context，并关闭数据库；明文只在数据库创建已成功后输出，不能将 stdout 当运行日志。stdout 写失败返回非零并告知“可能已创建，请另行查询或吊销”，不能声称数据库自动回滚。

命令可在受控 context 注入查询到的 Principal（APIKeyID=0 表示本地操作），复用同一服务；这种身份不来自网络请求。操作人拥有本地数据库配置和运行命令权限，不引入永久绕过登录的 HTTP 入口。19.1 上线后命令继续作为本地工具，页面改用登录会话。

## 4. 设计说明

首次签发由本地工具承接，避免把固定明文 Key 加进 seed 或让任意远端请求指定用户。HTTP API 的身份通过注入缝替换，owner 条件始终在业务服务和仓储体现。明文“只出现一次”是只在本次创建输出可见，丢失不支持找回；网络／stdout 失败可能已创建，允许重新签发并吊销遗留 Key。
