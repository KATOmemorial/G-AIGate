## 3. 输入输出与编排

```go
// internal/access；只定义入口消费接口，不 import router／meter／proxy／bootstrap
type Prechecker interface {
    Precheck(ctx context.Context, p *Principal) error
}
type ChatExecutor interface {
    Execute(ctx context.Context, w http.ResponseWriter, p *Principal,
        req *provider.ChatRequest) error
}
type ModelLister interface {
    List(ctx context.Context) ([]store.ModelAlias, error)
}
type ExecutionError struct {
    Cause error
    WroteHeader bool
    TimedOut bool
}
// ExecutionError 实现 Error／Unwrap；本包 ErrModelNotFound 对应别名不存在。
func RegisterV1Routes(r gin.IRouter, auth gin.HandlerFunc,
    precheck Prechecker, executor ChatExecutor, models ModelLister)
```

RegisterV1Routes 负责 /v1 全路径；auth／precheck／executor／models 不能为空。POST：Auth → 有界解析／校验 → middleware.WithModel 写回 c.Request → Precheck → Execute。GET models 同样 Auth，不做 chat 体解析和配额预检，返回 `{"object":"list","data":[{"id":"gpt-4o-demo","object":"model","owned_by":"gaigate"}]}`；按 name 升序，空 data=[]，列全部配置别名，不按健康／当前余额过滤。

**接口诚实性**：ChatExecutor 与 00 §6.5 router.Executor 的签名不同。B5 的装配适配器实现 ChatExecutor，在内部调用 Router.Route 再把 Plan 交 router.Executor；两者由 cmd／bootstrap 装配，不使 access import router。Prechecker 对应 QuotaGuard 的 Precheck 子集，B3 用明确 AllowAll 实现，未来 17.2 换入。临时行为必须留 TODO 与台账引用。

### 3.1 请求输入

固定 10 MiB 正文上限（10×1024×1024 字节），先限流量读取再解码；与 Gin multipart 内存设置无关。application/json 可带参数；其他媒体类型 415；超限 413。合法请求是完整单个非 null JSON 对象，禁止尾随 JSON、重复顶层字段。

model 为非空 string；stream 缺省 false，显式 null／非 bool 拒绝；messages 必须非空数组且每项对象有非空 string role，content／tool_calls 等剩余结构保留原始 JSON，不把 content 限为 string。stream_options 缺失／null 或对象；对象内 include_usage 若存在必须 bool，未知字段保留。其余顶层字段作为 Extra，不做全局 DisallowUnknownFields；不私造用户自定义回退头。

无效输入 400 gaigate_invalid_request，不调用 Precheck／Executor／上游。鉴权先于正文解析，未鉴权大请求仍 401。model 日志字段只在通过解析后写入，禁止记录原 messages 或 Authorization。

### 3.2 B3 临时执行（internal/bootstrap）

1. ModelRepo.Resolve 确认对外别名存在；未命中包装 access.ErrModelNotFound → 404 gaigate_model_not_found，SQL 故障 500。
2. ChannelRepo.ListActiveByModel(model)，取 priority 降序／id 升序第一项；没有返回 provider.ErrNoCandidate→503。不读取 health_status／breaker，不用 alias 默认／回退链；这是明确的 M0 临时选法。
3. KeyRepo.ListByChannel(channelID) 按 id 升序取第一把 status=1；没有则 503，不在 B3 改选另一个渠道。secret.Decrypt 用启动解码的 masterKey；GetModel 获取 channel_models.upstream_model，构造 Endpoint。映射／密文损坏是配置内部错误 500，不静默拿对外别名替代上游模型。
4. 用 middleware.WithChannelID 派生执行 context，并同步本请求的共享日志摘要（见下节）；用 provider/openai.New 构造的 Provider，调用 Forwarder 时传捕获该 Endpoint／req 的 opener，**闭包使用 proxy 传入 ctx**。stream=true 走 ChatStream／Forward，false 走 Chat／ForwardNonStream。
5. 将转发错误包装为 access.ExecutionError：Cause 保留可分类原因，WroteHeader 从 ForwardResult 复制，TimedOut 仅在 TTFB／Overall 时为 true；完整 ResultKind 留在 bootstrap 脱敏日志，不让 access import proxy。入口用 errors.As／Is 分类；未提交由 handler 一次映射，已提交失败 panic(http.ErrAbortHandler)，不再 JSON，不补 Done。客户端取消不继续写。

增量读取正式放 store：ModelRepo.List(ctx) 全量别名按 name；ChannelRepo.GetModel(ctx, channelID, model) 返回对应映射，缺失包装 ErrNotFound。已有接口方法保持，测试 fake 同步补充；无迁移。ModelList 消费 02 #9 的模型列表部分，渠道管理列表等仍归 14.1，不把整个条目关闭。

### 3.3 错误与中间件闭环

沿 13-L1 §4 全表；共用 13.1 错误输出工具，所有网关错误带 request_id。上游 400／404／422 仅在 Body 未截断、完整合法 OpenAI error 对象且无已知凭据时保留其 error 字段／状态，补顶层 request_id；其他顶层字段不透传。adapter 必须丢弃含该 Endpoint.APIKey 的错误体（按解析后字符串检查），handler 也不得回显客户端 Bearer。无法证明安全／完整则 502 gaigate_upstream_error，不能把任意上游 HTML／截断 JSON 返回给客户端。错误体／URL 凭据／密钥不进日志。

上游 401／403→502 upstream_auth_failed；429／5xx／网络／协议→502 upstream_error；TTFB／Overall→502 upstream_timeout，码均加 gaigate_ 前缀。其他未映射状态（含重定向）502；内部 SQL／配置故障 500。只有尚未提交时才生成这些响应。

**13.3 负责的 middleware 增量**：现有 Recover 会捕获所有 panic，必须先识别 http.ErrAbortHandler 并原样 re-panic；普通 panic 若尚未提交仍按原契约 500+日志，若已提交则保留脱敏故障日志并转为 ErrAbortHandler，不在 SSE 后追加 JSON。不改变 RequestID → AccessLog → Recover → Auth 顺序。AccessLog defer 必须仍执行一次且保留真实已提交状态；HTTP 200 可能伴随中断，另记结构化故障原因，不假改已发送状态码。

原有 WrapWriter 的嵌入接口不能证明底层 Flush／deadline 能力。按 00 §6.9 第7项的 2026-10-21 补充裁定，标准 Unwrap 最小透明能力及对应回归已获用户确认并随15.1交付，证据见15.1 §11.7／§11.12～§11.13，台账#27关闭；15.2 接续实际 deadline 验证。13.3 消费已交付能力并回归完整装配，不重复实施该前置项。Recover／请求摘要及其余必要装配仍归本 L2；额外包装改动须有新的具体依据，不能借本条扩大。禁止绕过 Gin 正文写入而令日志统计失真；10.2 原验收历史保留，各新增行为在实际 owner 的 L2 验收记录中登记。

**请求摘要增量同属本 L2**：context.WithValue 派生的新 context 不会自动更新外层 c.Request。AccessLog 必须在入口创建本请求独有的共享摘要，middleware.WithUserID／WithModel／WithChannelID 保持已有签名、保留标准 context 取值，并在存在摘要时同步相应字段；完成日志读取共享摘要（缺失时沿用原零值／context 回退）。摘要并发安全、无全局状态，不用于授权。这样 bootstrap／未来 router 仅派生自己的执行 context，外层日志仍得到实际渠道；必须以两个并发请求不同渠道证明不串值，不能只在 handler 手动重写 c.Request 掩盖执行器内的缺口。

## 4. 设计说明

M0 单一路径与正式路由隔离，防止 B3 提前实现 B5；依赖注入以真正的消费接口适配，避免当前 access→router 与未来 router→access 成环。协议错误必须在外层异常结束 HTTP，不能只少一个 Done 后正常 return；最终证据须经过真实中间件链。
