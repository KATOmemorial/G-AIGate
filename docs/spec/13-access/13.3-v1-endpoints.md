## 1. 模块定位

管道的"编排壳"：`/v1/chat/completions` 与 `/v1/models` 的 handler。B3 版本是 **M0 最小执行路径**（直连首渠道，无容灾），为 B5 的 16.4 留好接口缝。

## 2. 目标 / 非目标

**目标**：两个 handler；错误映射表落地（13-L1 §4 全表）；管道编排（auth → precheck → route → execute）；`internal/secret`（AES-GCM 加解密工具，14.2 复用）；B3 临时执行路径（naive executor）。

**非目标**：容灾与候选迭代（16.4，B5 替换临时路径）；配额真实语义（17.2，B6 替换桩）；`/v1/responses`（00 §11 决策⑤，不交付）。

## 3. 输入输出

```go
// internal/access —— 消费方接口缝（Go 惯例：接口定义在消费侧）
// 签名与 00 §6.5/§6.6 对应模块的最终实现一致，B5/B6 装配时直接替换
type Prechecker interface{ Precheck(ctx context.Context, p *Principal) error }        // B3: AllowAll 桩 TODO(17.2)
type Executor interface {                                                            // B3: naiveExecutor TODO(16.4)
    Execute(ctx context.Context, w http.ResponseWriter, p *Principal,
        model string, req *provider.ChatRequest) error
}

// 请求路径（契约级）：
// POST /v1/chat/completions
//   中间件链(10.2) → Auth(13.1) → 解析 body 到 provider.ChatRequest（Extra 收集未知字段）
//   → Prechecker.Precheck（拒绝 → 429 gaigate_quota_exceeded + Retry-After: 60）
//   → Executor.Execute
//   → 透传 executor 写好的响应/流；任何 ErrNoCandidate → 503 gaigate_no_candidate
// GET /v1/models → [{"id": alias.Name, "object": "model", "owned_by": "gaigate"}]（存在即可用，13-L1 §3.3）
```

**naiveExecutor（B3 临时，access 包内）**：

```
model → ChannelRepo.ListActiveByModel（缓存读）→ 取 priority 最高渠道
→ internal/secret 解密该渠道第一把 Key + channel_models 映射上游模型名 → provider.Endpoint
→ ChatStream / Chat → 15.1 Forwarder 转发（TTFB/Overall 超时来自 ProxyConfig）
→ 失败直接返回错误（无切换；B5 由 16.4 接管）
```

**internal/secret（本 PR 交付，01 §8 的落地）**：`Encrypt(plaintext, masterKey) / Decrypt(ciphertext, masterKey)`，AES-256-GCM，nonce 前置拼接；`MasterKey` 从 `GAIGATE_SECRET_MASTER_KEY` 读（10.1 已有）。

## 4. 设计说明

1. **接口缝定义在消费方（access）**：Prechecker/Executor 是 access 的需求描述，B3 用桩实现满足 M0，B5/B6 用真实现替换——装配只改 main 一行。这就是"模块可独立交付"在代码层的形态。
2. **错误映射集中在 handler 一处**：所有模块的错误（哨兵）到这里统一翻译成 00 §8.2 响应体——上游 401 转 502 的防误判规则（13-L1 §4）在此落地。
3. **naive executor 的诚实性**：临时路径明确标注 TODO(16.4)，且其行为（直连首渠道）被 B3 验收锁定——替换前后对"单渠道正常流"的行为必须不变，这就是回归依据。

## 5. 验收标准（可执行）

```bash
# 前置：B2 验收通过（seed 存在），mock 与网关都起来
go test ./internal/access/... -run TestV1    # 用例：
# ① 无 Key → 401；吊销 Key → 403（复用 13.1 fixture）
# ② 正常流式：经网关打到 mock normal 场景，SSE 帧数 = 直连 mock 的帧数，含 [DONE]
# ③ 正常非流式：JSON 响应含 usage
# ④ mock 切 downtime → 网关 502 gaigate_upstream_error（B3 无切换，直连失败直报）
# ⑤ mock 切 slow(2s) + ProxyConfig.TTFBTimeout=1s（测试覆盖）→ 502 超时错误，客户端零字节
# ⑥ GET /v1/models 返回 seed 的 gpt-4o-demo
# ⑦ 未知字段透传：请求带 "user":"tester" → mock 收到该字段（12.1 可加断言或抓包）

# B3 集成检查点（M0，手动/脚本）：

# → SSE 逐帧到达；test/e2e/mock_scenarios.sh 直连对照，帧数一致
```

## 7. 主要风险

- **最大的结构性风险是桩的替换遗漏**——用"TODO(16.4)/TODO(17.2)"标记 + B5/B6 验收用例（替换后 ②~⑤ 行为不变且新增容灾行为）双重保险。
- body 尺寸限制（防超大请求拖垮网关）：Gin 默认 32MB，本 PR 收紧到可配（默认 10MB），413 响应。
