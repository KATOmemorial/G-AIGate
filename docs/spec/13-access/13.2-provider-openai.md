# 13.2 Provider 抽象与 OpenAI 适配器（L2）

> 状态：已冻结（2026-10-20 用户确认 B3 文档；未实现） | 上游：[13-L1](../13-access.md) | 批次：B3 | 预计工作量：2 天
> 依赖 00 v0.9 已冻结；本施工图已获用户确认并冻结。上下文包见 §9。

## 1. 模块定位

共享内核字段及 OpenAI 兼容 HTTP 客户端。真正实现位于 internal/provider/openai，core 不含 HTTP／解析／worker 逻辑。业务只通过 Provider 调用，上游 mock 仍是独立 HTTP 服务。

## 2. 目标 / 非目标

目标：统一请求与响应、分类错误、Chat／ChatStream、有限 SSE parser、有界事件队列、可取消及等待关闭的流。M1 请求／非流式／错误，M2 SSE／终止／关闭与 mock 交叉验证，逐里程碑停点。

非目标：路由、重试、下游 ResponseWriter、预算策略、计量估算、适配其他协议；不修改 mock 行为或新增其抓包 API，不增加第三方依赖。

## 3. 输入输出

```go
// internal/provider：其余 Endpoint／Provider／Stream 方法严格沿用 00 §6.1
type ChatRequest struct {
    Model string
    Stream bool
    Messages []json.RawMessage
    Extra map[string]json.RawMessage
}
type ChatResponse struct {
    Body json.RawMessage
    Usage *Usage
}
type Usage struct { InputTokens, OutputTokens int64 }
type StreamEventKind uint8
const (
    Chunk StreamEventKind = iota
    UsageDone
    Done
    Error
)
type StreamEvent struct {
    Kind StreamEventKind
    Raw []byte
    Usage *Usage
    Err error
}
type UpstreamError struct {
    StatusCode int
    Body []byte
    BodyTruncated bool
    Retryable bool
    Cause error
}
// UpstreamError 实现 Error() 与 Unwrap()；Error() 不含 Body／URL 凭据。
// ErrStreamInterrupted／ErrNoCandidate／ErrUpstreamUnavailable 定义于 core；
// 流异常包装 ErrStreamInterrupted 并保留底层原因，其他模块不得重定义同名哨兵。

// internal/provider/openai
func New(httpClient *http.Client, streamBuffer int) (provider.Provider, error)
```

New 拒绝 nil client 或 streamBuffer<=0；不偷偷回落全局 http.DefaultClient。装配传 cfg.Proxy.StreamBuffer（默认 64）；client.Timeout=0，整次尝试预算由 proxy context 决定；禁止自动跟随重定向泄露 Authorization。不修改调用方的 client／Transport 共享对象，具体校验或复制策略自行实现并测试。名称 Name() 返回 openai，seed Provider=openai 可直接使用。

### 3.1 请求与 HTTP

- messages 每项保留原始对象，不用 Role／Content string 丢弃 tool_calls、图片或扩展字段。Extra 保存除 model／stream／messages 外的顶层原始值。序列化创建新对象，对输入及嵌套 RawMessage 只读，便于并发复用。
- Endpoint.Model 替换对外 model；流式合并 stream_options 对象并置 include_usage=true，保留其中其他字段；缺失／null 则新建。stream=false 不注入，其他正文语义保持。客户端是否请求 usage 不影响 B3 向下游转发真实 usage。
- Endpoint.BaseURL 为服务根或以 /v1 结尾的 API 根；分别追加 /v1/chat/completions 或 /chat/completions，保留已有路径前缀，规范尾斜杠。只允许 http／https、非空 host；拒绝 userinfo、query、fragment。路径不得通过字符串盲拼产生 /v1/v1。
- POST，Authorization 使用 Endpoint.APIKey，Content-Type application/json；不转发客户端 Authorization、Cookie、任意 X-* 或 X-Mock-Scenario。测试通过 mock 控制 API 选择场景。
- 仅 HTTP 200 视成功；流式要求 text/event-stream，非流式要求 application/json（允许参数）；非 200 包装 UpstreamError。禁止自动重试。
- 网络／连接／读取错误 StatusCode=0；429／5xx／网络 Retryable=true，其他状态 false，重定向原状态 false；ctx 取消／超时交调用方优先分类。最多探读 1025 字节，Body 保留前 1024 字节并用 BodyTruncated 标记超限；不日志打印。若完整 JSON 的任意字符串含该 Endpoint.APIKey，丢弃 Body；截断或无法安全解析的 Body 不能用于客户端透传。Cause 保留 context／网络底层原因，错误体处理见 13.3。
- 非流式正文上限 10 MiB，要求完整单个 JSON 对象，无尾随 JSON；原样保存 Body。usage 缺失／null 返回 nil；存在时 prompt_tokens／completion_tokens 必须为非负 int64 整数，越界／类型错是协议错误。ChatResponse.Usage 与方法返回 Usage 值一致，不重复生成两套可分歧数据。

### 3.2 SSE 与生命周期

| 输入 | 事件／行为 |
|---|---|
| data: 合法 JSON 对象，usage 缺失／null | Chunk，Raw 是原始 data 负载，Err／Usage=nil |
| data: 合法对象且非空 usage | UsageDone，Raw 保留，Usage 非负 int64；B3 支持标准的独立 usage 帧（choices=[]），不支持把内容与非空 usage 混在一帧，该情况按协议错误处理 |
| data: [DONE] | Done，Raw=[DONE]；一次终止后停止读取，关闭 body 和 channel |
| EOF／读失败，未见 Done | 一个 Error（Err 非 nil，匹配 ErrStreamInterrupted），然后关闭；不得产生 Done |
| 畸形 JSON／非法 usage／超限帧 | 同异常处理，停止后续读取与事件；不能当 Chunk 盲传 |
| context 取消／Close | 取消 HTTP、关闭 body、使阻塞发送可退出；调用方据 context 分类，不要求成功送出最后一个 Error |

支持 LF／CRLF；按空行分隔 event，多行 data 按 SSE 规则以 LF 连接，仅移除 data 冒号后的一个可选空格，不 TrimSpace 正文。注释、event／id／retry 字段忽略；无 data 的事件不提交任何输出。单 event 累计输入上限 1 MiB（含非 data 行），拒绝无限行／默认 Scanner 64KiB 隐式限制；恰好上限与超限必须测试。

worker 必须可被 Close 或 context 取消唤醒，固定容量 channel 满时停止解析，不丢帧、不无界缓存。事件数据独占，不复用下一次读入缓冲。唯一 worker 关闭 Events；Close 幂等并等待 worker 退出，调用方不得在该 worker 内调用会等待自身的 Close。正常 Done／错误也释放 body；并发 Close 不 panic／死锁。使用有生命周期的 errgroup 等机制，遵守 01 请求路径裸 go 禁令。

ChatStream 返回时已得到合法 HTTP 头，首事件仍异步；它不自设 TTFB 起点。proxy 在调用它之前创建预算 context，连接、响应头与首帧等待均被覆盖。Close 退出保障和背压先由本层机制测试，15.2 再做真实传输链验收。

## 4. 设计说明

opaque messages 与 Extra 避免网关静默剥离扩展结构；只理解路由与真实 usage 所需字段。Done 与 Error 独立，使 downstream 能辨别正常终止和 EOF；channel 关闭只表示生产者退出。有限帧／正文与有界队列同时限制每项与项数，不能只声称 channel 有界就保证内存有界。

协议依据：[OpenAI Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create) 的流式 usage／Done；本项目支持范围以本文明确子集为准。context／HTTP 生命周期参考 [Go 1.25 net/http](https://pkg.go.dev/net/http@go1.25.0)。

## 5. 验收标准（可执行）

`go test -count=1 ./internal/provider/... -v`，并对含 worker 用例执行同范围 -race；用 httptest 请求捕获和真实 TCP 服务，不只检查无 error。

| 组 | 必须断言 |
|---|---|
| 序列化 | unknown 顶层／messages 嵌套 tool／多模态／stream_options 未知字段深比较保留；model 重写；流／非流注入差异；原对象并发复用不变 |
| URL／HTTP | 根／v1／路径前缀与尾斜杠；非法 URL 零网络调用；重定向不跟随且未泄露 Key |
| 非流式 | JSON 原字节保留、Usage 一致；无 usage、零 token、溢出、超限、尾随 JSON／空体／错误 Content-Type |
| SSE | LF／CRLF／多行／注释／空事件；Chunk、UsageDone、Done 顺序；N+1+1 分别计数；缺 usage 可成功 |
| 异常 | 正常 HTTP EOF 但无 Done、真实截断、坏 JSON、错误 usage、超大行／event；一个 Error 且没有伪 Done |
| 关闭／背压 | body.Close、worker 进入／退出屏障；重复／并发 Close；空读与满 chan 时取消均退出；容量精确，入队不丢失，Raw 不被复用覆盖 |
| 错误 | 400／401／403／404／429／503／重定向及网络分类；1024 字节截断；errors.As／Unwrap 与日志脱敏 |
| mock 交叉 | 五场景经真实 HTTP：normal 8+1+1；slow 可取消；downtime／429 分类；interrupted 3 Chunk 后 Error，无 usage／Done |

交叉用例启动仓库 mock 到随机本机端口（可在外部测试包使用 internal/mock 作为 HTTP fixture）；只有测试可引用 mock，生产 adapter 不 import。不要依赖未定义 mock_e2e tag、固定端口或已运行服务。13.2 本身不要求下游网关。

## 7. 主要风险

Close 自等待、满 channel 无法取消、响应头已到但首帧永不到、缺 Done 被视成功、截断错误体被透传。以上必须有机制用例。未知字段“保留 JSON 语义”不等于全部 JSON 文本字节不变，SSE Raw 的具体保证见 §3.2。
