# 19-web（L1）

> 视图层原则（设计文档 §5）：前端薄、不含业务判断，核心数据与判断仍在网关模块。

---

## 1. 模块边界

**做什么**：登录与会话（cookie + Redis session）；用户控制台页面；管理后台页面；账单页；用户/分组/配额的**薄 CRUD API**（纯配置管理，无业务判断——配额预检/结算语义在 17）。

**不做什么**：数据加工与聚合（走 17 的 API）；渠道管理 API（14.1 已有，页面直接调用）；Key 管理 API（13.4 已有）。

## 2. 关键设计决策

1. **服务端渲染（html/template）+ 原生 fetch，不引前端框架**。理由：部署仍是单二进制（运维面最小）；页面形态就是表单 + 表格 + 简单图；"薄前端"是设计文档明示的取舍，也是面试可讲点。SPA 列为可选演进。
2. **图表首版用 CSS/SVG 条形图**，不引 chart.js——用量趋势的精度要求不支撑引入 JS 依赖。
3. **会话放 Redis**：复用现有基础设施；登出即删；admin 路由由会话中间件校验 role，越权返回 403。

## 3. 页面与 API 清单

| 页面 | 路由 | 数据源 |
|---|---|---|
| 登录 | `/login` | 11 的 users（bcrypt） |
| 用户控制台 | `/console` | 13.4（Key 管理）、17（额度/用量） |
| 管理后台-渠道 | `/admin/channels` | 14.1（CRUD/测试/健康状态） |
| 管理后台-模型 | `/admin/models` | 11（别名/策略配置） |
| 管理后台-用户 | `/admin/users` | 本模块薄 CRUD（users/groups/quotas） |
| 管理后台-概览 | `/admin/overview` | 17 聚合 API + 18 指标摘要 |
| 账单页 | `/billing` | 17 账单 API（+ CSV 导出） |

## 4. L2 清单（与 00 §4.1 预排一致，无调整）

- **19.1 登录与会话 + 用户控制台**：登录/登出、CSRF、console 页（Key 创建弹明文仅一次）。
- **19.2 管理后台**：渠道/模型/用户/概览四页，含连通性测试按钮与健康状态标识。
- **19.3 账单页**：月账单表、明细下钻、CSV 导出。

## 5. 主要风险

- 越权（admin 路由漏校验）——验收用例：普通用户 cookie 访问 `/admin/*` 全部 403。
- XSS：html/template 默认转义，Key 明文展示仅创建瞬间，且页面禁止缓存该响应。
