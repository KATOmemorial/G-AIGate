## 1. 模块定位

让进程"能起来、能配置、能被看见活着"：`internal/config` 包（配置结构、加载、校验）+ `cmd/g-aigate` 最小装配（Gin 骨架 + `/healthz` 占位）。位于管道 §3.1 第 0 环之前。

## 2. 目标 / 非目标

**目标**：`internal/config`：`Load(path) → *Config`；环境变量覆盖（前缀 `GAIGATE_`，`.` 分隔）；fail-fast 校验；`config.example.yaml`；`cmd/g-aigate` 启动后 `/healthz` 返回 200。

**非目标**：不连 MySQL/Redis（10.2 的 readyz 才接依赖）；不注册业务路由（B3 起逐批挂载）；不做配置热加载（00 §20-L1 决策④：进程级配置不热更）。

## 3. 输入输出

`internal/config` 公开 API 与结构体（本 L2 冻结，后续模块按 section 增量扩展时须走 00 §10）：

```go
func Load(path string) (*Config, error) // 加载 + 环境变量覆盖 + 校验，一步完成

type Config struct {
    Server  ServerConfig
    Log     LogConfig
    MySQL   MySQLConfig
    Redis   RedisConfig
    Proxy   ProxyConfig
    Channel ChannelConfig
    Router  RouterConfig
    Meter   MeterConfig
    Secret  SecretConfig
}

type ServerConfig struct {
    Addr            string        // 默认 ":8080"
    MetricsAddr     string        // 默认 ":9101"（Prometheus 抓取，compose 已按此配置）
    ShutdownTimeout time.Duration // 默认 60s
}
type LogConfig struct{ Level string } // debug|info|warn|error，默认 info

type MySQLConfig struct {
    Host string // 默认 127.0.0.1
    Port int    // 默认 3306
    User string // 默认 root
    Database string // 默认 gaigate
    Password string // 仅环境变量 GAIGATE_MYSQL_PASSWORD
}
type RedisConfig struct {
    Addr string // 默认 127.0.0.1:6379
    DB   int
}

type ProxyConfig struct {
    TTFBTimeout    time.Duration // 默认 10s
    OverallTimeout time.Duration // 默认 300s
    StreamBuffer   int           // 有界缓冲 chunk 数，默认 64
}
type ChannelConfig struct {
    ProbeInterval    time.Duration // 默认 30s
    FailureThreshold int           // 默认 5（连续失败→禁用）
    DisableDuration  time.Duration // 默认 60s（禁用冷却）
}
type RouterConfig struct {
    BreakerWindow       time.Duration // 默认 60s
    BreakerMinSamples   int           // 默认 20
    BreakerErrThreshold float64       // 默认 0.5
    BreakerOpenDuration time.Duration // 默认 30s（open→half-open）
    DefaultStrategy     string        // 默认 "weighted"；枚举 weighted|cost_first|latency_first|fallback_chain
}
type MeterConfig struct {
    EstimateCharsPerToken float64 // 默认 4（17.1 估算回退）
    SettleQueueSize       int     // 默认 1024（11.3 落账队列）
}
type SecretConfig struct {
    MasterKey string // 仅环境变量 GAIGATE_SECRET_MASTER_KEY（渠道 Key AES-GCM，14.2 用）
}
```

**校验规则**（全部 fail-fast，报错须指出字段名与原因）：端口 1~65535；所有 Duration > 0；`StreamBuffer > 0`；`BreakerErrThreshold ∈ (0,1]`；`DefaultStrategy ∈ 枚举`；`Log.Level ∈ {debug, info, warn, error}`（严格小写，不归一化）；`MasterKey` **必填**且 base64 解码后恰为 32 字节（AES-256；见决策④）。

**环境变量覆盖规则**：`GAIGATE_MYSQL_PASSWORD`、`GAIGATE_SECRET_MASTER_KEY` 只认环境变量（yaml 中出现即报错——防密钥入库）；其余项 `GAIGATE_<SECTION>_<FIELD>` 覆盖。

## 4. 设计说明

1. **配置分区按模块 ownership 划分**：每个 section 的字段只被一个模块消费，新增配置项的 PR 必然只改一个 section——评审时一眼看出影响面。
2. **fail-fast 优先于默认值兜底**：非法配置启动即退（exit code 1 + 结构化错误信息），不允许带病运行。
3. `config.example.yaml` 与默认值一一对应，是配置项的自文档。
4. **MasterKey 必填（实现反馈修正，2026-09-26）**：空密钥的网关无法完成 seed 加密（11.1）与渠道 Key 解密（14.2），失败不可避免——与其在首次使用时报错，不如启动时 fail-fast；"可空 + 用时校验"会把错误推离病因并让空值分支扩散到每个消费方。开发环境用固定示例密钥（见 §5），生产用生成命令。

## 5. 验收标准（可执行）

```bash
# 开发密钥（仅本地演示用）：base64("12345678901234567890123456789012")，解码后恰 32 字节
# 生产生成命令：openssl rand -base64 32
export GAIGATE_SECRET_MASTER_KEY=MTIzNDU2Nzg5MDEyMzQ1Njc4OTAxMjM0NTY3ODkwMTI=
go test ./internal/config/...        # 表驱动：合法配置/非法字段逐条/环境变量覆盖/密钥入 yaml 报错/缺 MasterKey 报错
go run ./cmd/g-aigate &              # 起来后：
curl -s localhost:8080/healthz       # → 200
GAIGATE_SERVER_ADDR=:99999 go run ./cmd/g-aigate   # → 退出码 1，报错含 "server.addr"
GAIGATE_SECRET_MASTER_KEY=short go run ./cmd/g-aigate  # → 退出码 1，报错含 "secret.master_key"
```

## 6. 依赖

上游：无（最底层）。被依赖：10.2（装配用 Config）、11（MySQL/Redis 客户端参数）、及之后所有模块按 section 消费。

## 7. 主要风险

- 配置结构体是后续所有模块的公共依赖，字段命名一旦定下变更成本高——本评审重点过目 §3 结构。
- Viper 环境变量覆盖的 key 格式（`.` vs `_`）易踩坑——用 `viper.SetEnvKeyReplacer`，测试覆盖。
