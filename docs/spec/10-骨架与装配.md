## 1. 模块边界

**做什么**：进程入口；配置加载与 fail-fast 校验；Gin 路由注册（把各模块 handler 挂上来）；全局中间件（RequestID / recover / 访问日志）；健康探针（`/healthz`、`/readyz`）；优雅关闭。

**不做什么**：任何业务判断——鉴权（13）、路由（16）、计量（17）都不在此；本模块的中间件只做横切关注点。

**在管道中的位置**：00 §3.1 的第 0 环（RequestID 注入 → 访问日志 → recover）。

## 2. 接口

无对外 Go 契约（装配层不产出被依赖的接口）。产物是一个可启动、可探活、可干净退出的网关二进制。

## 3. 关键设计决策

1. **手工依赖注入**：全部 wiring 在 `cmd/g-aigate/main.go` 中按依赖顺序手工构造。不引 wire/dig——当前依赖图（见 00 §5.2）足够小，手工装配可读、可调试、可讲。
2. **优雅关闭语义**：SIGTERM → 停止接受新请求（关 listener）→ 等待在途流式请求完成（上限 60s，可配）→ 依次关闭 metrics flush、Redis、MySQL。`/healthz` 作 liveness，`/readyz` 作 readiness（探测 MySQL ping + Redis ping，任一失败即 not ready，为滚动更新服务）。
3. **配置 fail-fast**：Viper 加载后立即做结构校验（端口范围、超时正数、必填项），非法即退出——不允许带病启动。

## 4. L2 清单（与 00 §4.1 预排一致，无调整）

- **10.1 入口与配置加载**：`internal/config` 结构体、校验、示例 `config.yaml`；`cmd/g-aigate` 装配出可启动的最小骨架。
- **10.2 中间件管道与优雅关闭**：RequestID（`req_` + ULID，注入 ctx 与响应头）、recover、访问日志；`/healthz` `/readyz`；shutdown 全流程。

## 5. 主要风险

- 在途流式请求的关闭语义是体验与资源的折中：60s 上限内强断可能截断用户回答——文档化为已知取舍，面试可讲。
- 中间件顺序错误会导致访问日志丢 request_id——验收用例覆盖。

## 6. 验收要点（详见各 L2）

B2 检查点贡献：启动即 `/healthz` 200；`/readyz` 随依赖状态翻转；Ctrl+C 退出码 0 且无 goroutine 泄漏告警；非法配置启动即失败并打印原因。
