## 1. 模块定位

跨节点共享状态的原子原语层：配额已用计数、健康状态存取、限流计数（预留）。**只提供原子操作，不承载判定语义**——健康状态机在 14.3，熔断的 Lua 在 16.3（00 §6.3 说明）。

## 2. 目标 / 非目标

**目标**：`QuotaCounter`（HINCRBY + 周期 TTL）、`HealthState`（HASH 读写）、`RateLimiter`（接口预留 + INCR/EXPIRE 实现）；全部基于 go-redis v9；miniredis 单测。

**非目标**：熔断窗口（16.3 自持 Lua）；任何"是否超限/是否禁用"的判断（消费方做）。

## 3. 输入输出

```go
// —— 配额计数 ——  key: gaigate:quota:used:{targetType}:{targetID}:{periodTag}
// periodTag: daily → "2026-09-26"；monthly → "2026-09"
type QuotaKey struct{ TargetType string; TargetID int64; Period string /*daily|monthly*/ }
func (k QuotaKey) String() string                     // 完整 Redis key（含按当天推导 periodTag）
func (k QuotaKey) TTLHint() time.Duration             // 周期末尾 + 1h 缓冲（daily +25h，monthly +25h 至次月1日）

type QuotaCounter interface {
    // 原子累加已用；首次写时设置 TTL（HINCRBY 后 EXPIRE，仅当无 TTL 时设置——用 Lua 保证幂等）
    AddUsed(ctx context.Context, k QuotaKey, tokens, costMicro int64) error
    GetUsed(ctx context.Context, k QuotaKey) (tokens, costMicro int64, err error)
}

// —— 健康状态 ——  key: gaigate:health:{channelID}，整 HASH 覆盖写
type HealthSnapshot struct {
    ConsecutiveFailures int32
    DisabledUntil       int64  // unix 秒；0 = 未禁用
    LastProbeAt         int64
    LastProbeOk         bool
}
type HealthState interface {
    Load(ctx context.Context, channelID int64) (HealthSnapshot, error)  // 不存在 → 零值快照
    Save(ctx context.Context, channelID int64, s HealthSnapshot) error  // HSET 全字段，无 TTL（持久）
}

// —— 限流（预留）——  key: gaigate:rl:{scope}:{id}:{window}
type RateLimiter interface {
    Allow(ctx context.Context, scope string, id string, limit int, window time.Duration) (bool, error)
}
```

**原子性契约**：`AddUsed` 的 HINCRBY + 首次 EXPIRE 在一个 Lua 脚本内完成（防止"加了数但没设 TTL"的永久 key）；`Save` 为单命令 HSET 多字段（原子）。

## 4. 设计说明

1. **TTL 设在计数 key 上而非单独管理**：周期切换即换 key（periodTag 变了），旧 key 靠 TTL 自然过期——不做任何清理任务。这是"用 key 命名做时间分片"的标准手法，面试可讲。
2. **HealthState 无 TTL**：渠道健康状态跨周期持续存在，"禁用到什么时候"由 `DisabledUntil` 时间戳语义表达，而非 key 过期。
3. **原语与语义分离**：本层改一个字段名会影响 14.3/16.3/17.2 三个消费方——所以字段结构在本 PR 冻结，变更走 00 §10。

## 5. 验收标准（可执行）

```bash
go test ./internal/store/... -run 'TestQuotaCounter|TestHealthState|TestRateLimiter'
# 用例清单（miniredis）：
# ① AddUsed 两次 → tokens/cost 累加正确；key 命名含正确 periodTag
# ② 并发 100 goroutine AddUsed 各 +1 → 总和 == 100（-race）
# ③ TTL：首次 AddUsed 后 key 有 TTL；重复 AddUsed 不重置 TTL
# ④ 跨天 periodTag 变化 → 新 key，旧 key 仍在（等 TTL）
# ⑤ HealthState Load 不存在的渠道 → 零值；Save/Load 往返一致
# ⑥ RateLimiter：窗口内第 limit+1 次 → false；window 过后 → true
```

## 7. 主要风险

- miniredis 对 Lua/EXPIRE 的支持边界：TTL 断言用 miniredis 的 TTL API；如有不支持项，该用例改走 testcontainers 真实 Redis 并注明。
- 时钟语义：periodTag 用服务器本地时区还是 UTC？决策——**UTC**（与 00 §7.4 时间约定一致），"daily" 按 UTC 日切，文档写明（内部系统可接受，避免时区漂移）。
