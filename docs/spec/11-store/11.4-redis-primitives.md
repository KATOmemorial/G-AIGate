## 1. 模块定位

跨节点共享状态的原子原语层：配额已用计数、健康状态存取、限流计数（预留）。**只提供原子操作，不承载判定语义**——健康状态机在 14.3，熔断的 Lua 在 16.3（00 §6.3 说明）。

## 2. 目标 / 非目标

**目标**：`QuotaCounter`（HINCRBY + 周期 TTL）、`HealthState`（HASH 读写）、`RateLimiter`（接口预留 + Lua INCR/PEXPIRE 实现，2026-10-19 实现反馈修正：Lua 闭合"加数无 TTL"洞以对齐 AddUsed 纪律，PEXPIRE 毫秒精度支持亚秒窗口、整秒窗口语义等价）；全部基于 go-redis v9（锁 v9.7.3）；miniredis 单测。

**非目标**：熔断窗口（16.3 自持 Lua）；任何"是否超限/是否禁用"的判断（消费方做）。

## 3. 输入输出

```go
// —— 配额计数 ——  key: gaigate:quota:used:{targetType}:{targetID}:{periodTag}
// periodTag: daily → "2026-09-26"；monthly → "2026-09"
type QuotaKey struct{ TargetType string; TargetID int64; Period string /*daily|monthly*/ }
func (k QuotaKey) String() string                     // 完整 Redis key（含按当天推导 periodTag）
func (k QuotaKey) TTLHint() time.Duration             // 到期 = 周期末 + 1h 的**绝对时刻**，与首写时刻无关（2026-10-17 实现反馈澄清：
                                                      // daily 次日 00:00 UTC +1h、monthly 次月 1 日 00:00 UTC +1h；周期起点首写时
                                                      // TTL 最长 25h，深夜首写更短。周期内过期 = 丢配额计数，是 bug 不是特性）

type QuotaCounter interface {
    // 原子累加已用；首次写时设置 TTL（HINCRBY 后 EXPIRE，仅当无 TTL 时设置——用 Lua 保证幂等）
    AddUsed(ctx context.Context, k QuotaKey, tokens, costMicro int64) error
    GetUsed(ctx context.Context, k QuotaKey) (tokens, costMicro int64, err error)
}

// —— 健康状态 ——  key: gaigate:health:{channelID}，整 HASH 覆盖写
type HealthSnapshot struct {
    ConsecutiveFailures int32
    DisabledUntil       int64  // unix 秒；0 = 未禁用
    LastProbeAt         int64
    LastProbeOk         bool
}
type HealthState interface {
    Load(ctx context.Context, channelID int64) (HealthSnapshot, error)  // 不存在 → 零值快照
    Save(ctx context.Context, channelID int64, s HealthSnapshot) error  // HSET 全字段，无 TTL（持久）
}

// —— 限流（预留）——  key: gaigate:rl:{scope}:{id}:{window}
type RateLimiter interface {
    Allow(ctx context.Context, scope string, id string, limit int, window time.Duration) (bool, error)
}
```

**原子性契约**：`AddUsed` 的 HINCRBY + 首次 EXPIRE 在一个 Lua 脚本内完成（防止"加了数但没设 TTL"的永久 key）；`RateLimiter.Allow` 同纪律（Lua INCR + PEXPIRE）；`Save` 为单命令 HSET 多字段（原子）。

## 4. 设计说明

1. **TTL 设在计数 key 上而非单独管理**：周期切换即换 key（periodTag 变了），旧 key 靠 TTL 自然过期——不做任何清理任务。这是"用 key 命名做时间分片"的标准手法，面试可讲。
2. **HealthState 无 TTL**：渠道健康状态跨周期持续存在，"禁用到什么时候"由 `DisabledUntil` 时间戳语义表达，而非 key 过期。
3. **原语与语义分离**：本层改一个字段名会影响 14.3/16.3/17.2 三个消费方——所以字段结构在本 PR 冻结，变更走 00 §10。

## 5. 验收标准（可执行）

```bash
go test ./internal/store/... -run 'TestQuotaCounter|TestHealthState|TestRateLimiter'
# 用例清单（miniredis）：
# ① AddUsed 两次 → tokens/cost 累加正确；key 命名含正确 periodTag
# ② 并发 100 goroutine AddUsed 各 +1 → 总和 == 100（-race）
# ③ TTL：首次 AddUsed 后 key 有 TTL；重复 AddUsed 不重置 TTL
# ④ 跨天 periodTag 变化 → 新 key，旧 key 仍在（等 TTL）
# ⑤ HealthState Load 不存在的渠道 → 零值；Save/Load 往返一致
# ⑥ RateLimiter：窗口内第 limit+1 次 → false；window 过后 → true
```

## 7. 主要风险

**本轮四项裁定与决策（2026-10-19/20）**：

1. **TTLHint 绝对时刻语义**（实现正确；文档措辞 `a1b831a` 澄清）：到期 = 周期末 + 1h 的**绝对时刻**，与首写时刻无关——daily 次日 00:00 UTC +1h、monthly 次月 1 日 00:00 UTC +1h；周期起点首写最长 25h，深夜首写更短。机制证据：`TestQuotaCounter_TTLHintLateDayShorterThanFullPeriod`（23:00 首写 TTLHint==2h 且 miniredis `TTL`==2h）。
2. **HASH 子字段清单**（接受为实现内部约定，**不冻结进契约**）：配额 → `tokens` / `cost_micro`；健康 → `consecutive_failures` / `disabled_until` / `last_probe_at` / `last_probe_ok`（bool 编码 `"1"`/`"0"`）。理由：消费方 14.3/17.2 经 Go 接口读写、不直连 Redis；多副本跑同一二进制保证一致；直连 Redis 仅限调试。故 §3 冻结的 Go 结构（`HealthSnapshot` 等）与接口签名才是契约面。
3. **依赖锁定 go-redis v9.7.3 / miniredis v2.34.0**。升级条件：升级 go-redis 须**同步评估 Go 工具链版本与台账 #8 的 -race 镜像方案**——go-redis 新版本（如 v9.23.0）要求 `go ≥ 1.26.0`，会顶掉 go.mod 的 `go 1.25.0` 并使 `golang:1.25` 镜像无法构建（本机无 C 工具链，-race 依赖该镜像）。
4. **RateLimiter Lua INCR+PEXPIRE 口径**（文档 `373ae61`）：用 Lua 闭合"加了数没 TTL"的永久 key 洞，对齐 `AddUsed` 已确立的原子性纪律；`PEXPIRE` 毫秒精度是 `EXPIRE` 的超集，整秒窗口语义等价。

**实现记录（与文档的对应、偏差与理由）**：

1. key 命名逐字符对照 00 §7.2：`gaigate:quota:used:{targetType}:{targetID}:{periodTag}`、`gaigate:health:{channelID}`、`gaigate:rl:{scope}:{id}:{window}`；测试以 miniredis `Exists`/`HGet`/`TTL` 做**机制性证据**（非仅 `String()` 字符串断言）。
2. `AddUsed` Lua：`HINCRBY`×2 后**仅当 `TTL<0`（无过期）才 `EXPIRE`** → 幂等且重复写不重置 TTL；字段名由 Go 常量拼入，单一来源。
3. 时钟：`QuotaKey.String`/`TTLHint` 签名无时钟参数（§3 冻结），以包级 `nowFn`（生产 `time.Now`，一律 UTC）承载可注入时钟，仅测试覆盖跨天/跨月。
4. `RateLimiter.Allow` 判定 `n <= limit`（`limit<=0` 恒拒）；`{window}` 分片取 `time.Duration.String()`（如 `"1m0s"`），不同窗口不共键。
5. §7 风险项未触发：miniredis v2.34.0 支持 `EVAL` 及所需命令（`HINCRBY`/`TTL`/`EXPIRE`/`INCR`/`PEXPIRE`），全部用例走 miniredis，**无需 testcontainers 真实 Redis 回退**。
6. 未做启动期 redis 连通性 fail-fast（仅 readyz ping 体现就绪），沿用 10.2 决策①"readyz 动态注册"；就绪性由 `/readyz` 承载（运行时证据见上）。容器编排健康门是否需要启动即校验，移交 20.1（台账 #20）。
