# 11.2 渠道/Key/别名/价格访问层（L2）

> 状态：草案（待 review） | 上游：[11-L1](../11-store.md) | 批次：B2 | 预计工作量：1 天
> 上下文包：[00-总纲](../00-总纲.md) §6.3、11.1（schema 与 GORM 模型）、11-L1 §1（缓存策略）

---

## 1. 模块定位

配置类数据的读写层：channels / channel_keys / channel_models / model_aliases / model_prices。router 每请求都要读它们，所以本 L2 的核心除了 CRUD，还有 **cache-aside 缓存**（11-L1 决策①）。

## 2. 目标 / 非目标

**目标**：GORM 模型与 5 张表的访问方法；60s TTL 进程内缓存 + 管理变更主动失效；singleflight 防缓存击穿。

**非目标**：不解密 `provider_key_enc`（原样返回密文，解密归 14.2）；不做健康状态读写（11.4）；不做 admin HTTP（14.1）。

## 3. 输入输出

```go
// 跨模块契约（00 §6.3）+ CRUD，方法签名本 L2 冻结
type ChannelRepo interface {
    ListActiveByModel(ctx context.Context, model string) ([]Channel, error) // enabled=1，priority 降序，走缓存
    Get(ctx context.Context, id int64) (*Channel, error)
    Create(ctx context.Context, ch *Channel, models []ChannelModel, keys [][]byte) error // 事务：渠道+映射+密文Key
    Update(ctx context.Context, ch *Channel) error
    Delete(ctx context.Context, id int64) error
}
type ModelRepo interface {
    Resolve(ctx context.Context, name string) (*ModelAlias, error) // 走缓存
    Create/Update/Delete/...
}
type KeyRepo interface {
    ListByChannel(ctx context.Context, channelID int64) ([]ChannelKey, error) // enc 原样
    Add/Remove/...
}
type PriceRepo interface {
    // 生效价格：enabled 且 effective_from <= now 的最新一条；无价格 → ErrNoPrice（17.3 决定降级策略）
    Effective(ctx context.Context, model string, at time.Time) (*ModelPrice, error)
}

// 缓存失效入口（14.1 的管理 API 在变更后调用）
type Invalidator interface {
    InvalidateChannels(model string) // 按 model 清 ListActiveByModel 缓存项
    InvalidateAlias(name string)
    InvalidateAll()
}
```

**缓存行为契约**：同一 `ListActiveByModel(model)` 在 TTL 内至多触发一次 DB 查询（singleflight 合并并发）；`Invalidate*` 后下一次读穿透并刷新；缓存对象为**值拷贝**（调用方修改不得污染缓存）。

## 4. 设计说明

1. **缓存击穿用 singleflight 而非锁**：TTL 过期瞬间的并发读合并为一次回源，这是标准解法，面试可讲。
2. **Create 的事务边界**：渠道 + channel_models + channel_keys 必须一个事务（部分写入的渠道对路由是脏数据）。
3. **密文透传原则**：store 层不知道也不需要知道 Key 内容——加解密边界在 14.2，本层只搬运字节。

## 5. 验收标准（可执行）

```bash
# 前置：11.1 验收通过（seed 存在）
go test ./internal/store/... -run 'TestChannel|TestModel|TestPrice|TestCache'
# 用例清单：
# ① ListActiveByModel("gpt-4o-demo") 返回 2 条且 priority 降序
# ② 缓存命中：第二次调用不产生 SQL（用计数 hook 断言）
# ③ InvalidateChannels 后立即读到变更值（无 60s 等待）
# ④ 并发 50 goroutine 同 key 读，DB 查询次数 == 1（singleflight）
# ⑤ Create 事务：注入 channel_keys 插入失败 → 渠道行不存在（回滚）
# ⑥ Effective：多条 effective_from，返回最新生效条；无价格返回 ErrNoPrice
```

## 7. 主要风险

- 缓存对象被调用方修改导致污染——值拷贝 + lint 约束，测试用例⑤覆盖（改返回值不影响缓存）。
- `fallback_ids` JSON 解析失败的容错：坏数据不 panic，记日志并按无回退处理。
