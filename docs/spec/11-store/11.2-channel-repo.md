# 11.2 渠道/Key/别名/价格访问层（L2）

> 状态：已实现（2026-10-16，验收见 §9） | 上游：[11-L1](../11-store.md) | 批次：B2 | 预计工作量：1 天

## 1. 模块定位

配置类数据的读写层：channels / channel_keys / channel_models / model_aliases / model_prices。router 每请求都要读它们，所以本 L2 的核心除了 CRUD，还有 **cache-aside 缓存**（11-L1 决策①）。

## 2. 目标 / 非目标

**目标**：GORM 模型与 5 张表的访问方法；60s TTL 进程内缓存 + 管理变更主动失效；singleflight 防缓存击穿。

**非目标**：不解密 `provider_key_enc`（原样返回密文，解密归 14.2）；不做健康状态读写（11.4）；不做 admin HTTP（14.1）。

## 3. 输入输出

```go
// 跨模块契约（00 §6.3）+ CRUD，方法签名本 L2 冻结
type ChannelRepo interface {
    ListActiveByModel(ctx context.Context, model string) ([]Channel, error) // enabled=1，priority 降序，走缓存
    Get(ctx context.Context, id int64) (*Channel, error)
    Create(ctx context.Context, ch *Channel, models []ChannelModel, keys [][]byte) error // 事务：渠道+映射+密文Key
    Update(ctx context.Context, ch *Channel) error
    Delete(ctx context.Context, id int64) error
}
type ModelRepo interface {
    Resolve(ctx context.Context, name string) (*ModelAlias, error) // 走缓存
    Create/Update/Delete/...
    // Update 语义（台账 #11，评审建议3）：全字段覆盖——空 Strategy/DisplayName 写空串、
    // 空 FallbackIDs 置 NULL，与 Create 的默认补齐不对称；调用方（14.1）必须传完整对象
}
type KeyRepo interface {
    ListByChannel(ctx context.Context, channelID int64) ([]ChannelKey, error) // enc 原样
    Add/Remove/...
}
type PriceRepo interface {
    // 生效价格：enabled 且 effective_from <= at 的最新一条；无价格 → ErrNoPrice（17.3 决定降级策略）。
    // 缓存语义（台账 #10，评审建议1）：缓存按 model 单键、快照 = 回源时刻的解析结果，
    // 仅支持"当前时刻"消费；历史 at 查询不属缓存路径（需 InvalidateAll 后回源）——17.3 消费约定为准
    Effective(ctx context.Context, model string, at time.Time) (*ModelPrice, error)
}

// 缓存失效入口（14.1 的管理 API 在变更后调用）
type Invalidator interface {
    InvalidateChannels(model string) // 按 model 清 ListActiveByModel 缓存项
    InvalidateAlias(name string)
    InvalidateAll()
}
```

**缓存行为契约**：同一 `ListActiveByModel(model)` 在 TTL 内至多触发一次 DB 查询（singleflight 合并并发）；`Invalidate*` 后下一次读穿透并刷新；缓存对象为**值拷贝**（调用方修改不得污染缓存）。

## 4. 设计说明

1. **缓存击穿用 singleflight 而非锁**：TTL 过期瞬间的并发读合并为一次回源，这是标准解法，面试可讲。
2. **Create 的事务边界**：渠道 + channel_models + channel_keys 必须一个事务（部分写入的渠道对路由是脏数据）。
3. **密文透传原则**：store 层不知道也不需要知道 Key 内容——加解密边界在 14.2，本层只搬运字节。

## 7. 主要风险

- 缓存对象被调用方修改导致污染——值拷贝 + lint 约束，测试用例⑤覆盖（改返回值不影响缓存）。
- `fallback_ids` JSON 解析失败的容错：坏数据不 panic，记日志并按无回退处理。

**实现记录（与本文档的对应与补充说明）**：

1. **接口归属**：`ChannelRepo` / `ModelRepo` / `KeyRepo` / `PriceRepo` / `Invalidator` 定义在 store 包内（与 13.1 的 `store.APIKeyRepo` 消费模式一致）；id 参数用 `int64`（对齐 00 §6.4 `channelID int64` 跨模块惯例），内部访问 DB 时转 uint64（GORM 模型字段仍 uint64）。
2. **Create 三表事务**（§4 决策②）：channels + channel_models + channel_keys 同事务；显式置 `created_at`/`updated_at`，`health_status` 空值补 `unknown`（沿用台账 #1 教训 / 01 §3.1）；`channel_keys.weight` 显式置 1（依赖 DDL 默认的列必须显式赋值）。
3. **Update 的存在性判定**：MySQL 默认返回 changed-rows（值未变时受影响行 = 0），故 `RowsAffected==0` 时补一次存在性 `Count` 再决定是否 `ErrNotFound`——否则"无变更更新"会被误判为不存在（`TestChannelRepo_Update_NoOpIsOK` 锁定）。
4. **Delete 级联**：schema 无外键（11.1 DDL 冻结），事务内显式删除 channel_keys / channel_models 再删 channels；`model_aliases` 的引用不清（60s TTL 兜底见 11-L1 §1）。
5. **`fallback_ids` 是 JSON 列**：写空串被 MySQL 拒（Error 3140，非法 JSON 文档）→ `aliasRow.FallbackIDs *string` + `nullableJSON`，空值写 NULL；JSON 列会规范化文本（`"[3,4]"`→`"[3, 4]"`），故消费按 `ParseFallbackIDs` 解析后的 id 判定而非比字符串（§7 风险；台账 #7）。
6. **`ParseFallbackIDs` 容错**（§7）：坏 JSON / NULL 不 panic，记一条 Warn 日志并按"无回退"返回 nil。
7. **缓存语义**（§3 冻结）：只覆盖配置读路径（`ListActiveByModel` / `Resolve` / `Effective`）；CRUD 不缓存；TTL 60s + singleflight 合并回源（§4 决策①）；值拷贝返回（含 `LastCheckedAt` / `DefaultChannelID` 指针字段深拷贝）；无负缓存（`ErrNoPrice` / `ErrNotFound` 不写缓存）。
8. **写方法不自动失效**：严格按 §3——失效入口由 14.1 管理 API 变更后调用 `Invalidator`。原因是 `Delete(channelID)` 无法得知受影响的 model key，`Invalidator` 带 model/name 参数正是为此；漏调时由 60s TTL 收敛。
9. **价格缓存按 model 单键**：快照 = 回源时刻按传入 `at` 解析的结果；配置读按"当前时刻"消费（17.3），符合 60s 取舍；**历史 `at` 查询不属该缓存语义**，需先 `InvalidateAll`（已写入 `Effective` 代码注释，测试⑥据此调整）。
10. **缓存 key 命名空间**：`chan:model:` / `alias:` / `price:model:`，失效入口按前缀定位条目。
11. **计数断言实现**：GORM 的 `gorm:query` 回调对 `Scan` 不触发，改用 GORM logger 的 `Trace`（每执行一条 SQL 调用一次）计数，覆盖 Find/First/Scan/Raw，见 `cache_test.go`。
12. **main 装配未改动**：11.2 是纯访问层，消费者（14.1 / 14.2 / 16 / 17.3）落地时装配；当前 `cmd/g-aigate` 无引用，故未接线。
