## 1. 模块定位

B2 的地基：把 00 §7.1 的表级契约落成可执行 DDL 与版本化迁移，并提供幂等 seed（含指向 mock 的示例渠道）。所有后续 store 访问层与 B3+ 的业务模块都跑在这套 schema 上。

## 2. 目标 / 非目标

**目标**：`migrations/` 下两对迁移文件（init + seed）；`internal/store/migrate.go`（启动时自动执行，`GET_LOCK` 防多副本并发）；`internal/store/seed.go`（幂等 seed，Go 实现）；GORM 模型与表一一对应。

**非目标**：不实现任何查询方法（11.2/11.3）；不实现 Redis 侧（11.4）；不做数据修复工具。

## 3. 输入输出

**迁移文件**：

```
migrations/000001_init.up.sql / 000001_init.down.sql   # 仅 schema；seed 不走 SQL（bcrypt/AES 须运行时计算，见决策①）
```

**Seed（Go 实现，幂等 upsert）**：

| 对象 | 值 |
|---|---|
| group | `default` |
| admin 用户 | `admin` / 密码来自 `GAIGATE_ADMIN_PASSWORD`（默认 `admin123`，仅 dev） |
| 渠道 1 | `demo-primary`：openai 兼容，`http://127.0.0.1:18080`（mock），priority 10 / weight 70，Key `sk-mock-a` |
| 渠道 2 | `demo-fallback`：同上，priority 5 / weight 30，Key `sk-mock-b` |
| channel_models | 两渠道均服务 `gpt-4o-demo`（upstream 同名） |
| model_aliases | `gpt-4o-demo` → default 渠道 1，fallback `[2]`，strategy `weighted` |
| model_prices | `gpt-4o-demo`：input 15,000,000 / output 60,000,000 微元/M（≈¥15/¥60） |

**迁移执行方式**：网关启动时自动执行（`migrate.Up` + MySQL `GET_LOCK('gaigate_migrate', 10)` 防多副本并发，拿不到锁的副本等待重试）。生产可改为 K8s Job——文档注明。

## 4. 设计说明

1. **seed 用 Go 而非 SQL**：bcrypt 哈希与 AES-GCM 密文必须在运行时用环境变量计算，SQL 里放不了真密文。
2. **usage_records 三索引**：request_id（对账点查）、user+time（用户控制台）、time（全局账单聚合）——三个索引对应三类查询路径，多一个都不加。
3. **channel_models.upstream_model**：修正 00 §7.1 的隐含缺口（对外模型名 ≠ 上游模型名是多对多映射存在的意义），登记 00 变更记录。

## 7. 主要风险

- DDL 是全项目最难改的东西之一——本 PR review 重点：索引、字段类型、NOT NULL 约束。
- `GET_LOCK` 等待策略：超时后 fail-fast 退出（依赖 DBA 干预），不静默跳过迁移。

**实现记录（与本文档的对应与补充说明）**：

1. **迁移文件数量**：§2"两对迁移文件（init + seed）"与 §3"仅 schema"矛盾，按 §3 及 main `b8b342a` 的澄清执行——仅 `000001_init` 一对文件，seed 全走 Go（bcrypt/AES 运行时计算，§4 决策①）。§5 回滚链命令相应为 `down 1 && up 1`。
2. **channel_models.upstream_model**：§3 注释要求"随本 PR 登记 00 变更记录"——经查 00 §7.1（v0.3）表级契约已含 `upstream_model` 列且 §11 v0.3 已登记（2026-09-26），无需再动 00。
3. **GET_LOCK 实现**：GET_LOCK 是会话级锁，故从连接池取出专用 `*sql.Conn` 获取并持有，迁移经池内其他连接执行；单次等待 10s（§3），拿不到锁重试，总预算 60s 耗尽 fail-fast（§7）。迁移连接 DSN 需 `multiStatements=true`（迁移文件含多条 DDL）。
4. **seed 幂等语义**：按业务唯一键 ensure——缺失插入 / 与 seed 规格不一致更新 / 一致零写（重启零抖动，验收以 users.updated_at 不变佐证）。channel_keys / model_prices 无业务唯一键（DDL 冻结），以存在性检查保证幂等；多副本同时首次 seed 存在竞态窗口（GET_LOCK 按 §3 仅覆盖迁移），开发单副本下属文档化取舍，代码注释已登记。
5. **admin 密码**：以环境为权威——bcrypt 比对一致零写，变更则重算（`GAIGATE_ADMIN_PASSWORD` 缺省回退 `admin123`，仅 dev）。
6. **model_prices.effective_from**：§3 未指定取值，实现取纪元零点（1970-01-01 UTC，MySQL DATETIME 合法区间内）——确定性、自始生效、重启不产生新行。
7. **GORM 模型**：类型与列一一对应（BIGINT UNSIGNED→uint64、INT→int32、INT UNSIGNED→uint32、BIGINT/微元→int64、TINYINT status→int8+Go 常量），未用 AutoMigrate；GORM 日志 Silent，防非 JSON 行污染 00 §8.3 契约。
8. **工程环境**：本机 3306 被占用，docker MySQL 映射宿主 3307（`.env` 不入库），网关以 `GAIGATE_MYSQL_PORT=3307` 覆盖（10.1 环境变量机制）；compose 中 jaeger 镜像 `jaegertracing/all-in-one:1.62` 拉取失败（manifest not found），本 PR 仅起 mysql+redis，镜像问题留待 20-deploy 处理。`GROUPS` 为 MySQL 8.0+ 保留字——DDL 与 GORM 查询均带反引号不受影响，手写原生 SQL 需注意（已在测试注释登记）。
9. **顺手修复**：`.golangci.yml` 的 `issues.exclude-rules` 在 golangci-lint v2 下被静默忽略（测试豁免一直未生效），迁至 `linters.exclusions.rules`，意图不变。
