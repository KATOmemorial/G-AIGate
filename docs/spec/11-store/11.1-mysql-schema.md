# 11.1 MySQL schema 与迁移（L2）

## 1. 模块定位

B2 的地基：把 00 §7.1 的表级契约落成可执行 DDL 与版本化迁移，并提供幂等 seed（含指向 mock 的示例渠道）。所有后续 store 访问层与 B3+ 的业务模块都跑在这套 schema 上。

## 2. 目标 / 非目标

**目标**：`migrations/` 下两对迁移文件（init + seed）；`internal/store/migrate.go`（启动时自动执行，`GET_LOCK` 防多副本并发）；`internal/store/seed.go`（幂等 seed，Go 实现）；GORM 模型与表一一对应。

**非目标**：不实现任何查询方法（11.2/11.3）；不实现 Redis 侧（11.4）；不做数据修复工具。

## 3. 输入输出

**迁移文件**：

```
migrations/000001_init.up.sql / 000001_init.down.sql
migrations/000002_seed.up.sql / 000002_seed.down.sql   # 仅清空 seed 数据，schema 不动
```

**000001_init 完整 DDL**（字段级冻结；`id` 一律 `BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY`；时间一律 `DATETIME(3)` UTC；status 用 `TINYINT`，含义由 Go 常量定义）：

```sql
CREATE TABLE `groups` (
  `id`         BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  `name`       VARCHAR(64) NOT NULL,
  `created_at` DATETIME(3) NOT NULL,
  UNIQUE KEY `uk_groups_name` (`name`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE `users` (
  `id`            BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  `username`      VARCHAR(64) NOT NULL,
  `password_hash` VARCHAR(255) NOT NULL,
  `role`          VARCHAR(16) NOT NULL DEFAULT 'user',  -- user|admin
  `group_id`      BIGINT UNSIGNED NOT NULL,
  `status`        TINYINT NOT NULL DEFAULT 1,           -- 1 启用 0 禁用
  `created_at`    DATETIME(3) NOT NULL, `updated_at` DATETIME(3) NOT NULL,
  UNIQUE KEY `uk_users_username` (`username`),
  KEY `idx_users_group` (`group_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE `api_keys` (
  `id`         BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  `user_id`    BIGINT UNSIGNED NOT NULL,
  `name`       VARCHAR(128) NOT NULL DEFAULT '',
  `key_prefix` VARCHAR(16) NOT NULL,                    -- 明文前 8 位，索引用
  `key_hash`   CHAR(64) NOT NULL,                       -- SHA-256 hex
  `status`     TINYINT NOT NULL DEFAULT 1,              -- 1 启用 0 吊销
  `created_at` DATETIME(3) NOT NULL, `expired_at` DATETIME(3) NULL,
  UNIQUE KEY `uk_api_keys_hash` (`key_hash`),
  KEY `idx_api_keys_prefix` (`key_prefix`),
  KEY `idx_api_keys_user` (`user_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE `channels` (
  `id`                BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  `name`              VARCHAR(128) NOT NULL,
  `provider`          VARCHAR(32) NOT NULL,             -- openai|mock|...
  `base_url`          VARCHAR(255) NOT NULL,
  `priority`          INT NOT NULL DEFAULT 0,           -- 大者优先
  `weight`            INT NOT NULL DEFAULT 1,
  `enabled`           TINYINT NOT NULL DEFAULT 1,
  `health_status`     VARCHAR(16) NOT NULL DEFAULT 'unknown', -- 展示缓存列，路由不读
  `error_rate_cache`  FLOAT NOT NULL DEFAULT 0,
  `latency_p99_cache` INT NOT NULL DEFAULT 0,           -- ms，展示缓存列
  `last_checked_at`   DATETIME(3) NULL,
  `created_at`        DATETIME(3) NOT NULL, `updated_at` DATETIME(3) NOT NULL,
  KEY `idx_channels_enabled` (`enabled`, `priority`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE `channel_models` (
  `channel_id` BIGINT UNSIGNED NOT NULL,
  `model`      VARCHAR(128) NOT NULL,                   -- 对外模型名（别名）
  `upstream_model` VARCHAR(128) NOT NULL,               -- 映射后的上游模型名
  PRIMARY KEY (`channel_id`, `model`),
  KEY `idx_cm_model` (`model`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
-- 注意：相对 00 §7.1 增加 upstream_model 列——渠道对同一对外模型可用不同上游名，
-- 这是 channel_models 多对多的本意；属字段级补全，随本 PR 一并登记 00 变更记录。

CREATE TABLE `channel_keys` (
  `id`               BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  `channel_id`       BIGINT UNSIGNED NOT NULL,
  `provider_key_enc` VARBINARY(512) NOT NULL,           -- AES-256-GCM 密文
  `weight`           INT NOT NULL DEFAULT 1,
  `status`           TINYINT NOT NULL DEFAULT 1,
  `created_at`       DATETIME(3) NOT NULL,
  KEY `idx_ck_channel` (`channel_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE `model_aliases` (
  `id`                 BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  `name`               VARCHAR(128) NOT NULL,
  `display_name`       VARCHAR(128) NOT NULL DEFAULT '',
  `default_channel_id` BIGINT UNSIGNED NULL,
  `fallback_ids`       JSON NULL,                       -- 渠道 id 数组，如 [2,3]
  `strategy`           VARCHAR(32) NOT NULL DEFAULT 'weighted',
  `created_at`         DATETIME(3) NOT NULL, `updated_at` DATETIME(3) NOT NULL,
  UNIQUE KEY `uk_alias_name` (`name`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE `model_prices` (
  `id`                BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  `model`             VARCHAR(128) NOT NULL,
  `input_price_per_m`  BIGINT NOT NULL,                 -- 微元 / 百万 token
  `output_price_per_m` BIGINT NOT NULL,
  `currency`          VARCHAR(8) NOT NULL DEFAULT 'CNY',
  `effective_from`    DATETIME(3) NOT NULL,
  `enabled`           TINYINT NOT NULL DEFAULT 1,
  KEY `idx_price_model` (`model`, `effective_from`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE `usage_records` (
  `id`            BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  `request_id`    VARCHAR(32) NOT NULL,
  `user_id`       BIGINT UNSIGNED NOT NULL,
  `api_key_id`    BIGINT UNSIGNED NOT NULL,
  `channel_id`    BIGINT UNSIGNED NOT NULL,
  `model`         VARCHAR(128) NOT NULL,
  `input_tokens`  INT UNSIGNED NOT NULL DEFAULT 0,
  `output_tokens` INT UNSIGNED NOT NULL DEFAULT 0,
  `cost`          BIGINT NOT NULL DEFAULT 0,            -- 微元
  `latency_ms`    INT UNSIGNED NOT NULL DEFAULT 0,
  `status`        VARCHAR(16) NOT NULL,                 -- success|failed|canceled
  `estimated`     TINYINT NOT NULL DEFAULT 0,
  `created_at`    DATETIME(3) NOT NULL,
  KEY `idx_usage_req` (`request_id`),
  KEY `idx_usage_user_time` (`user_id`, `created_at`),
  KEY `idx_usage_time` (`created_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE `quotas` (
  `id`          BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  `target_type` VARCHAR(16) NOT NULL,                   -- api_key|user|group
  `target_id`   BIGINT UNSIGNED NOT NULL,
  `period`      VARCHAR(16) NOT NULL,                   -- daily|monthly
  `token_limit` BIGINT NOT NULL DEFAULT 0,              -- 0 = 不限
  `cost_limit`  BIGINT NOT NULL DEFAULT 0,              -- 微元，0 = 不限
  `soft_ratio`  DECIMAL(3,2) NOT NULL DEFAULT 0.80,
  UNIQUE KEY `uk_quota_target` (`target_type`, `target_id`, `period`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE `bills` (
  `id`          BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  `user_id`     BIGINT UNSIGNED NOT NULL,
  `group_id`    BIGINT UNSIGNED NOT NULL,
  `period`      CHAR(7) NOT NULL,                       -- 'YYYY-MM'
  `total_cost`  BIGINT NOT NULL DEFAULT 0,
  `token_total` BIGINT NOT NULL DEFAULT 0,
  `created_at`  DATETIME(3) NOT NULL,
  UNIQUE KEY `uk_bills_user_period` (`user_id`, `period`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

**Seed（Go 实现，幂等 upsert）**：

| 对象 | 值 |
|---|---|
| group | `default` |
| admin 用户 | `admin` / 密码来自 `GAIGATE_ADMIN_PASSWORD`（默认 `admin123`，仅 dev） |
| 渠道 1 | `demo-primary`：openai 兼容，`http://127.0.0.1:18080`（mock），priority 10 / weight 70，Key `sk-mock-a` |
| 渠道 2 | `demo-fallback`：同上，priority 5 / weight 30，Key `sk-mock-b` |
| channel_models | 两渠道均服务 `gpt-4o-demo`（upstream 同名） |
| model_aliases | `gpt-4o-demo` → default 渠道 1，fallback `[2]`，strategy `weighted` |
| model_prices | `gpt-4o-demo`：input 15,000,000 / output 60,000,000 微元/M（≈¥15/¥60） |

**迁移执行方式**：网关启动时自动执行（`migrate.Up` + MySQL `GET_LOCK('gaigate_migrate', 10)` 防多副本并发，拿不到锁的副本等待重试）。生产可改为 K8s Job——文档注明。

## 4. 设计说明

1. **seed 用 Go 而非 SQL**：bcrypt 哈希与 AES-GCM 密文必须在运行时用环境变量计算，SQL 里放不了真密文。
2. **usage_records 三索引**：request_id（对账点查）、user+time（用户控制台）、time（全局账单聚合）——三个索引对应三类查询路径，多一个都不加。
3. **channel_models.upstream_model**：修正 00 §7.1 的隐含缺口（对外模型名 ≠ 上游模型名是多对多映射存在的意义），登记 00 变更记录。

## 5. 验收标准（可执行）

```bash
docker compose -f deploy/infra/docker-compose.yml up -d mysql
go run ./cmd/g-aigate          # 启动自动迁移 + seed（此时 store 已在 main 装配）
docker exec gaigate-mysql mysql -uroot -pgaigate_dev gaigate -e "SHOW TABLES;"
# → 11 张表全部存在
docker exec gaigate-mysql mysql -uroot -pgaigate_dev gaigate -e "SELECT id,name,priority FROM channels;"
# → 两条 demo 渠道
# 幂等性：重启网关一次，seed 不产生重复行（SELECT COUNT(*) FROM channels == 2）
# 回滚链：migrate down 2 && up 2 后 schema 与 seed 完整
```

## 6. 依赖

上游：10.1（MySQL 配置、MasterKey）、deploy/infra（MySQL 实例）。被依赖：11.2/11.3（全部访问层）、12 验收（seed 渠道指向 mock）。

## 7. 主要风险

- DDL 是全项目最难改的东西之一——本 PR review 重点：索引、字段类型、NOT NULL 约束。
- `GET_LOCK` 等待策略：超时后 fail-fast 退出（依赖 DBA 干预），不静默跳过迁移。

## 8. 预计工作量

DDL + 迁移 + seed 实现 0.5 天，验收与幂等/回滚测试 0.5 天。
