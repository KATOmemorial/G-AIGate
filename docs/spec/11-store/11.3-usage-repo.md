# 11.3 计量/配额/账单访问层（L2）

> 状态：草案（待 review） | 上游：[11-L1](../11-store.md) | 批次：B2 | 预计工作量：1 天
> 上下文包：[00-总纲](../00-总纲.md) §6.6/§7.1、11-L1 §3（决策③④）、17-L1 §2（消费方式）

## 1. 模块定位

账务数据的读写层：usage_records（只追加）、quotas（配置）、bills（物化聚合）。核心特点是**写入异步化**——请求路径上的 Record 永不阻塞、永不失败返回。

## 2. 目标 / 非目标

**目标**：`UsageRepo`（异步队列 + 批量落库 + drain 语义）；`QuotaRepo`（配额配置 CRUD）；`BillRepo`（月账单 upsert 与查询）。

**非目标**：配额的预检/结算语义（17.2，本层只存配置）；计价（17.3）；查询聚合 API（17.3）。

## 3. 输入输出

```go
type UsageRecord struct { // 与表一一对应，字段冻结
    RequestID string; UserID, APIKeyID, ChannelID int64
    Model string; InputTokens, OutputTokens uint32
    Cost int64; LatencyMs uint32; Status string; Estimated bool; CreatedAt time.Time
}

type UsageRepo interface {
    // 永不阻塞、永不返回业务错误：入队即返回。
    // 队列满 → 丢弃并调用 OnDrop 回调（默认 error 日志；B7 由 18 挂 gaigate_usage_drop_total）
    Record(rec UsageRecord)
    SetOnDrop(fn func(rec UsageRecord))
    Close(ctx context.Context) error // drain：把队列中记录全部落库后退出（10.2 关闭序列第一步）
}
// 内部：缓冲 chan（容量 MeterConfig.SettleQueueSize，默认 1024）
//       worker 每 100 条或 500ms 批量 INSERT（事务），失败重试 3 次后放弃 + OnDrop

type QuotaRepo interface {
    Get(ctx, targetType string, targetID int64, period string) (*Quota, error)
    Upsert(ctx, q *Quota) error
    ListByTarget(ctx, targetType string, targetID int64) ([]Quota, error)
}
type BillRepo interface {
    UpsertMonth(ctx, userID, groupID int64, period string, totalCost, tokenTotal int64) error
    List(ctx, filter BillFilter) ([]Bill, error) // 按 user/group/period 过滤
}
```

**UsageRecord 只追加**：不提供 Update/Delete（11-L1 决策②，账目不可变）。

## 4. 设计说明

1. **丢弃可观测而非假装不丢**：队列满是真实会发生的事（DB 抖动 + 流量高峰），丢弃并打点是诚实的工程答案；修复路径（本地 WAL）已在 11-L1 文档化为后置项。面试题："你的计费会丢数据吗？"——标准答案是说出窗口、量化手段（gaigate_usage_drop_total）、修复方向。
2. **批量写入的触发条件**：条数或时间先到者触发——低流量时 500ms 保证及时性，高流量时 100 条摊薄开销。
3. **Close 的 drain 语义**是优雅关闭链路的一环（10.2 §3.2）：先 drain 落账队列，再关 DB 连接，顺序反了就丢账。

## 5. 验收标准（可执行）

```bash
go test ./internal/store/... -run 'TestUsage|TestQuota|TestBill'
# 用例清单：
# ① Record 1000 条 → Close 后 SELECT COUNT(*) == 1000
# ② 队列灌满（容量 1024，灌 5000 条瞬间）→ 丢弃数 + OnDrop 回调数 一致，进程不死锁
# ③ worker 批量：注入慢 DB（事务 hook 人为延迟）→ 观察批量行为（单测用 hook 断言批次大小）
# ④ Close 期间继续 Record → 全部落库（drain 边界）
# ⑤ Quota Upsert 幂等（同 target+period 更新不重复）
# ⑥ Bill UpsertMonth 重复调用取最后值（UNIQUE 键冲突转 update）
```

## 7. 主要风险

- OnDrop 回调在 18 之前只有日志——可接受，B7 接管打点。
- 批量 INSERT 的 max_allowed_sql 长度：100 条 × 记录宽度远低于默认限制，不构成风险，文档留痕。
